HTML у PDF

Конвертуйте збережений HTML-файл у PDF на сервері конвертації, щоб вебсторінка чи HTML-експорт стали фіксованими сторінками, готовими до друку.

🔒 Ваші файли обробляються локально у браузері й ніколи не завантажуються на сервер.
1

Завантажте

Виберіть файл або перетягніть його.

2

Налаштуйте

Виберіть параметри — усе відбувається у вашому браузері.

3

Завантажте результат

Миттєво збережіть готовий файл. Без водяних знаків.

Чимало корисних документів існує лише у вигляді HTML: підтвердження замовлення, збережене з браузера, звіт, вивантажений із програми, розсилка, документація, згенерована однією сторінкою, або сторінка, яку ви зверстали самі. HTML підлаштовується під розмір будь-якого вікна — і саме цього не треба, коли документ треба підшити, надрукувати чи додати до заяви. PDF фіксує його в одному форматі сторінки.

Інструмент приймає .html або .htm файл із вашого комп’ютера, а не вебадресу. Файл у зашифрованому вигляді вивантажується до сервісу CloudConvert через ретранслятор PDFora; там рушій рендерингу верстає сторінку й друкує її в PDF. Результат повертається з назвою вашого файлу, а із сервісу після цього видаляється. Конвертація відбувається не у вашому браузері, і налаштувань розміру сторінки чи полів на сторінці інструмента немає.

Найбільше дивує більшість людей те, що стається з усім, на що посилається HTML-файл. Вебсторінка рідко складається з одного файлу: зображення, таблиці стилів і шрифти зазвичай лежать окремо, а HTML на них лише посилається. Вивантажується тільки один вибраний вами файл, тож усе, на що він посилається відносним шляхом на вашому диску, сервер знайти не може. Тому якісний PDF — це передусім питання того, щоб перед конвертацією зробити HTML-файл самодостатнім.

Як конвертувати HTML у PDF

  1. Переконайтеся, що HTML-файл самодостатній або використовує для зображень і стилів повні вебадреси (https://...); подробиці нижче.
  2. Відкрийте «HTML у PDF» і виберіть .html або .htm файл.
  3. Натисніть «Конвертувати» й зачекайте, поки файл вивантажиться й відрендериться на сервері.
  4. Завантажте PDF — він матиме назву вашого файлу з розширенням .pdf.
  5. Перевірте, чи на місці зображення, кольори й макет і чи нічого не обрізано біля правого краю.

Коли використовувати цей інструмент

  • Квитанції та підтвердження бронювання, збережені з браузера, — у PDF для бухгалтерії чи як юридичне підтвердження.
  • Звіти, які програма вивантажує в HTML, а їх треба прикласти до листа чи заархівувати.
  • Розробник перетворює згенерований HTML-шаблон рахунку, сертифіката чи листа на PDF, щоб перевірити, як він виглядатиме на друку.
  • Документація чи посібник користувача, опубліковані однією довгою HTML-сторінкою, — надрукувати для читання офлайн.
  • Збережені статті з інтернету для досліджень — у форматі, який не зміниться, навіть якщо зміниться сайт.
  • Email-розсилки, збережені як HTML, — у PDF як запис того, що було надіслано.

Що варто знати заздалегідь

  • Відносні посилання ламаються. Якщо в HTML написано <img src="images/logo.png"> або <link href="style.css">, ці файли лишаються на вашому комп’ютері, і сервер їх не бачить. У PDF тоді не буде зображень, а текст буде без стилів. Використовуйте абсолютні адреси https:// або вбудуйте CSS у блок <style>, а зображення — як data URI.
  • Ресурси з абсолютними вебадресами сервер може завантажити під час рендерингу, тож публічно доступні зображення й стилі зазвичай з’являються. Усе, що за логіном, у внутрішній мережі чи на localhost, — ні.
  • Поля для URL немає. Щоб конвертувати живу сторінку, спершу збережіть її. Формат браузера «Вебсторінка, один файл» (.mhtml) не приймається, тож вибирайте «Вебсторінка, лише HTML» і будьте готові, що відносні зображення зникнуть, — або скористайтеся вбудованим у браузер «Друк → Зберегти як PDF».
  • Діють стилі для друку. Якщо на сторінці є CSS для @media print, конвертер зазвичай його застосовує, тож навігація може зникнути, а кольори — відрізнятися від того, що ви бачите на екрані. Розривами сторінок можна керувати через break-before і break-inside у CSS.
  • Вміст, який будує JavaScript, ненадійний. Сторінки, що підвантажують вміст скриптами вже після завантаження, можуть конвертуватися порожньою оболонкою. Збережіть сторінку, коли вона повністю завантажиться, або формуйте вміст у HTML на боці сервера.
  • Макети, ширші за друковану сторінку, — як-от фіксований дизайн на 1400 пікселів чи широкі таблиці, — можуть обрізатися або зменшуватися. Зазвичай допомагає адаптивна верстка або max-width для основного вмісту.

Поради для найкращого результату

  • У власних шаблонах тримайте весь CSS у блоці <style> у <head> — це найнадійніший спосіб отримати PDF зі стилями.
  • Додайте в CSS @page { size: A4; margin: 15mm; }, якщо потрібні конкретний розмір сторінки чи поля.
  • Ставте break-inside: avoid на рядки таблиць, картки й ілюстрації, щоб вони не розривалися між двома сторінками.
  • Стежте за розміром зображень: банер на 5 MB, вбудований як data URI, однаково дасть PDF на 5 MB.
  • Спершу відкрийте HTML-файл у попередньому перегляді друку в браузері: якщо там щось не так, у конвертованому PDF, найімовірніше, буде так само.

Практичний приклад: HTML-шаблон рахунку невеликого інтернет-магазину

Інтернет-магазин handmade-свічок, де працює двоє людей, генерує рахунки простим скриптом у вигляді HTML-файлів. Кожен файл посилається на invoice.css і logo.png у тій самій папці. Якщо конвертувати його напряму, PDF виходить звичайним чорним текстом стандартним шрифтом, без логотипа, а таблиця з підсумками розтягнута на всю ширину: сервер отримав HTML без таблиці стилів і зображення.

Рішення — зробити файл самодостатнім. Тепер скрипт копіює вміст invoice.css у блок <style>, додає @page { size: A4; margin: 18mm; } і break-inside: avoid для рядків таблиці товарів, а логотип бере за публічною адресою https на сайті магазину замість локального шляху. Більше нічого не змінюється.

Після повторної конвертації рахунок — це односторінковий PDF формату A4 з логотипом, фірмовими кольорами магазину й таблицею підсумків, яка більше не розривається, коли в замовленні багато позицій. Оскільки шаблон тепер самодостатній, кожен рахунок, який створює скрипт, конвертується однаково.

Усунення проблем

У PDF немає стилів, лише простий текст
Таблицю стилів підключено відносним шляхом, і її не було вивантажено. Вбудуйте CSS у блок <style> або підключіть його за повною адресою https://.
Немає зображень
Зображення з вашого диска, підключені відносними шляхами, недоступні. Використайте публічні URL https:// або вбудуйте зображення як data URI й конвертуйте знову.
Сторінка обрізана праворуч
Макет має фіксовану ширину, більшу за сторінку. Додайте max-width: 100% основним контейнерам і зображенням або стилі для друку, що звужують макет.
PDF порожній або майже порожній
Імовірно, вміст створюється JavaScript після завантаження, або файл — лише переадресація. Збережіть сторінку, коли вона повністю відмалюється, або сформуйте вміст безпосередньо в HTML.
Текст відображається іншим шрифтом
Вебшрифти, підключені локально, були недоступні. Підключіть шрифт із публічного URL, вбудуйте його через @font-face і data URI або використайте поширений набір шрифтів.
Інструмент не приймає мій файл
Приймаються лише .html і .htm. Збережені .mhtml чи .webarchive треба перезберегти як «лише HTML».

Часті запитання

Чи можна конвертувати сайт, ввівши його URL?

Ні. Інструмент конвертує HTML-файл, який ви вибрали. Спершу збережіть сторінку як HTML або для живої сторінки скористайтеся «Друк → Зберегти як PDF» у браузері.

Чи вивантажується HTML-файл?

Так. Він у зашифрованому вигляді надсилається до сервісу конвертації, там рендериться й потім видаляється. Не конвертуйте сторінки з персональними даними, які ви не хотіли б довіряти третій стороні.

Чому зникли мої зображення й CSS?

Вивантажується лише сам HTML-файл. Файли, на які він посилається відносними шляхами, лишаються на вашому комп’ютері; використовуйте абсолютні посилання https:// або вбудовуйте їх у HTML.

Чи можна задати розмір сторінки чи поля?

На сторінці інструмента — ні. Задайте їх у HTML правилом CSS @page, наприклад @page { size: A4; margin: 15mm; }.

Чи клікабельні посилання в PDF?

Посилання на вебадреси зазвичай лишаються клікабельними. Відносні посилання на інші локальні файли нікуди корисно не ведуть.

Чи виконується JavaScript під час конвертації?

Частково може, але вміст, що підвантажується пізно чи залежить від дій користувача, часто відсутній. Для надійного результату HTML уже має містити остаточний вміст.
