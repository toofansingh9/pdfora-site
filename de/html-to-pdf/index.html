HTML in PDF

Wandeln Sie eine gespeicherte HTML-Datei auf einem Konvertierungsserver in ein PDF um – aus einer Webseite oder einem HTML-Export werden feste, druckbare Seiten.

🔒 Ihre Dateien werden lokal in Ihrem Browser verarbeitet und niemals hochgeladen.
1

Hochladen

Wählen Sie Ihre Datei aus oder ziehen Sie sie per Drag-and-drop.

2

Anpassen

Wählen Sie Ihre Optionen — alles geschieht in Ihrem Browser.

3

Herunterladen

Speichern Sie die fertige Datei sofort. Keine Wasserzeichen.

Die Bestellbestätigung für den neuen Laptop, den Sie als Arbeitsmittel in der Steuererklärung angeben wollen, existiert nur als gespeicherte Webseite. Der Monatsbericht aus der Buchhaltungssoftware kommt als HTML-Export. Die Projektdokumentation besteht aus einer einzigen langen HTML-Seite. All das ist praktisch, solange man es am Bildschirm liest, denn HTML passt sich jeder Fensterbreite an. Soll das Dokument aber abgelegt, gedruckt oder einem Antrag beigefügt werden, ist genau diese Beweglichkeit hinderlich. Ein PDF legt den Inhalt auf ein festes Seitenformat fest.

„HTML in PDF“ nimmt eine .html- oder .htm-Datei von Ihrem Rechner entgegen – eine Webadresse lässt sich nicht eingeben. Die Datei geht verschlüsselt über das Relay von PDFora an den Dienst CloudConvert. Dort baut eine Rendering-Engine die Seite auf und druckt sie als PDF. Das Ergebnis kommt mit dem Namen Ihrer Datei zurück und wird danach beim Dienst gelöscht. Die Umwandlung läuft also nicht in Ihrem Browser, und Einstellungen für Seitenformat oder Ränder gibt es auf der Tool-Seite nicht.

Womit die meisten nicht rechnen: Eine Webseite ist fast nie nur eine Datei. Bilder, Stylesheets und Schriften liegen üblicherweise als eigene Dateien daneben und werden vom HTML nur aufgerufen. Hochgeladen wird aber ausschließlich die eine Datei, die Sie auswählen. Alles, was per relativem Pfad auf Ihrer Festplatte eingebunden ist, bleibt für den Server unsichtbar. Wer ein originalgetreues PDF möchte, macht die HTML-Datei deshalb vorher eigenständig.

So wandeln Sie HTML in PDF um

  1. Sorgen Sie dafür, dass die HTML-Datei eigenständig ist oder für Bilder und Stylesheets vollständige Webadressen (https://...) nutzt – siehe die Hinweise unten.
  2. Öffnen Sie HTML in PDF und wählen Sie die .html- oder .htm-Datei aus.
  3. Klicken Sie auf „Konvertieren“ und warten Sie, bis die Datei hochgeladen und auf dem Server gerendert ist.
  4. Laden Sie das PDF herunter; es trägt den Namen Ihrer Datei mit der Endung .pdf.
  5. Prüfen Sie, ob Bilder, Farben und Layout übernommen wurden und am rechten Rand nichts abgeschnitten ist.

Wann Sie dieses Tool nutzen sollten

  • Bestellbestätigungen aus Onlineshops als PDF sichern, etwa als Beleg für Arbeitsmittel in der Steuererklärung oder für einen späteren Gewährleistungsfall.
  • Für die Haus- oder Seminararbeit Online-Quellen als PDF archivieren, damit der zitierte Stand erhalten bleibt, auch wenn sich die Website ändert.
  • HTML-Berichte aus Buchhaltungs- oder Vereinssoftware in eine Form bringen, die sich per E-Mail verschicken und ablegen lässt.
  • Als Entwickler generierte Rechnungen, Teilnahmebestätigungen oder Briefvorlagen aus HTML ausgeben, um das Drucklayout zu prüfen.
  • Eine Dokumentation oder Bedienungsanleitung, die als eine lange HTML-Seite vorliegt, für das Lesen ohne Internet aufbereiten.
  • Als HTML gespeicherte Newsletter umwandeln, um festzuhalten, was tatsächlich verschickt wurde.

Das sollten Sie vorher wissen

  • Relative Verweise funktionieren nicht. Steht im HTML <img src="images/logo.png"> oder <link href="style.css">, bleiben diese Dateien auf Ihrem Rechner und der Server sieht sie nicht. Das PDF zeigt dann fehlende Bilder und ungestylten Text. Verwenden Sie absolute https://-Adressen oder betten Sie das CSS in einen <style>-Block und Bilder als Data-URIs ein.
  • Ressourcen mit absoluter Webadresse kann der Server beim Rendern abrufen, öffentlich erreichbare Bilder und Stylesheets erscheinen deshalb meist. Alles hinter einem Login, im Intranet oder auf localhost dagegen nicht.
  • Ein Feld für eine URL gibt es nicht. Eine Live-Seite müssen Sie zuerst speichern. „Webseite, einzelne Datei“ (.mhtml) wird nicht angenommen – nehmen Sie „Webseite, nur HTML“ und rechnen Sie mit fehlenden relativen Bildern, oder nutzen Sie gleich Drucken > Als PDF speichern im Browser.
  • Druck-Styles greifen. Enthält die Seite CSS für @media print, verwendet der Konverter dieses in der Regel. Dadurch können Navigationsleisten verschwinden oder Farben anders aussehen als am Bildschirm. Seitenumbrüche steuern Sie per CSS mit break-before und break-inside.
  • Per JavaScript erzeugte Inhalte sind unzuverlässig. Seiten, die ihren Inhalt erst nach dem Laden per Skript nachladen, kommen womöglich als leere Hülle heraus. Speichern Sie die Seite, nachdem sie vollständig geladen ist, oder erzeugen Sie den Inhalt serverseitig direkt im HTML.
  • Layouts, die breiter sind als eine gedruckte Seite – etwa feste 1400-Pixel-Designs oder breite Tabellen –, können abgeschnitten oder verkleinert werden. Ein responsives Layout oder eine max-width für den Hauptinhalt behebt das meist.

Tipps für beste Ergebnisse

  • Packen Sie bei eigenen Vorlagen das gesamte CSS in einen <style>-Block im <head>. Das ist der zuverlässigste Weg zu einem sauber gestalteten PDF.
  • Mit @page { size: A4; margin: 15mm; } im CSS legen Sie eine bestimmte Seitengröße und Ränder fest.
  • Setzen Sie break-inside: avoid auf Tabellenzeilen, Karten und Abbildungen, damit sie nicht über zwei Seiten verteilt werden.
  • Achten Sie auf vernünftige Bildgrößen: Ein 5 MB großes Titelbild als Data-URI ergibt trotzdem ein 5 MB großes PDF.
  • Schauen Sie sich die HTML-Datei zuerst in der Druckvorschau Ihres Browsers an. Sieht sie dort falsch aus, wird das umgewandelte PDF vermutlich ähnlich aussehen.

Praxisbeispiel: Teilnahmebestätigungen für Volkshochschulkurse

Ein Entwickler aus Wien erzeugt für die Volkshochschulkurse einer Bekannten Teilnahmebestätigungen als HTML-Dateien. Die Vorlage ist querformatig gestaltet, mit einer festen Breite von 1123 Pixeln, lädt die Schrift aus fonts/lora.woff2 und ein Hintergrundmotiv aus hintergrund.jpg – beides per relativem Pfad. Der erste Versuch mit „HTML in PDF“ liefert eine Hochformatseite in Standardschrift, ohne Hintergrund, und der rechte Teil der Urkunde ist abgeschnitten.

Er ändert drei Dinge an der Vorlage. Mit @page { size: A4 landscape; margin: 0; } und einer max-width für den Hauptcontainer passt die Urkunde auf eine Querformatseite. Die Schrift bindet er über eine öffentliche https-Adresse ein. Das Hintergrundmotiv verkleinert er zunächst auf rund 300 KB und bettet es dann als Data-URI ein, damit nicht jede Bestätigung unnötig groß wird.

Danach kommt jede Bestätigung als einseitiges A4-Querformat mit der richtigen Schrift und dem Hintergrund heraus. Weil auf jedem Blatt der Name einer Teilnehmerin oder eines Teilnehmers steht und die Datei zur Umwandlung an einen externen Dienst geht, bespricht er vorher mit der Kursleiterin, ob das für sie in Ordnung ist.

Fehlerbehebung

Das PDF hat keine Gestaltung, nur nackten Text
Das Stylesheet war über einen relativen Pfad eingebunden und wurde nicht hochgeladen. Betten Sie das CSS in einen <style>-Block ein oder verlinken Sie es mit einer vollständigen https://-Adresse.
Bilder fehlen
Bilder auf Ihrer Festplatte mit relativem Pfad sind für den Server nicht erreichbar. Verwenden Sie öffentliche https://-URLs oder betten Sie die Bilder als Data-URIs ein und wandeln Sie erneut um.
Die Seite ist rechts abgeschnitten
Das Layout hat eine feste Breite, die größer als die Seite ist. Ergänzen Sie max-width: 100% für Hauptcontainer und Bilder oder ein Druck-Stylesheet, das das Layout schmaler macht.
Das PDF ist leer oder fast leer
Der Inhalt wird wahrscheinlich erst nach dem Laden per JavaScript erzeugt, oder die Datei ist nur eine Weiterleitung. Speichern Sie die Seite, wenn sie vollständig gerendert ist, oder schreiben Sie den Inhalt direkt ins HTML.
Der Text erscheint in einer anderen Schrift
Lokal eingebundene Webfonts waren nicht verfügbar. Binden Sie die Schrift über eine öffentliche URL ein, betten Sie sie per @font-face als Data-URI ein oder verwenden Sie gängige Systemschriften.
Das Tool lehnt meine Datei ab
Angenommen werden nur .html und .htm. Gespeicherte .mhtml- oder .webarchive-Dateien müssen Sie erneut als „nur HTML“ speichern.

Häufig gestellte Fragen

Kann ich einfach die Adresse einer Website eingeben?

Nein. Umgewandelt wird eine HTML-Datei, die Sie auswählen. Speichern Sie die Seite also zuerst als HTML – oder nutzen Sie bei einer Live-Seite im Browser Drucken > Als PDF speichern.

Verlässt die HTML-Datei meinen Rechner?

Ja. Sie wird verschlüsselt an den Konvertierungsdienst geschickt, dort gerendert und danach gelöscht. Seiten mit personenbezogenen Daten, die kein Drittanbieter verarbeiten soll, wandeln Sie deshalb besser nicht hier um.

Warum fehlen im PDF die Bilder und die Gestaltung?

Hochgeladen wird nur die HTML-Datei selbst. Dateien, die sie über relative Pfade einbindet, bleiben auf Ihrem Rechner. Verwenden Sie vollständige https://-Adressen oder betten Sie Bilder und CSS direkt ins HTML ein.

Wo stelle ich Seitenformat und Ränder ein?

Auf der Tool-Seite gar nicht, sondern im HTML selbst mit einer CSS-Regel @page, zum Beispiel @page { size: A4; margin: 15mm; }.

Kann man im PDF auf die Links klicken?

Links auf Webadressen funktionieren in der Regel weiter. Relative Links auf andere Dateien auf Ihrem Rechner führen dagegen ins Leere.

Wird JavaScript bei der Umwandlung ausgeführt?

Unter Umständen teilweise. Inhalte, die erst später nachgeladen werden oder eine Eingabe brauchen, fehlen aber häufig. Zuverlässig wird das Ergebnis, wenn der endgültige Inhalt schon im HTML steht.
