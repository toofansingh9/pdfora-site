Sending a payslip, a medical letter or a tax return as a plain attachment means anyone who sees the inbox, a forwarded thread or a shared laptop can read it. An open password changes that: the file is encrypted, and without the password it is just scrambled bytes. PDFora's Protect PDF tool adds that password, lets you decide what the reader may do once the file is open, and does it without your document ever leaving your device.

Under the hood the tool runs qpdf, a long-established open-source PDF library, compiled to WebAssembly so it works inside the browser tab. The engine is about 1.3 MB and is loaded from this site the first time you use the tool. It encrypts the file with AES-256 (the strongest encryption the PDF format defines), sets the open password you type, and writes a new copy named after the original with -protected added. The pages themselves are not touched: text, images, links and fonts stay exactly as they were.

PDF security has two passwords, and the difference matters. The open password (user password) is the real lock; without it nobody can read the content. The permissions password (owner password) only controls the restriction flags for printing, copying and editing. Those flags are honoured by Acrobat, browsers and most mainstream readers, but they are a request to the software rather than a barrier, and some programs ignore them. Treat the open password as your protection and the restrictions as a polite sign on the door.

How to password-protect a PDF

  1. Open Protect PDF and add one file. If it already has a password, the tool will stop and ask you to unlock it first.
  2. Type the password readers will need to open the file, then type it again in Repeat password. The two must match exactly.
  3. Untick Allow printing, Allow copying text and images or Allow editing and form filling if you want those actions blocked; all three are allowed by default.
  4. Optionally enter a separate permissions password. Leave it empty and the tool generates a long random one, so the restrictions cannot be changed later.
  5. Click Protect PDF, download yourfile-protected.pdf, then open it once to confirm the password prompt appears before you send it.

When to use this tool

  • Payslips and salary letters emailed to staff, each opened with a password agreed in person or by phone.
  • Medical reports, legal advice or HR documents that should be readable only by the person they are addressed to.
  • Tax returns, bank statements and ID copies sent to an accountant or a lender by email.
  • Exam papers shared with co-teachers a week before the exam, with copying switched off as an extra nudge.
  • Signed contracts stored on a shared drive or cloud folder that more people can browse than should read them.
  • A price list or report for a client where you want to discourage printing and copying, knowing the flags are a deterrent rather than a lock.

What to know before you start

  • Encryption is AES-256. Current versions of Acrobat and Adobe Reader, Chrome, Edge, Firefox and macOS Preview open such files without trouble; very old PDF readers may not open them at all.
  • The open password is required and is the only thing that actually keeps the content private. Pick a long one; with AES-256 the password is the realistic weak point, not the algorithm.
  • The three restriction checkboxes set permission flags. Compliant readers respect them, but they are not strong security: software that ignores the flags can print or copy the text once the file is open.
  • If you leave the permissions password empty, a random 36-character one is generated and never shown. That locks the restrictions in place; to change them later, unlock the file with the open password and protect it again.
  • Files that are already encrypted are refused with a message to unlock them first. The tool does not stack a second password on top of an existing one.
  • Everything runs in your browser. The file and the password are never uploaded, and there is no copy of either on our side, so a forgotten open password cannot be recovered by us or anyone else.

Tips for the best results

  • Use a passphrase of four or more unrelated words rather than a short string of symbols; it is both harder to guess and easier to read out over the phone.
  • Send the password by a different channel from the file: the PDF by email, the password by text message or a call.
  • Protect as the last step. Merge, compress, edit and add page numbers first, because other tools cannot work on an encrypted file.
  • Keep an unprotected master copy somewhere safe, so a later change does not depend on remembering the password.
  • Store the password in a password manager entry named after the file, not in the email, the file name or a note on the monitor.

A worked example: a small practice sending tax returns

A two-person accounting practice sends about 60 clients a draft tax return for review each spring. Each return is a 14-page PDF of roughly 380 KB, exported from their tax software. Until now it went out as a plain attachment, which meant a shared family inbox or a forwarded thread exposed income, bank details and national ID numbers.

They add one step. Each return goes through Protect PDF with the client's passphrase as the open password, agreed once on the phone at the start of the engagement and recorded in the practice's shared password manager. Printing stays allowed, because many clients print the draft to annotate it, but editing is switched off so nobody mistakes an altered copy for the practice's version. The permissions password is left empty. On their office laptop the first file takes a couple of seconds while the engine loads; after that each one is almost instant, and the protected files come out close to the original size.

Before the batch goes out they open three of the protected files in Adobe Reader and on a phone to check the password prompt appears and the pages look right. The step adds well under a minute per client. It does not stop a client from forwarding the file together with the password, and it does not make a weak passphrase strong, so they ask every client for at least four words. The encryption is the easy part; keeping the passwords out of the email body is where the real protection comes from.

Troubleshooting

It says the two passwords do not match
Retype both fields. Watch for Caps Lock and for a trailing space pasted from another app; the comparison is exact.
It says the PDF is already protected
The file has an open password or permission restrictions already. Remove them with Unlock PDF (you need the current open password if it asks for one), then protect the unlocked copy with your new settings.
The recipient's app will not open the file
Very old PDF readers may not support AES-256. Ask the recipient to open it in a current browser, Adobe Reader or Preview rather than lowering the security.
The recipient can still print or copy
Their reader is ignoring the permission flags, which some programs do. The flags are not strong security; if the content must not be copied, limit who receives it.
The encryption engine does not load
The engine is loaded from this site on first use. A very slow connection, a script blocker or an aggressive corporate filter can stop it; reload the page and try again, or try another network.
It says it could not encrypt this PDF
The file is probably damaged in a way the engine cannot write back out. Run it through Repair PDF and protect the repaired copy.

Frequently asked questions

Is my file or password sent to a server?

No. The encryption engine runs inside your browser tab. The PDF and the password stay on your device, and nothing is stored after you close the tab.

What encryption does it use?

AES with a 256-bit key, the strongest option the PDF standard offers. The security in practice depends on how long and unpredictable your password is.

What is the difference between the password and the permissions password?

The password is needed to open and read the file. The permissions password only controls whether printing, copying and editing are allowed, and is needed to change those settings later.

Can people remove the restrictions on printing and copying?

Anyone who can open the file can, with software that ignores the flags. Restrictions discourage casual copying; only the open password keeps the content private.

What if I forget the password?

It cannot be recovered. There is no backdoor in AES-256 and we never see the password. Keep an unprotected original and store the password in a password manager.

Will protecting the PDF change how it looks or its size?

No. The pages are left exactly as they were and the file size usually stays close to the original. What changes is who can open it and what the reader app allows.
