First, the honest status: the Protect PDF tool is not working yet. If you choose a file and click the button, you will see a message that password protection is coming soon. It needs a dedicated processing route that is still being built, and we would rather say so than offer a tool that produces a file which only looks protected. This page explains how PDF passwords work, what the tool is meant to do, and how to protect a file right now with software you probably already have.

PDF security has two separate passwords, and mixing them up is the most common mistake. An open password (also called a user password) encrypts the file, so it cannot be read at all without the password. A permissions password (owner password) lets anyone open the file but asks the reader's software to restrict actions such as printing, copying text or editing. The first is real protection; the second depends on the reader's software respecting the flags, and many programs can ignore them.

How strong the protection is depends on the encryption used. Modern PDF software uses AES with 128-bit or 256-bit keys; old files may use RC4, which is considered weak. With AES-256, the realistic weak point is the password itself: a short or guessable one can be found by trying many candidates, whatever the algorithm.

How to password-protect a PDF today

  1. In Microsoft Word, choose File > Save As, pick PDF, open Options and tick 'Encrypt the document with a password' before saving.
  2. In LibreOffice, use File > Export as PDF, open the Security tab and set an open password, a permissions password or both.
  3. On a Mac, open the PDF in Preview, choose File > Export, tick Encrypt (or use the Permissions options) and enter a password.
  4. In other PDF editors, look for Security, Protect or Encrypt in the file or tools menu, and choose AES-256 if it is offered.
  5. Close the file, open it again and confirm the password prompt appears before you send it.

When to use this tool

  • Payslips and salary letters emailed to staff, opened with a password agreed separately.
  • Medical or legal documents sent to a client who should be the only reader.
  • A tenant's reference and ID copies that a landlord must store but should not leave readable on a shared drive.
  • Exam papers prepared in advance and shared with co-teachers before the exam date.
  • Tax returns and bank statements sent to an accountant by email.
  • Discouraging casual copying of a published booklet with a permissions password (knowing it is a deterrent, not a lock).

What to know before you start

  • The Protect tool currently shows 'coming soon' and does not change your file. Use one of the methods above until it launches.
  • An open password encrypts the content; without it, the file cannot be read. This is the option to use for confidential documents.
  • A permissions password only sets restriction flags. The text is still readable, and some programs do not enforce the flags.
  • If you lose an open password on a properly encrypted file, there is no backdoor. Keep the password in a password manager, not in the same email as the file.
  • Encrypting a PDF does not hide its existence or its file name, and some metadata may remain visible depending on the software. Rename the file if the name itself is sensitive.
  • Other PDFora tools cannot open encrypted PDFs; do your merging, compressing or editing first and add the password last. A protected file sent to the wrong address is still unreadable to that person, which is the main practical benefit of an open password over a plain attachment.

Tips for the best results

  • Use a long passphrase, four or more unrelated words, rather than a short password with symbols.
  • Send the password by a different channel from the file, for example the PDF by email and the password by text message or phone.
  • Choose AES-256 when the software offers a choice; avoid 40-bit or RC4 options, which exist only for very old readers.
  • Keep an unprotected master copy in a secure place, so you can make changes later without needing to unlock anything.
  • Protect as the final step: finish editing, compressing and merging, then encrypt.

Example: a small accounting practice sending tax documents

A two-person accounting practice sends each client a prepared tax return for review. Until now they emailed the PDF as it was, which meant anyone who saw the inbox, a forwarded thread or a shared family laptop could read it.

They change one step. The return is exported from their software as normal, then opened in LibreOffice and exported again with an open password, using AES encryption. The password is the client's chosen passphrase, agreed once on the phone at the start of the engagement and never sent by email. The PDF email goes out as before; the client opens it with a passphrase only they and the practice know.

The process adds about a minute per client. It does not protect against a client who forwards the file with the password, and a weak passphrase could still be guessed, so they ask clients for at least four words. When PDFora's Protect tool launches it will fit into the same step; until then, the desktop route works. It is also worth deciding up front who keeps the passwords. In a small office, a shared password manager entry per client avoids the situation where only one person can open last year's files. Writing the password into the email body, the file name or a sticky note on the monitor undoes the whole exercise. The encryption itself is the easy part; handling the password sensibly is where most real-world protection fails, whichever tool is used to apply it.

Troubleshooting

The Protect tool says 'coming soon'
That is the current state of the tool; it does not process files yet. Use Word, LibreOffice, Preview or another PDF editor as described above.
The recipient can open my file without a password
You probably set only a permissions password. Set an open (user) password so the document is encrypted.
The recipient's app does not accept the password
Very old readers may not support AES-256. Ask them to use a current PDF reader rather than lowering the encryption.
I can no longer merge or compress the file
Encrypted PDFs cannot be processed by most tools, including PDFora's. Work on the unprotected master copy and protect it again afterwards.
The printing restriction is being ignored
Permission flags depend on the reader's software. If a document must not be printed or copied, a PDF permissions password is not enough; limit who receives it.
I forgot the open password
There is no recovery option for strong encryption. Go back to the unprotected original or the program that created the file.

Frequently asked questions

Does the Protect PDF tool work yet?

Not yet. It currently shows a 'coming soon' message and does not change your file.

What is the difference between an open password and a permissions password?

An open password encrypts the file so it cannot be read without it. A permissions password only asks reader software to restrict printing, copying or editing.

Is a password-protected PDF really secure?

With AES encryption and a long password, it is very hard to break. Short or common passwords are the real weakness.

Can I protect a PDF on my phone?

Some mobile PDF apps offer it, usually in a share, security or export menu. On a computer, Word, LibreOffice and Preview all include it.

Will protecting the PDF change how it looks?

No. Encryption does not change the content or layout, only who can open it or what the reader app allows.

Will the tool be free when it launches?

Yes, it is planned as a free tool like the rest of the site.
