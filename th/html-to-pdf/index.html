HTML เป็น PDF

แปลงไฟล์ HTML ที่บันทึกไว้เป็น PDF ผ่านเซิร์ฟเวอร์แปลงไฟล์ เปลี่ยนหน้าเว็บหรือไฟล์ HTML ที่ส่งออกมาให้เป็นหน้ากระดาษตายตัวที่พร้อมพิมพ์

🔒 ไฟล์ของคุณถูกประมวลผลภายในเบราว์เซอร์ของคุณและไม่เคยถูกอัปโหลด
1

อัปโหลด

เลือกหรือลากแล้ววางไฟล์ของคุณ

2

ปรับแต่ง

เลือกตัวเลือกของคุณ — ทุกอย่างเกิดขึ้นในเบราว์เซอร์ของคุณ

3

ดาวน์โหลด

บันทึกไฟล์ที่เสร็จแล้วได้ทันที ไม่มีลายน้ำ

เอกสารที่มีประโยชน์หลายอย่างมีอยู่ในรูปแบบ HTML เท่านั้น เช่น หน้ายืนยันคำสั่งซื้อที่บันทึกจากเบราว์เซอร์ รายงานที่แอปส่งออกมา จดหมายข่าว คู่มือที่สร้างเป็นหน้าเดียวยาวๆ หรือหน้าเว็บที่คุณทำเอง HTML จะจัดตัวเองใหม่ตามขนาดหน้าต่างที่เปิดอยู่ ซึ่งเป็นสิ่งที่คุณไม่ต้องการเลยเมื่อต้องเก็บเข้าแฟ้ม พิมพ์ หรือแนบไปกับคำร้อง PDF จะตรึงเนื้อหาไว้ที่ขนาดหน้ากระดาษเดียว

เครื่องมือนี้รับไฟล์ .html หรือ .htm จากเครื่องของคุณ ไม่ใช่ที่อยู่เว็บ ไฟล์จะถูกอัปโหลดแบบเข้ารหัสไปยังบริการ CloudConvert ผ่านตัวส่งต่อของ PDFora ที่นั่นเอนจินแสดงผลจะจัดหน้าแล้วพิมพ์ออกมาเป็น PDF ไฟล์ผลลัพธ์ส่งกลับมาโดยใช้ชื่อเดียวกับไฟล์ของคุณ และถูกลบออกจากบริการหลังจากนั้น การแปลงไม่ได้เกิดในเบราว์เซอร์ของคุณ และบนหน้าเครื่องมือไม่มีตัวเลือกขนาดหน้าหรือระยะขอบ

เรื่องที่คนส่วนใหญ่แปลกใจที่สุดคือสิ่งที่เกิดกับไฟล์อื่นๆ ที่ HTML อ้างถึง หน้าเว็บแทบไม่เคยเป็นไฟล์เดียว รูปภาพ สไตล์ชีต และฟอนต์มักเป็นไฟล์แยกที่ HTML ลิงก์ไป แต่ระบบอัปโหลดเฉพาะไฟล์เดียวที่คุณเลือก อะไรที่อ้างด้วยพาธแบบสัมพัทธ์บนดิสก์ของคุณ เซิร์ฟเวอร์จึงหาไม่เจอ การได้ PDF ที่ตรงกับต้นฉบับจึงขึ้นอยู่กับการทำให้ไฟล์ HTML สมบูรณ์ในตัวเองก่อนแปลงเป็นหลัก

วิธีแปลง HTML เป็น PDF

  1. ตรวจให้แน่ใจว่าไฟล์ HTML สมบูรณ์ในตัวเอง หรือใช้ที่อยู่เว็บเต็มรูปแบบ (https://...) สำหรับรูปภาพและสไตล์ชีต ดูรายละเอียดด้านล่าง
  2. เปิดเครื่องมือ HTML เป็น PDF แล้วเลือกไฟล์ .html หรือ .htm
  3. คลิก แปลง แล้วรอระหว่างที่ไฟล์ถูกอัปโหลดและแสดงผลบนเซิร์ฟเวอร์
  4. ดาวน์โหลด PDF ซึ่งใช้ชื่อเดิมของไฟล์คุณแต่เป็นนามสกุล .pdf
  5. ตรวจดูว่ารูปภาพ สี และเลย์เอาต์มาครบ และไม่มีเนื้อหาถูกตัดที่ขอบด้านขวา

ควรใช้เครื่องมือนี้เมื่อใด

  • ใบเสร็จและหน้ายืนยันการจองที่บันทึกจากเบราว์เซอร์ เก็บเป็น PDF ไว้ทำบัญชีหรือเป็นหลักฐาน
  • รายงานที่โปรแกรมส่งออกเป็น HTML ซึ่งต้องแนบไปกับอีเมลหรือเก็บเข้าคลัง
  • นักพัฒนาที่แปลงเทมเพลตใบแจ้งหนี้ ใบประกาศ หรือจดหมายที่สร้างเป็น HTML ให้เป็น PDF เพื่อเช็กเลย์เอาต์ตอนพิมพ์
  • คู่มือหรือเอกสารการใช้งานที่เผยแพร่เป็นหน้า HTML ยาวหน้าเดียว พิมพ์ออกมาไว้อ่านแบบออฟไลน์
  • บทความเว็บที่บันทึกไว้ใช้ค้นคว้า ในรูปแบบที่ไม่เปลี่ยนตามแม้เว็บไซต์ต้นทางจะเปลี่ยน
  • จดหมายข่าวทางอีเมลที่บันทึกเป็น HTML แล้วแปลงเก็บไว้เป็นหลักฐานว่าส่งอะไรออกไป

สิ่งที่ควรรู้ก่อนเริ่ม

  • ลิงก์แบบสัมพัทธ์จะใช้ไม่ได้ ถ้า HTML เขียนว่า <img src="images/logo.png"> หรือ <link href="style.css"> ไฟล์เหล่านั้นยังอยู่ในเครื่องคุณและเซิร์ฟเวอร์มองไม่เห็น PDF จะออกมาโดยไม่มีรูปและข้อความไม่มีสไตล์ ให้ใช้ที่อยู่ https:// แบบเต็ม หรือฝัง CSS ไว้ในบล็อก <style> และฝังรูปเป็น data URI
  • ทรัพยากรที่ใช้ที่อยู่เว็บเต็มอาจถูกเซิร์ฟเวอร์ดึงมาตอนแสดงผล รูปและสไตล์ชีตที่เข้าถึงได้แบบสาธารณะจึงมักแสดงขึ้น แต่อะไรที่ต้องล็อกอิน อยู่ในอินทราเน็ต หรืออยู่บน localhost จะไม่แสดง
  • ไม่มีช่องใส่ URL ถ้าจะแปลงหน้าเว็บจริงต้องบันทึกก่อน ไฟล์ที่ได้จาก บันทึกหน้าเป็น > หน้าเว็บ ไฟล์เดียว (.mhtml) ใช้ไม่ได้ ให้เลือก หน้าเว็บ เฉพาะ HTML และเตรียมใจว่ารูปที่อ้างแบบสัมพัทธ์จะหายไป หรือใช้ พิมพ์ > บันทึกเป็น PDF ของเบราว์เซอร์แทน
  • สไตล์สำหรับการพิมพ์มีผล ถ้าหน้าเว็บมี CSS สำหรับ @media print ตัวแปลงมักใช้ CSS นั้น ซึ่งอาจซ่อนแถบเมนูหรือเปลี่ยนสีไปจากที่เห็นบนจอ การขึ้นหน้าใหม่ควบคุมได้ด้วย break-before และ break-inside ใน CSS
  • เนื้อหาที่สร้างด้วย JavaScript ไม่แน่นอน หน้าที่ใช้สคริปต์ดึงเนื้อหาหลังโหลดอาจแปลงออกมาเป็นแค่โครงเปล่า ให้บันทึกหน้าหลังจากโหลดเสร็จสมบูรณ์ หรือสร้างเนื้อหาลงใน HTML ตั้งแต่ฝั่งเซิร์ฟเวอร์
  • เลย์เอาต์ที่กว้างกว่าหน้ากระดาษ เช่น ดีไซน์ที่ล็อกความกว้างไว้ 1400 พิกเซล หรือตารางกว้างๆ อาจถูกตัดหรือถูกย่อ เลย์เอาต์แบบ responsive หรือการกำหนด max-width ให้เนื้อหาหลักมักแก้ได้

เคล็ดลับเพื่อผลลัพธ์ที่ดีที่สุด

  • สำหรับเทมเพลตของคุณเอง ให้ใส่ CSS ทั้งหมดในบล็อก <style> ภายใน <head> นี่คือวิธีที่ได้ผลแน่นอนที่สุดในการได้ PDF ที่มีสไตล์ครบ
  • เพิ่ม @page { size: A4; margin: 15mm; } ลงใน CSS ถ้าต้องการขนาดหน้าหรือระยะขอบที่เจาะจง
  • ใช้ break-inside: avoid กับแถวตาราง การ์ด และรูปประกอบ เพื่อไม่ให้ถูกแบ่งไปอยู่สองหน้า
  • ใช้รูปขนาดพอเหมาะ รูปแบนเนอร์ 5 MB ที่ฝังเป็น data URI ก็ยังทำให้ PDF หนัก 5 MB อยู่ดี
  • เปิดไฟล์ HTML ในหน้าตัวอย่างก่อนพิมพ์ของเบราว์เซอร์ก่อน ถ้าตรงนั้นดูผิด ใน PDF ที่แปลงออกมาก็มีแนวโน้มจะผิดเหมือนกัน

ตัวอย่างจริง: เทมเพลตใบแจ้งหนี้ HTML ของร้านออนไลน์เล็กๆ

ร้านออนไลน์ที่ทำกันสองคนสร้างใบแจ้งหนี้เป็นไฟล์ HTML จากสคริปต์ง่ายๆ แต่ละไฟล์ลิงก์ไปที่ invoice.css และ logo.png ในโฟลเดอร์เดียวกัน พอแปลงตรงๆ PDF ออกมาเป็นตัวหนังสือดำล้วนในฟอนต์มาตรฐาน ไม่มีโลโก้ และตารางยอดรวมยืดเต็มความกว้าง เพราะเซิร์ฟเวอร์ได้รับแค่ไฟล์ HTML โดยไม่มีสไตล์ชีตและรูปภาพ

ทางแก้คือทำให้ไฟล์อยู่ได้ด้วยตัวเอง ตอนนี้สคริปต์คัดลอกเนื้อหาของ invoice.css ลงในบล็อก <style> เพิ่ม @page { size: A4; margin: 18mm; } และใส่ break-inside: avoid ให้แถวรายการสินค้า แล้วเปลี่ยนโลโก้ให้ชี้ไปยังที่อยู่ https สาธารณะบนเว็บไซต์ของร้านแทนพาธในเครื่อง นอกนั้นไม่มีอะไรเปลี่ยน

เมื่อแปลงอีกครั้ง ใบแจ้งหนี้กลายเป็น PDF ขนาด A4 หน้าเดียว มีโลโก้ สีประจำร้าน และตารางยอดรวมที่ไม่ถูกแบ่งครึ่งอีกแล้วแม้ออร์เดอร์จะมีหลายรายการ และเพราะเทมเพลตสมบูรณ์ในตัวเองแล้ว ใบแจ้งหนี้ทุกใบที่สคริปต์สร้างก็แปลงออกมาได้แบบเดียวกัน

การแก้ปัญหา

PDF ไม่มีสไตล์เลย เป็นแค่ข้อความเปล่า
สไตล์ชีตถูกอ้างด้วยพาธแบบสัมพัทธ์จึงไม่ได้ถูกอัปโหลดไปด้วย ให้ฝัง CSS ไว้ในบล็อก <style> หรือลิงก์ด้วยที่อยู่ https:// แบบเต็ม
รูปภาพหายไป
รูปในเครื่องที่อ้างด้วยพาธแบบสัมพัทธ์เข้าถึงไม่ได้ ให้ใช้ URL https:// สาธารณะ หรือฝังรูปเป็น data URI แล้วแปลงใหม่
หน้าถูกตัดทางด้านขวา
เลย์เอาต์มีความกว้างตายตัวที่มากกว่าหน้ากระดาษ ให้เพิ่ม max-width: 100% ให้กล่องเนื้อหาหลักและรูปภาพ หรือเพิ่มสไตล์ชีตสำหรับพิมพ์ที่ทำให้เลย์เอาต์แคบลง
PDF ว่างเปล่าหรือเกือบว่าง
เนื้อหาน่าจะถูกสร้างด้วย JavaScript หลังโหลด หรือไฟล์เป็นแค่หน้าเปลี่ยนเส้นทาง ให้บันทึกหน้าหลังจากแสดงผลครบแล้ว หรือสร้างเนื้อหาไว้ใน HTML โดยตรง
ข้อความออกมาเป็นฟอนต์อื่น
เว็บฟอนต์ที่อ้างจากในเครื่องใช้ไม่ได้ ให้ลิงก์ฟอนต์จาก URL สาธารณะ ฝังด้วย @font-face และ data URI หรือใช้ชุดฟอนต์ที่มีทั่วไป
เครื่องมือไม่รับไฟล์ของฉัน
รับเฉพาะ .html และ .htm ไฟล์ .mhtml หรือ .webarchive ที่บันทึกไว้ต้องบันทึกใหม่เป็นแบบเฉพาะ HTML

คำถามที่พบบ่อย

แปลงเว็บไซต์โดยใส่ URL ได้ไหม?

ไม่ได้ เครื่องมือนี้แปลงไฟล์ HTML ที่คุณเลือก ให้บันทึกหน้าเป็น HTML ก่อน หรือใช้ พิมพ์ > บันทึกเป็น PDF ของเบราว์เซอร์สำหรับหน้าเว็บที่เปิดอยู่

ไฟล์ HTML ถูกอัปโหลดหรือเปล่า?

ใช่ ไฟล์ถูกส่งแบบเข้ารหัสไปยังบริการแปลงไฟล์ แสดงผลที่นั่นแล้วถูกลบทิ้ง หลีกเลี่ยงการแปลงหน้าที่มีข้อมูลส่วนตัวที่คุณไม่อยากให้บุคคลที่สามประมวลผล

ทำไมรูปภาพและ CSS ของฉันหายไป?

ระบบอัปโหลดเฉพาะไฟล์ HTML เท่านั้น ไฟล์ที่อ้างด้วยพาธแบบสัมพัทธ์ยังอยู่ในเครื่องคุณ ให้ใช้ลิงก์ https:// แบบเต็มหรือฝังไว้ใน HTML

ตั้งขนาดหน้าหรือระยะขอบได้ไหม?

บนหน้าเครื่องมือตั้งไม่ได้ ให้กำหนดใน HTML ด้วยกฎ CSS @page เช่น @page { size: A4; margin: 15mm; }

ลิงก์ใน PDF คลิกได้ไหม?

ลิงก์ไปยังที่อยู่เว็บปกติยังคลิกได้ ส่วนลิงก์แบบสัมพัทธ์ไปยังไฟล์อื่นในเครื่องจะไม่พาไปที่ไหนที่ใช้งานได้

JavaScript ทำงานระหว่างแปลงไหม?

อาจทำงานได้บางส่วน แต่เนื้อหาที่โหลดช้าหรือต้องรอผู้ใช้กดก่อนมักหายไป ถ้าต้องการผลที่แน่นอน HTML ควรมีเนื้อหาสุดท้ายอยู่ในไฟล์แล้ว
