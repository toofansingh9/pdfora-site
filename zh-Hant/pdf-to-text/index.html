PDF 轉文字

把 PDF 的文字層取出來，存成純文字 .txt 檔，方便搜尋、貼上或進一步處理。

手動從 PDF 複製文字又慢又亂：選取範圍會跨欄亂跳，每一頁都重複出現頁首，長篇文件得「全選」幾十次。這個工具會讀取 PDF 裡原本就存著的文字，全部寫進一個純文字檔，一頁接著一頁，可以直接拿到文字編輯器、試算表或程式裡使用。

這裡說的「文字」是什麼，要先弄清楚。用文書軟體、瀏覽器或會計軟體產生的 PDF，裡面存有真正的字元和它們的位置。PDF.js 會逐頁讀取這些字元，把同一頁的片段用空格接起來，頁與頁之間用一個空行隔開。掃描頁就不一樣了，它是紙張的照片，裡面根本沒有任何字元，所以這個工具對它什麼也取不出來。掃描檔需要用 OCR 來辨識圖片中的文字。

輸出刻意保持最簡單。沒有粗體、沒有字型、沒有表格、沒有圖片，頁面內原本的換行也不會保留；每一頁都會變成一長串連續的文字。這讓檔案很容易搜尋，也方便丟給其他工具處理，但無法用來重建文件的版面。如果版面很重要，「PDF 轉 Word」會是比較好的選擇。

如何從 PDF 擷取文字

  1. 開啟「PDF 轉文字」並選擇一個 PDF 檔案。
  2. 按下「擷取文字」。工具會依序讀取每一頁的文字內容，進度列一頁一頁前進。
  3. 完成後，結果會顯示處理了多少頁。下載以 PDF 檔名命名的 .txt 檔（thesis.pdf 會變成 thesis.txt）。
  4. 用文字編輯器開啟檔案，搜尋一段你確定文件裡有的句子，確認文字都有取出來。
  5. 如果整頁都是空的，代表那些頁面是圖片；這些頁面的文字可以用「OCR PDF」辨識，以 .txt 檔的形式取得。

適用情境

  • 在自己的筆記中引用論文或研究報告的段落，不用重新打字。
  • 用文字編輯器的尋找功能，在長篇合約或規章中找出某個詞的每一處出現位置。
  • 把文件丟進字數統計、翻譯工具，或需要純文字輸入的程式。
  • 原始可編輯檔案遺失時，取回文件的文字內容，作為新版本的起點。
  • 了解螢幕閱讀器或搜尋引擎大概會在 PDF 裡看到什麼，因為它們讀的是同一層文字。
  • 從對帳單中取出數字，貼到試算表裡再整理。

開始前需要了解

  • 只會讀取文字層。掃描頁、文件照片，以及已轉成外框的文字，在輸出中都會是空白或幾乎空白的頁面。
  • 同一頁的文字片段以單一空格連接，頁與頁之間以一個空行分隔。頁面內的換行不會保留，所以段落和表格各列會連在一起。
  • 讀取順序依照文字在 PDF 中儲存的順序，通常和視覺順序一致，但不一定。雙欄版面、側欄和註腳可能會交錯出現。
  • 頁首、頁尾和頁碼每一頁都會出現，因為對 PDF 來說它們就是一般文字。
  • 有些 PDF 會逐字儲存文字，或間距很奇怪，導致字詞中間出現多餘的空格。有些則使用沒有正確字元對照表的字型，取出來會是一堆亂碼符號而不是文字。
  • 圖片、圖表和示意圖中的文字不會被擷取，尚未平面化到頁面上的表單欄位文字也不會。在 PDF 中被拆到兩行的英文連字號單字，通常會維持拆開，中間夾著連字號和一個空格。搜尋「- 」就能找到大部分。

獲得最佳效果的訣竅

  • 如果結果是亂碼或空白，先試試在一般 PDF 檢視器裡能不能選取文字。如果在那裡也選不起來，擷取也不會成功，這時就改用「OCR PDF」：它會辨識頁面圖片，把文字輸出成 .txt 檔。
  • 用編輯器的「尋找及取代」一次清掉重複的頁首和頁尾，不必每一頁手動修改。
  • 表格的話，「PDF 轉 Excel」能讓列與欄保持分開；純文字則會把每一列擠成一行。
  • 如果編輯器詢問，請把 .txt 存成 UTF-8；從 PDF 取出的中文、重音字母等非拉丁字元都會以 Unicode 保留。
  • 如果只需要其中一章，先分割大型 PDF；文字檔越小越好處理。隱藏文字，例如其他程式的 OCR 加在掃描圖片底下的文字層，會像其他文字一樣被擷取。

實際範例：法律系學生整理閱讀資料

一位法律系學生從法院網站下載了一份 60 頁的判決書 PDF，想找出每一段引用某個先前判決的地方，再把那些段落貼進筆記。在 PDF 檢視器裡捲動複製時，每一段都會連帶抓到頁首。

她擷取文字後，用純文字編輯器開啟 judgment.txt。搜尋那個判決字號，找到十一處。因為每一頁都是一整塊文字，她可以靠數空行大致知道每個結果在第幾頁；頁首那一行出現在每一頁區塊的開頭，很容易略過。

有一頁出來是空的。重新打開 PDF，她發現那是夾在判決書裡的一份掃描附件。她用「OCR PDF」處理判決書，再從產生的 .txt 檔複製附件的文字，貼進空缺的地方。這個道理適用於所有情況：一份 PDF 可能同時有真正的文字頁和圖片頁，只有前者能直接擷取。

疑難排解

文字檔是空的，或只有空行
這個 PDF 是掃描檔或由圖片組成。請改用「OCR PDF」：它會辨識頁面圖片，把文字輸出成 .txt 檔。
輸出滿是奇怪的符號
PDF 使用的字型沒有可用的字元對照表，所以字元無法轉回文字。在擷取失敗的情況下，對轉譯後的頁面做 OCR 通常可行。
字詞被多餘的空格拆開
PDF 以小片段儲存文字，而工具會用空格把片段接起來。請用編輯器的「尋找及取代」整理常見的情況。
各欄文字混在一起
文字依照儲存的順序讀取，多欄頁面可能會在欄與欄之間跳來跳去。請從 PDF 檢視器複製需要的那一欄，或改用能辨識版面的「PDF 轉 Word」。
PDF 在工具中打不開
檔案可能有密碼保護或已損毀。請在產生它的應用程式中移除密碼，或先執行「修復 PDF」。
段落內的換行都不見了
這是工具的運作方式：每一頁會變成一串連續文字。請貼到文書軟體中，在需要的地方加上換行；如果結構很重要，請改用「PDF 轉 Word」。

常見問題

這個工具可以讀取掃描的 PDF 嗎？

不行。掃描檔裡是圖片，不是字元。請改用「OCR PDF」，它會辨識圖片並把文字存成 .txt 檔。

粗體、標題等格式會保留嗎？

不會。輸出的是純文字，沒有字型、樣式、表格或圖片。

為什麼每一頁開頭都是同一行字？

那一行是 PDF 的頁首。它是一般文字，所以每一頁都會被擷取出來。

支援哪些語言？

只要字元在 PDF 中儲存正確，任何語言都可以；文字會以 Unicode 保留。由右至左書寫的文字，可能會以儲存順序而非顯示順序輸出。

在 .txt 檔中，頁與頁之間怎麼分隔？

每一頁的文字後面都會接一個空行，所以各頁會顯示為獨立的區塊。

擷取是在伺服器上進行的嗎？

不是。PDF.js 在你的瀏覽器中讀取文字，.txt 檔也是在那裡產生的。如果文件是不想上傳的合約草稿或考卷，這一點就很重要。
