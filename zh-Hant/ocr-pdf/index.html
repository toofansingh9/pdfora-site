OCR PDF

用光學字元辨識，從掃描或拍照產生的 PDF 讀出文字，下載成純文字檔。

掃描的 PDF 看起來像文件，用起來卻像相簿：你沒辦法搜尋、沒辦法複製一段話，也沒辦法把數字貼進試算表，因為每一頁都只是一張「文字的照片」。光學字元辨識（OCR）會分析這些圖片，判斷上面是哪些字母。PDFora 的「OCR PDF」工具會對 PDF 的每一頁做這件事，再把辨識出的文字做成 .txt 檔給你，讓你搜尋、編輯、再利用。

先講清楚會得到什麼。目前這個工具輸出的是純文字，不是可搜尋的 PDF。每一頁會以大約每英寸 144 像素轉譯，交給 Tesseract.js（一套編譯成可在瀏覽器執行的開源 OCR 引擎），讀到的文字依頁序寫入檔案，頁與頁之間空一行。不會保留版面：欄位、表格和字型都不會重建。在頁面圖片後方放隱形文字的「可搜尋 PDF」輸出已在規劃中，但還沒有推出。輸出通常需要稍微整理：斷行處的連字號會保留，頁首和頁碼也會被當成一般文字行讀進來。

辨識是在你自己的裝置上執行的。第一次使用時，會從公開的 CDN 下載 Tesseract 引擎和語言資料，網路慢的話可能要等一陣子；你的 PDF 本身不在這次下載之中，也不會被傳到任何地方。

如何從掃描的 PDF 擷取文字

  1. 開啟「OCR PDF」工具，加入一個 PDF。掃描檔、存成 PDF 的手機照片和只有圖片的匯出檔都可以。
  2. 選擇文件的語言：英文、印地文、西班牙文或法文。預設是英文。
  3. 按下「執行 OCR」。狀態列會顯示正在讀第幾頁；每頁大約要幾秒鐘，在手機上會更久。
  4. 下載結果，檔名是原檔名加上 -ocr.txt，例如 lease-ocr.txt。
  5. 打開文字檔，在依賴內容之前，先對照掃描檔校對人名、數字和金額。

適用情境

  • 從掃描的英文合約複製條款貼進回覆信件，不用重新打字。
  • 把印出來的會議紀錄或協會的外勤報告，轉成可編輯的文字放進電子報或資料庫。
  • 從影印的書籍章節或期刊論文中摘錄引文做讀書筆記，頁與頁的分隔也會保留。
  • 從一疊掃描信件中擷取地址和編號，之後方便搜尋。
  • 把印地文或西班牙文文件讀成文字，再貼進翻譯工具。
  • 檢查 PDF 是否已經有文字層：如果「PDF 轉文字」什麼都抓不到、OCR 卻讀得出文字，那這個檔案就是純掃描檔。

開始前需要了解

  • 輸出是純 .txt 檔，依引擎判斷的閱讀順序存放文字，沒有格式、圖片或頁面版面。
  • 提供四種語言：英文、印地文、西班牙文和法文。中文等其他語言的文件會用錯誤的字元模型辨識，結果會很差。
  • 準確度主要取決於掃描品質。乾淨、端正、對比高的印刷頁面通常效果不錯；手寫、淡掉的影印、蓋在文字上的印章和歪斜的手機照片，錯誤會很多。
  • 表格和多欄版面會被當成一行一行的文字讀取。欄位可能互相交錯，表格儲存格也會失去格線結構。
  • 辨識前每一頁會以大約每英寸 144 像素轉譯。非常小的字，例如小於 8 pt 的註腳，可能低於引擎在這個解析度下能穩定辨識的程度。
  • 每一頁都會跑 OCR，即使那一頁本來就有真正的文字。如果是混合型文件，數位頁面用「PDF 轉文字」更快、也完全準確。

獲得最佳效果的訣竅

  • 如果掃描器由你操作，請用 300 dpi、黑白或灰階掃描；這對辨識的幫助比工具裡任何設定都大。
  • 先用「旋轉 PDF」把側躺的頁面轉正。引擎預期的是頁面端正、文字由左往右。
  • 長文件可以先分割，只對需要的頁面跑 OCR。辨識時間是一頁一頁累加的。
  • 數字要仔細校對。0 和 O、1 和 l、5 和 S 的混淆是最常見的 OCR 錯誤，在發票和證件號碼上代價也最高。
  • 把原始掃描檔和文字檔放在一起；文字是工作用的副本，掃描檔才是正本紀錄。

實例：研究生與影印的英文課程讀本

一位歷史所研究生手上有一份 22 頁的英文課程讀本，是系辦從影印本掃描來的。她的報告需要十幾段引文，也想在讀本裡搜尋某個條約的每一次出現，而不是再從頭翻一遍。

她選擇英文，用 OCR 處理這份 PDF，在筆電上花了幾分鐘。產生的文字檔馬上就能搜尋，頁與頁之間的空行也讓她能推算每段引文出自哪一頁，方便標註出處。有兩頁當初影印時是歪的，辨識出來的行是亂碼；她在圖書館把這兩頁轉正重新掃描，單獨跑 OCR，再把乾淨的文字貼回去。

每一段要用的引文，她都對照掃描檔檢查過，因為引文裡讀錯一個字比沒有引文更糟；她也修正了一個被引擎把 1648 讀成 1043 的年份。

她也用這個文字檔整理參考書目：每章標題頁上的出版資訊都辨識得很乾淨，因為標題頁通常用大而疏的字體印刷。錯誤多半集中在小小的註腳，所以註腳她直接看掃描檔，不採信辨識結果。

疑難排解

文字檔是空的或幾乎是空的
頁面可能對比太低、字太小，或本來就是空白。打開 PDF 放大看看：如果你自己都很難讀，引擎也一樣。可以的話，用更高的對比重新掃描。
輸出全是莫名其妙的字元
確認語言設定和文件相符。也檢查頁面是否端正；側躺或顛倒的頁面會產生亂碼，請先轉正。
工具一開始就卡住
第一次使用會下載 OCR 引擎和語言資料。網路很慢、有過濾，或裝了指令碼封鎖工具時，可能會卡住。請允許 cdn.jsdelivr.net 後再試一次。
各欄的文字混在一起
多欄頁面有時會被當成橫跨整頁的一行行文字讀取。請用「裁剪 PDF」把每一欄裁成獨立的頁面，或複製需要的段落後手動整理。
在手機上非常慢
OCR 很吃效能，每一頁都是用你裝置的處理器辨識。長文件請改用桌上型電腦，或分割後只對需要的頁面跑 OCR。
我要的是可搜尋的 PDF，不是文字檔
可搜尋 PDF 的輸出目前還沒有提供。現階段請用文字檔來搜尋和複製，掃描檔則保留作為視覺紀錄。

常見問題

這個工具能讓我的 PDF 變成可搜尋的嗎？

目前還不行。它把辨識出的文字輸出成 .txt 檔。可搜尋 PDF 的輸出已在規劃中。

支援哪些語言？

英文、印地文、西班牙文和法文。執行 OCR 前，請選擇和文件相符的語言。

可以辨識手寫字嗎？

效果很差。引擎是用印刷文字訓練的；工整的大寫印刷體有時可以，草寫通常不行。

我的文件會被上傳去辨識嗎？

不會。引擎會下載到你的瀏覽器並在那裡辨識；從 CDN 取得的只有引擎和語言檔案。

為什麼每一頁要好幾秒？

每一頁都要先轉譯成圖片，再用你自己的處理器分析字形，這比讀取現成的文字繁重得多。

會保留表格和格式嗎？

不會。輸出是依閱讀順序排列的純文字，表格結構、字型和圖片都不會重現。
