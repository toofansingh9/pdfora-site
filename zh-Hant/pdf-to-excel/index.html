PDF 轉 Excel

把 PDF 裡的表格擷取到 Excel（.xlsx）活頁簿，讓你可以排序、篩選和計算。

🔒 你的檔案在瀏覽器中本機處理，絕不會上傳。

會想把 PDF 轉成 Excel，通常都是為了表格：銀行對帳單、價目表、報告附錄、成績單。在 PDF 裡數字看起來排得很整齊，但底下其實沒有格子。每個數字都是獨立的一小段文字，被放在頁面上的某個位置，看起來像儲存格框線的線條也只是圖形。所以從 PDF 閱讀器複製貼到試算表，常常會全部擠進同一欄。

真正的轉檔器會分析文字的位置，判斷哪些項目上下對齊成欄、左右對齊成列，再寫進真正的試算表儲存格。PDFora 會把 PDF 送到伺服器端的轉換引擎（經由我們自己的中繼送到 CloudConvert）來做這件事，因為這種分析遠超出網頁能穩定處理的範圍。檔案經加密連線上傳、轉成 .xlsx 後再下載回來給你；工作完成後，上傳的副本會從該服務刪除。

沒有任何選項要設定：一個 PDF 進去，一個涵蓋整份文件的活頁簿出來。會計軟體或試算表匯出的 PDF 通常結果很乾淨；設計過的報告、旋轉的表格或掃描檔則需要多整理一些。尤其是數字要檢查，因為看起來正確的值，仍可能被存成文字。

如何把 PDF 轉成 Excel

  1. 開啟「PDF 轉 Excel」，選擇一個 PDF。如果只需要其中一個表格，先把那幾頁擷取出來，活頁簿裡就不會有其他東西。
  2. 按下「轉換」，狀態會依序顯示「上傳中…」和「轉換中…」。
  3. 等待下載。工具每隔幾秒向伺服器查詢一次，如果工作大約三分鐘後仍未完成就會停止。
  4. 儲存 .xlsx 檔（檔名和原檔相同、副檔名為 .xlsx，除非伺服器傳回不同的名稱）。
  5. 打開活頁簿，選取數字欄，確認 Excel 把它們當成數字，例如把某一欄加總，再和 PDF 上的總計比較。

適用情境

  • 小店老闆把廠商的 PDF 價目表轉成試算表，再自己加一欄利潤。
  • 把銀行或信用卡對帳單和帳本上的紀錄逐筆核對。
  • 協會彙整各地分會以 PDF 報告寄來的問卷統計結果。
  • 學生分析公開出版的政府統計 PDF 裡的表格。
  • 把收到的 PDF 課表或排班表重新整理，好依人員或日期篩選。
  • 原始試算表早已不在時，從舊報告中撈出庫存清單。

開始前需要了解

  • 檔案是在伺服器上處理，而不是在你的瀏覽器裡：加密上傳、轉換，之後從轉換服務刪除。
  • 掃描的表格是圖片。沒有文字層就沒有數字可以放進儲存格。「OCR PDF」可以把數字辨識成 .txt 檔，再由你自己貼進試算表；每個數字都要檢查，因為 OCR 可能把 1 和 7、0 和 8 之類的數字看錯。
  • 數字格式可能會變成文字。千分位符號、貨幣符號、用括號表示的負號，或結尾的 CR，都可能讓 Excel 認不出那是數值。
  • PDF 裡的合併標題、自動換行的儲存格文字，以及跨兩行的列，常常會被拆成好幾列。
  • 不是表格的內容（段落、註腳、頁首）也會落進儲存格，所以要有清掉一些東西的心理準備。
  • 有密碼保護的 PDF 無法轉換，請先在原本的應用程式裡移除保護。在轉換出的餘額欄旁邊放一個累計餘額公式，兩者第一次對不上的那一列會被標出來，通常就是轉檔器錯位的那一列。

獲得最佳效果的訣竅

  • 轉換前只擷取含有表格的頁面，活頁簿比較小，要整理的範圍也比較集中。
  • 如果數字靠儲存格左邊對齊，它們就是文字。用「資料 > 資料剖析」不做任何變更直接完成，或乘以 1，就能轉成數字。
  • 注意地區設定：用逗號當小數點的 PDF，可能會讓設定成小數點的試算表搞混，反之亦然。
  • 重複的標題列（每一頁 PDF 一列）用篩選標題文字的方式刪除，不要手動一列列刪。
  • 在相信轉換後的數字之前，至少拿一欄的加總和 PDF 比對一次。

實例：接案者核對季度對帳單

一位接案設計師收到金流服務商寄來的四頁 PDF 對帳單，列出這一季 63 筆入帳。她的記帳士要一份試算表，客戶名稱、日期、總金額和手續費各自分欄。

她把 PDF 轉換後打開活頁簿。資料列都在，但每一頁開頭都有重複的標題列，手續費欄的扣款顯示成 (2.40) 這種格式，被 Excel 當成文字。她篩選掉標題列，用「尋找及取代」把括號改成前置的負號，再把整欄轉成數字。日期則直接成了真正的日期，因為 PDF 用的是不會混淆的年-月-日格式。

最後她把總金額欄加總，和對帳單最後一頁印的總計比較，分毫不差，因此知道沒有任何一列被漏掉或拆開。每一份轉換出來的表格，都值得做這一次比對。銀行對帳單尤其要特別小心。很多銀行會把累計餘額單獨放一欄，沒有支出或沒有存入的交易就留空。轉換後這些空格有時會塌掉，讓那一列的存入金額跑到支出欄，而且只有那一列。排序或篩選都看不出來，只有加總，或拿累計餘額公式和印出來的餘額比較才抓得到。把這個檢查做進試算表一次，之後每個月都能重複使用。

疑難排解

全部都擠在 A 欄
轉檔器偵測不到欄位，通常是因為 PDF 用空格而不是位置來對齊文字。請用「資料 > 資料剖析」，以空格或固定寬度分欄。
數字加不起來
它們被存成文字了。移除貨幣符號和千分位符號後，再把儲存格轉成數字；也檢查有沒有用括號表示負號。
PDF 的一列變成試算表的兩列
PDF 裡某個儲存格換行到第二行了。用 =A2&" "&A3 之類的公式把兩部分接起來，或手動編輯，再刪掉多出來的那一列。
活頁簿裡都是圖片而不是數字
這個 PDF 是掃描檔，沒有真正的數字可以轉換。請用「OCR PDF」把數字擷取成 .txt 檔，貼進試算表，再校對數字。
工作逾時
大型報告可能超過工具大約三分鐘的等待時間。請把含有表格的頁面擷取出來，只轉換那幾頁。
伺服器轉換失敗
檢查 PDF 是否要求密碼或已經損毀。移除保護或用「修復 PDF」處理後再試一次。

常見問題

每一頁一個工作表，還是全部放在同一個工作表？

這取決於轉換引擎怎麼解讀你的文件；跨多頁的表格常常會依頁拆開。需要的話，可以用複製貼上或 Power Query 合併。

原本試算表裡的公式會回來嗎？

不會。PDF 只儲存顯示出來的值，所以活頁簿裡只有數字和文字，沒有產生它們的公式。

可以讀取掃描文件裡的表格嗎？

沒辦法直接轉換。「OCR PDF」可以把數字辨識成 .txt 檔，你再貼進試算表，並仔細檢查。

可以用 Google 試算表或 LibreOffice 開嗎？

可以。輸出是標準的 .xlsx 檔，兩者都能開啟。

為什麼有些日期錯了？

像 03/04 這樣的日期有歧義。Excel 會依照你的地區設定來解讀，所以請拿幾個日期和 PDF 對照一下。

檔案會被上傳嗎？

會，這個工具使用伺服器端的轉檔器。PDF 會加密傳送，轉換完成後從該服務刪除。
