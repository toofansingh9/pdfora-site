HTML en PDF

Convertissez un fichier HTML enregistré en PDF sur un serveur de conversion, pour transformer une page web ou un export HTML en pages fixes et imprimables.

Une page HTML se réorganise selon l'écran qui l'affiche : c'est sa grande qualité sur le web, et son principal défaut dès qu'il faut l'archiver, l'imprimer ou la joindre à une réclamation. Or beaucoup de documents n'existent que sous cette forme : la confirmation de réservation enregistrée depuis le navigateur, le rapport exporté par un logiciel métier, des notes de cours générées en une seule page, la newsletter de votre association ou un modèle que vous avez codé vous-même. Un PDF fige tout cela sur un format de page qui ne bougera plus.

HTML en PDF part d'un fichier .html ou .htm enregistré sur votre ordinateur, et non d'une adresse web. Le fichier transite, chiffré, par le relais de PDFora jusqu'au service CloudConvert, où un moteur de rendu met la page en forme puis l'imprime en PDF. Le résultat vous est renvoyé sous le nom de votre fichier et il est ensuite supprimé du service. La conversion n'a donc pas lieu dans votre navigateur, et la page de l'outil ne propose aucun réglage de format ni de marges.

Le point qui piège presque tout le monde concerne les fichiers que le HTML appelle. Une page web est rarement un fichier unique : ses images, ses feuilles de style et ses polices vivent généralement à côté, dans des fichiers distincts. Seul le fichier choisi part vers le serveur, si bien que tout ce qui est référencé par un chemin relatif sur votre disque reste hors de sa portée. Réussir sa conversion, c'est donc d'abord rendre le HTML autonome.

Convertir un fichier HTML en PDF

  1. Vérifiez que le fichier HTML est autonome ou qu'il appelle ses images et feuilles de style par des adresses complètes (https://...) ; voir les remarques plus bas.
  2. Ouvrez HTML en PDF et choisissez le fichier .html ou .htm.
  3. Cliquez sur Convertir et patientez pendant l'envoi et le rendu sur le serveur.
  4. Téléchargez le PDF, qui reprend le nom de votre fichier avec l'extension .pdf.
  5. Vérifiez que les images, les couleurs et la mise en page sont bien là, et que rien n'est coupé sur le bord droit.

Quand utiliser cet outil

  • Confirmations de commande, billets et réservations enregistrés depuis le navigateur, conservés en PDF pour la comptabilité ou en cas de litige avec un vendeur.
  • Notes de cours ou supports produits en une seule page HTML par un enseignant, à distribuer en version imprimable.
  • Rapports exportés en HTML par un logiciel de gestion ou de caisse, à archiver ou à transmettre au comptable.
  • Développeurs qui vérifient le rendu imprimé d'un modèle HTML de facture, d'attestation ou de courrier.
  • Documentation technique publiée sur une longue page, à lire hors connexion dans le train.
  • Newsletters d'association ou articles de blog sauvegardés dans un format qui ne changera pas si le site évolue.

À savoir avant de commencer

  • Les liens relatifs ne fonctionnent pas. Si le HTML contient <img src="images/logo.png"> ou <link href="style.css">, ces fichiers restent sur votre ordinateur et le serveur ne les voit pas. Le PDF affiche alors des images manquantes et un texte sans mise en forme. Utilisez des adresses absolues en https://, ou intégrez le CSS dans un bloc <style> et les images en data URI.
  • Les ressources appelées par une adresse web absolue peuvent être récupérées par le serveur au moment du rendu : les images et feuilles de style publiques apparaissent donc en général. Tout ce qui se trouve derrière une connexion, sur un intranet ou sur localhost, n'apparaîtra pas.
  • Il n'y a pas de champ pour une URL. Pour convertir une page en ligne, enregistrez-la d'abord ; le format Page web, fichier unique (.mhtml) de votre navigateur n'est pas accepté. Choisissez Page web, HTML uniquement, en sachant que les images relatives manqueront, ou passez par Imprimer > Enregistrer au format PDF du navigateur.
  • Les styles d'impression s'appliquent. Si la page contient du CSS @media print, le convertisseur l'utilise généralement, ce qui peut masquer des barres de navigation ou changer les couleurs par rapport à l'écran. Les sauts de page se pilotent en CSS avec break-before et break-inside.
  • Le contenu généré par JavaScript n'est pas fiable. Une page qui charge son contenu par script après l'ouverture peut ressortir comme une coquille vide. Enregistrez la page une fois entièrement chargée, ou générez le contenu directement dans le HTML côté serveur.
  • Les mises en page plus larges qu'une page imprimée, comme un design figé à 1400 pixels ou un grand tableau, peuvent être coupées ou réduites. Une mise en page responsive ou un max-width sur le contenu principal règle généralement le problème.

Conseils pour de meilleurs résultats

  • Pour vos propres modèles, placez tout le CSS dans un bloc <style> dans le <head> : c'est le moyen le plus sûr d'obtenir un PDF mis en forme.
  • Ajoutez @page { size: A4; margin: 15mm; } à votre CSS si vous avez besoin d'un format ou de marges précis.
  • Appliquez break-inside: avoid aux lignes de tableau, cartes et figures pour qu'elles ne soient pas coupées entre deux pages.
  • Gardez des images de taille raisonnable : une image d'en-tête de 5 MB intégrée en data URI donne toujours un PDF de 5 MB.
  • Ouvrez d'abord le fichier HTML dans l'aperçu avant impression de votre navigateur ; si le rendu y est mauvais, il le sera sans doute aussi dans le PDF converti.

Cas concret : des notes de cours générées en HTML

Mathieu enseigne l'informatique dans un cégep de Sherbrooke. Il rédige ses notes de cours en Markdown, qu'un petit outil transforme en un fichier notes.html accompagné d'un dossier img/ contenant six schémas d'environ 40 KB chacun et d'une feuille de style cours.css. Il veut en tirer un PDF à déposer sur la plateforme du cours. Premier essai : texte brut dans une police par défaut, six cadres d'image vides, et un long bloc de code coupé net sur le bord droit de la page.

Le diagnostic est simple : le serveur n'a reçu que notes.html, sans cours.css ni le dossier img/. Mathieu configure son outil pour intégrer la feuille de style dans un bloc <style> et les six schémas en data URI, ce qui reste raisonnable vu leur petite taille. Il ajoute aussi @page { size: A4; margin: 15mm; }, white-space: pre-wrap sur les blocs de code et break-inside: avoid sur les figures.

La nouvelle conversion donne un PDF de 9 pages avec la mise en forme du cours, les schémas à leur place et un code qui passe à la ligne au lieu de déborder. Comme le réglage se trouve désormais dans son outil de génération, les notes des chapitres suivants se convertissent du premier coup.

Résolution des problèmes

Le PDF n'a aucune mise en forme, juste du texte brut
La feuille de style était appelée par un chemin relatif et n'a pas été envoyée. Intégrez le CSS dans un bloc <style> ou liez-le par une adresse https:// complète.
Les images manquent
Les images de votre disque appelées par des chemins relatifs sont inaccessibles. Utilisez des URL https:// publiques ou intégrez les images en data URI, puis relancez la conversion.
La page est coupée à droite
La mise en page a une largeur fixe supérieure à celle de la page. Ajoutez max-width: 100% aux conteneurs principaux et aux images, ou une feuille de style d'impression qui resserre la mise en page.
Le PDF est vide ou presque
Le contenu est sans doute créé par JavaScript après le chargement, ou le fichier n'est qu'une redirection. Enregistrez la page une fois le rendu terminé, ou placez le contenu directement dans le HTML.
Le texte s'affiche dans une autre police
Les polices web appelées en local n'étaient pas disponibles. Liez la police depuis une URL publique, intégrez-la avec @font-face et une data URI, ou utilisez une pile de polices courantes.
L'outil refuse mon fichier
Seuls les fichiers .html et .htm sont acceptés. Les fichiers .mhtml ou .webarchive doivent être réenregistrés en HTML uniquement.

Questions fréquentes

Peut-on simplement coller l'adresse d'un site pour le convertir ?

Non, l'outil travaille sur un fichier HTML que vous choisissez. Enregistrez d'abord la page en HTML, ou utilisez Imprimer > Enregistrer au format PDF dans votre navigateur pour une page en ligne.

Mon fichier HTML part-il sur Internet ?

Oui. Il est transmis chiffré au service de conversion, rendu là-bas, puis supprimé. Évitez d'y faire passer des pages contenant des données personnelles que vous ne voulez pas confier à un tiers.

Pourquoi le PDF n'a-t-il ni images ni mise en forme ?

Parce que seul le fichier HTML est envoyé. Les images et feuilles de style appelées par des chemins relatifs restent sur votre ordinateur ; liez-les par des adresses https:// complètes ou intégrez-les dans le HTML.

Où règle-t-on le format A4 ou les marges ?

Pas sur la page de l'outil, mais dans le HTML lui-même, avec une règle CSS @page, par exemple @page { size: A4; margin: 15mm; }.

Les liens seront-ils encore cliquables dans le PDF ?

Ceux qui pointent vers des adresses web le restent normalement. Les liens relatifs vers d'autres fichiers de votre disque ne mèneront nulle part.

Le JavaScript de la page est-il exécuté ?

En partie, parfois, mais le contenu chargé tardivement ou qui attend une action de l'utilisateur manque souvent. Pour un résultat fiable, le HTML doit déjà contenir le contenu définitif.
