HTML en PDF

Convertissez un fichier HTML enregistré en PDF sur un serveur de conversion, pour transformer une page web ou un export HTML en pages fixes et imprimables.

🔒 Vos fichiers sont traités localement dans votre navigateur et ne sont jamais téléversés.

Bien des documents utiles n'existent qu'en HTML : une confirmation de commande enregistrée depuis le navigateur, un rapport exporté par une application, une newsletter, une documentation générée sur une seule page, ou une page que vous avez codée vous-même. Le HTML s'adapte à la fenêtre qui l'affiche, et c'est justement ce qu'on ne veut pas quand le document doit être archivé, imprimé ou joint à une réclamation. Un PDF le fige sur un format de page.

Cet outil prend un fichier .html ou .htm présent sur votre ordinateur, pas une adresse web. Le fichier est envoyé, chiffré, au service CloudConvert via le relais de PDFora ; un moteur de rendu y met la page en forme et l'imprime en PDF. Le résultat vous revient sous le nom de votre fichier, puis il est supprimé du service. La conversion ne se fait pas dans votre navigateur, et la page de l'outil ne propose aucun réglage de format ni de marges.

Ce qui surprend le plus, c'est le sort de tout ce que le fichier HTML appelle. Une page web tient rarement en un seul fichier : images, feuilles de style et polices sont généralement des fichiers séparés, référencés depuis le HTML. Seul le fichier choisi est envoyé, donc tout ce qui est appelé par un chemin relatif sur votre disque reste introuvable pour le serveur. Obtenir un PDF fidèle consiste donc surtout à rendre le fichier HTML autonome avant de le convertir.

Convertir un fichier HTML en PDF

  1. Vérifiez que le fichier HTML est autonome ou qu'il appelle ses images et feuilles de style par des adresses complètes (https://...) ; voir les remarques plus bas.
  2. Ouvrez HTML en PDF et choisissez le fichier .html ou .htm.
  3. Cliquez sur Convertir et patientez pendant l'envoi et le rendu sur le serveur.
  4. Téléchargez le PDF, qui reprend le nom de votre fichier avec l'extension .pdf.
  5. Vérifiez que les images, les couleurs et la mise en page sont bien là, et que rien n'est coupé sur le bord droit.

Quand utiliser cet outil

  • Reçus et confirmations de réservation enregistrés depuis le navigateur, conservés en PDF pour la comptabilité ou comme preuve.
  • Rapports exportés en HTML par un logiciel, à joindre à un e-mail ou à archiver.
  • Développeurs qui transforment un modèle HTML de facture, d'attestation ou de courrier en PDF pour contrôler le rendu à l'impression.
  • Documentation ou guide utilisateur publié sur une longue page HTML, imprimé pour être lu hors connexion.
  • Articles web sauvegardés pour une recherche, dans un format qui ne bougera pas si le site change.
  • Newsletters enregistrées en HTML et converties pour garder une trace de ce qui a été envoyé.

À savoir avant de commencer

  • Les liens relatifs ne fonctionnent pas. Si le HTML contient <img src="images/logo.png"> ou <link href="style.css">, ces fichiers restent sur votre ordinateur et le serveur ne les voit pas. Le PDF affiche alors des images manquantes et un texte sans mise en forme. Utilisez des adresses absolues en https://, ou intégrez le CSS dans un bloc <style> et les images en data URI.
  • Les ressources appelées par une adresse web absolue peuvent être récupérées par le serveur au moment du rendu : les images et feuilles de style publiques apparaissent donc en général. Tout ce qui se trouve derrière une connexion, sur un intranet ou sur localhost, n'apparaîtra pas.
  • Il n'y a pas de champ pour une URL. Pour convertir une page en ligne, enregistrez-la d'abord ; le format Page web, fichier unique (.mhtml) de votre navigateur n'est pas accepté. Choisissez Page web, HTML uniquement, en sachant que les images relatives manqueront, ou passez par Imprimer > Enregistrer au format PDF du navigateur.
  • Les styles d'impression s'appliquent. Si la page contient du CSS @media print, le convertisseur l'utilise généralement, ce qui peut masquer des barres de navigation ou changer les couleurs par rapport à l'écran. Les sauts de page se pilotent en CSS avec break-before et break-inside.
  • Le contenu généré par JavaScript n'est pas fiable. Une page qui charge son contenu par script après l'ouverture peut ressortir comme une coquille vide. Enregistrez la page une fois entièrement chargée, ou générez le contenu directement dans le HTML côté serveur.
  • Les mises en page plus larges qu'une page imprimée, comme un design figé à 1400 pixels ou un grand tableau, peuvent être coupées ou réduites. Une mise en page responsive ou un max-width sur le contenu principal règle généralement le problème.

Conseils pour de meilleurs résultats

  • Pour vos propres modèles, placez tout le CSS dans un bloc <style> dans le <head> : c'est le moyen le plus sûr d'obtenir un PDF mis en forme.
  • Ajoutez @page { size: A4; margin: 15mm; } à votre CSS si vous avez besoin d'un format ou de marges précis.
  • Appliquez break-inside: avoid aux lignes de tableau, cartes et figures pour qu'elles ne soient pas coupées entre deux pages.
  • Gardez des images de taille raisonnable : une image d'en-tête de 5 MB intégrée en data URI donne toujours un PDF de 5 MB.
  • Ouvrez d'abord le fichier HTML dans l'aperçu avant impression de votre navigateur ; si le rendu y est mauvais, il le sera sans doute aussi dans le PDF converti.

Cas concret : le modèle de facture HTML d'une petite boutique

Une boutique en ligne tenue par deux associés à Bordeaux génère ses factures en fichiers HTML grâce à un petit script. Chaque fichier appelle invoice.css et logo.png, placés dans le même dossier. Converti tel quel, le PDF n'affiche qu'un texte noir dans une police par défaut, sans logo, avec le tableau des totaux étiré sur toute la largeur : le serveur a reçu le HTML sans sa feuille de style ni son image.

La solution consiste à rendre le fichier autonome. Le script recopie désormais le contenu de invoice.css dans un bloc <style>, ajoute @page { size: A4; margin: 18mm; } et break-inside: avoid sur les lignes du tableau des articles, et fait pointer le logo vers son adresse https publique sur le site de la boutique au lieu d'un chemin local. Rien d'autre ne change.

Après une nouvelle conversion, la facture tient sur une page A4 avec le logo, les couleurs de la boutique et un tableau des totaux qui n'est plus coupé quand une commande compte beaucoup de lignes. Le modèle étant maintenant autonome, chaque facture produite par le script se convertit de la même façon.

Résolution des problèmes

Le PDF n'a aucune mise en forme, juste du texte brut
La feuille de style était appelée par un chemin relatif et n'a pas été envoyée. Intégrez le CSS dans un bloc <style> ou liez-le par une adresse https:// complète.
Les images manquent
Les images de votre disque appelées par des chemins relatifs sont inaccessibles. Utilisez des URL https:// publiques ou intégrez les images en data URI, puis relancez la conversion.
La page est coupée à droite
La mise en page a une largeur fixe supérieure à celle de la page. Ajoutez max-width: 100% aux conteneurs principaux et aux images, ou une feuille de style d'impression qui resserre la mise en page.
Le PDF est vide ou presque
Le contenu est sans doute créé par JavaScript après le chargement, ou le fichier n'est qu'une redirection. Enregistrez la page une fois le rendu terminé, ou placez le contenu directement dans le HTML.
Le texte s'affiche dans une autre police
Les polices web appelées en local n'étaient pas disponibles. Liez la police depuis une URL publique, intégrez-la avec @font-face et une data URI, ou utilisez une pile de polices courantes.
L'outil refuse mon fichier
Seuls les fichiers .html et .htm sont acceptés. Les fichiers .mhtml ou .webarchive doivent être réenregistrés en HTML uniquement.

Questions fréquentes

Puis-je convertir un site en saisissant son URL ?

Non. L'outil convertit un fichier HTML que vous choisissez. Enregistrez d'abord la page en HTML, ou utilisez Imprimer > Enregistrer au format PDF de votre navigateur pour une page en ligne.

Le fichier HTML est-il envoyé en ligne ?

Oui. Il est transmis chiffré au service de conversion, mis en page là-bas, puis supprimé. Évitez de convertir des pages contenant des données personnelles que vous ne voudriez pas voir traitées par un tiers.

Pourquoi mes images et mon CSS ont-ils disparu ?

Seul le fichier HTML lui-même est envoyé. Les fichiers qu'il appelle par des chemins relatifs restent sur votre ordinateur ; utilisez des liens https:// absolus ou intégrez-les dans le HTML.

Puis-je régler le format de page ou les marges ?

Pas depuis la page de l'outil. Réglez-les dans le HTML avec une règle CSS @page, par exemple @page { size: A4; margin: 15mm; }.

Les liens restent-ils cliquables dans le PDF ?

Les liens vers des adresses web restent normalement cliquables. Les liens relatifs vers d'autres fichiers locaux ne mèneront nulle part.

Le JavaScript s'exécute-t-il pendant la conversion ?

Il peut s'exécuter en partie, mais le contenu chargé tardivement ou dépendant d'une action de l'utilisateur manque souvent. Pour un résultat fiable, le HTML doit déjà contenir le contenu final.
