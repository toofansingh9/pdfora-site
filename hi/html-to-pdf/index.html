HTML से PDF

सेव की हुई HTML फ़ाइल को कन्वर्ज़न सर्वर पर PDF में बदलें — वेब पेज या HTML एक्सपोर्ट को तय, प्रिंट करने लायक पेजों में।

🔒 आपकी फ़ाइलें आपके ब्राउज़र में ही प्रोसेस होती हैं और कभी अपलोड नहीं होतीं।
1

अपलोड करें

अपनी फ़ाइल चुनें या खींचकर छोड़ें।

2

सेट करें

अपने विकल्प चुनें — सब कुछ आपके ब्राउज़र में होता है।

3

डाउनलोड करें

तैयार फ़ाइल तुरंत सेव करें। कोई वॉटरमार्क नहीं।

बहुत-से काम के दस्तावेज़ सिर्फ़ HTML में होते हैं: ब्राउज़र से सेव किया ऑर्डर कन्फ़र्मेशन, किसी ऐप से एक्सपोर्ट हुई रिपोर्ट, न्यूज़लेटर, एक ही पेज में बना डॉक्यूमेंटेशन, या आपका ख़ुद बनाया पेज। HTML जिस विंडो में खुलता है, उसी के हिसाब से फैल-सिकुड़ जाता है — और जब दस्तावेज़ फ़ाइल करना हो, प्रिंट करना हो या किसी क्लेम के साथ लगाना हो, तब यही चीज़ नहीं चाहिए। PDF उसे एक तय पेज साइज़ में जमा देती है।

यह टूल आपके कंप्यूटर से .html या .htm फ़ाइल लेता है, वेब एड्रेस नहीं। फ़ाइल एन्क्रिप्ट होकर PDFora के रिले से CloudConvert सेवा पर अपलोड होती है, जहाँ एक रेंडरिंग इंजन पेज का लेआउट बनाकर उसे PDF में प्रिंट करता है; नतीजा आपकी फ़ाइल के नाम से वापस आता है और बाद में सेवा से हटा दिया जाता है। कन्वर्ज़न आपके ब्राउज़र में नहीं होता, और टूल पेज पर पेज साइज़ या मार्जिन की कोई सेटिंग नहीं है।

ज़्यादातर लोगों को सबसे ज़्यादा हैरानी इस बात पर होती है कि HTML फ़ाइल जिन चीज़ों की ओर इशारा करती है, उनका क्या होता है। वेब पेज शायद ही कभी एक फ़ाइल होता है: इमेज, स्टाइलशीट और फ़ॉन्ट आम तौर पर अलग फ़ाइलें होती हैं जिनका HTML में सिर्फ़ रेफ़रेंस होता है। अपलोड सिर्फ़ वही एक फ़ाइल होती है जो आप चुनते हैं, इसलिए आपकी डिस्क पर relative path से जुड़ी कोई भी चीज़ सर्वर को नहीं मिलती। सही-सही PDF पाने का असली तरीका है कन्वर्ट करने से पहले HTML फ़ाइल को अपने-आप में पूरा (self-contained) बनाना।

HTML को PDF में कैसे बदलें

  1. पक्का करें कि HTML फ़ाइल अपने-आप में पूरी है, या उसकी इमेज और स्टाइलशीट पूरे वेब एड्रेस (https://...) से जुड़ी हैं; नीचे के नोट्स देखें।
  2. HTML से PDF टूल खोलें और .html या .htm फ़ाइल चुनें।
  3. कन्वर्ट करें पर क्लिक करें और फ़ाइल के अपलोड होकर सर्वर पर रेंडर होने तक इंतज़ार करें।
  4. PDF डाउनलोड करें; उसका नाम आपकी फ़ाइल वाला ही रहेगा, बस एक्सटेंशन .pdf होगा।
  5. देखें कि इमेज, रंग और लेआउट ठीक आए हैं, और दाईं ओर कुछ कटा तो नहीं।

यह टूल कब इस्तेमाल करें

  • ब्राउज़र से सेव की गई रसीदें और बुकिंग कन्फ़र्मेशन, जिन्हें हिसाब-किताब या कानूनी रिकॉर्ड के लिए PDF में रखना है।
  • किसी सॉफ़्टवेयर से HTML में एक्सपोर्ट हुई रिपोर्ट, जिसे ईमेल में अटैच करना या आर्काइव करना है।
  • डेवलपर जो HTML में बने इनवॉइस, सर्टिफ़िकेट या लेटर टेम्पलेट को PDF में बदलकर प्रिंट लेआउट जाँचना चाहते हैं।
  • एक लंबे HTML पेज पर छपा डॉक्यूमेंटेशन या यूज़र गाइड, जिसे ऑफ़लाइन पढ़ने के लिए प्रिंट करना है।
  • रिसर्च के लिए सेव किए वेब लेख, ऐसे फ़ॉर्मैट में जो साइट बदलने पर भी नहीं बदलेगा।
  • HTML में सेव किए ईमेल न्यूज़लेटर, जिन्हें भेजे गए कंटेंट के रिकॉर्ड के तौर पर कन्वर्ट करना है।

शुरू करने से पहले जान लें

  • Relative लिंक टूट जाते हैं। अगर HTML में <img src="images/logo.png"> या <link href="style.css"> लिखा है, तो वे फ़ाइलें आपके कंप्यूटर पर ही रहती हैं और सर्वर उन्हें नहीं देख सकता। तब PDF में इमेज गायब होंगी और टेक्स्ट बिना स्टाइल के। पूरे https:// एड्रेस इस्तेमाल करें, या CSS को <style> ब्लॉक में और इमेज को data URI के रूप में अंदर ही डाल दें।
  • पूरे वेब एड्रेस वाली चीज़ें सर्वर पेज रेंडर करते समय ला सकता है, इसलिए सार्वजनिक रूप से खुलने वाली इमेज और स्टाइलशीट आम तौर पर आ जाती हैं। लॉगिन के पीछे, इंट्रानेट पर या localhost पर रखी चीज़ें नहीं आएँगी।
  • URL डालने का बॉक्स नहीं है। लाइव पेज कन्वर्ट करना हो तो पहले उसे सेव करें; ब्राउज़र का Save Page As > Web Page, Single File (.mhtml) नहीं चलता, इसलिए Web Page, HTML Only चुनें और मानकर चलें कि relative इमेज गायब होंगी — या फिर ब्राउज़र का अपना Print > Save as PDF इस्तेमाल करें।
  • प्रिंट स्टाइल लागू होते हैं। अगर पेज में @media print वाली CSS है, तो कन्वर्टर आम तौर पर उसी को इस्तेमाल करता है; इससे स्क्रीन के मुकाबले नेविगेशन बार छिप सकते हैं या रंग बदल सकते हैं। पेज ब्रेक CSS में break-before और break-inside से कंट्रोल किए जा सकते हैं।
  • JavaScript से बनने वाले कंटेंट पर भरोसा नहीं किया जा सकता। जो पेज लोड होने के बाद स्क्रिप्ट से कंटेंट लाते हैं, वे खाली ढाँचे की तरह कन्वर्ट हो सकते हैं। पेज पूरी तरह लोड होने के बाद सेव करें, या कंटेंट सर्वर साइड पर ही HTML में डाल दें।
  • प्रिंट पेज से चौड़े लेआउट, जैसे 1400 पिक्सेल की फ़िक्स्ड डिज़ाइन या चौड़ी टेबल, कट सकते हैं या छोटे हो सकते हैं। आम तौर पर responsive लेआउट या मुख्य कंटेंट पर max-width लगाने से यह ठीक हो जाता है।

बेहतरीन नतीजों के लिए सुझाव

  • अपने टेम्पलेट में सारी CSS <head> के अंदर <style> ब्लॉक में रखें; स्टाइल वाली PDF पाने का यही सबसे भरोसेमंद तरीका है।
  • खास पेज साइज़ या मार्जिन चाहिए तो CSS में @page { size: A4; margin: 15mm; } जोड़ें।
  • टेबल की लाइनों, कार्ड और फ़िगर पर break-inside: avoid लगाएँ ताकि वे दो पेजों में न बँटें।
  • इमेज का साइज़ समझदारी से रखें: data URI में डाली गई 5 MB की बड़ी इमेज से PDF भी 5 MB की ही बनेगी।
  • पहले HTML फ़ाइल को ब्राउज़र के प्रिंट प्रीव्यू में खोलकर देखें; अगर वहाँ गड़बड़ दिखे, तो कन्वर्ट हुई PDF में भी शायद वैसा ही दिखेगा।

उदाहरण: एक छोटी ऑनलाइन दुकान का HTML इनवॉइस टेम्पलेट

इंदौर में दो लोगों की एक ऑनलाइन हैंडलूम दुकान एक छोटी स्क्रिप्ट से HTML फ़ाइलों में इनवॉइस बनाती है। हर फ़ाइल उसी फ़ोल्डर की invoice.css और logo.png से जुड़ी है। सीधे कन्वर्ट करने पर PDF में बस डिफ़ॉल्ट फ़ॉन्ट में सादा काला टेक्स्ट आता है, लोगो नहीं, और टोटल वाली टेबल पूरी चौड़ाई में फैल जाती है — क्योंकि सर्वर को HTML फ़ाइल तो मिली, लेकिन उसकी स्टाइलशीट और इमेज नहीं।

इलाज है फ़ाइल को अपने-आप में पूरा बनाना। अब स्क्रिप्ट invoice.css का कंटेंट एक <style> ब्लॉक में कॉपी करती है, @page { size: A4; margin: 18mm; } जोड़ती है, आइटम वाली टेबल की लाइनों पर break-inside: avoid लगाती है, और लोगो को लोकल path की जगह दुकान की वेबसाइट पर उसके सार्वजनिक https एड्रेस से जोड़ती है। बाकी कुछ नहीं बदलता।

दोबारा कन्वर्ट करने पर इनवॉइस एक पेज की A4 PDF बनता है — लोगो के साथ, दुकान के रंगों में, और टोटल वाली टेबल ज़्यादा आइटम होने पर भी नहीं टूटती। टेम्पलेट अब अपने-आप में पूरा है, इसलिए स्क्रिप्ट से बनने वाला हर इनवॉइस इसी तरह कन्वर्ट होता है।

समस्याएँ और समाधान

PDF में कोई स्टाइल नहीं, बस सादा टेक्स्ट है
स्टाइलशीट relative path से जुड़ी थी और अपलोड नहीं हुई। CSS को <style> ब्लॉक में डालें या पूरे https:// एड्रेस से लिंक करें।
इमेज गायब हैं
आपकी डिस्क पर relative path वाली इमेज तक सर्वर नहीं पहुँच सकता। सार्वजनिक https:// URL इस्तेमाल करें या इमेज को data URI के रूप में डालें, फिर दोबारा कन्वर्ट करें।
पेज दाईं ओर से कटा हुआ है
लेआउट की फ़िक्स्ड चौड़ाई पेज से ज़्यादा है। मुख्य कंटेनर और इमेज पर max-width: 100% लगाएँ, या ऐसी प्रिंट स्टाइलशीट जोड़ें जो लेआउट को संकरा कर दे।
PDF खाली या लगभग खाली है
शायद कंटेंट लोड होने के बाद JavaScript से बनता है, या फ़ाइल सिर्फ़ एक redirect है। पेज पूरी तरह रेंडर होने के बाद सेव करें, या कंटेंट HTML में ही डालें।
टेक्स्ट किसी दूसरे फ़ॉन्ट में दिख रहा है
लोकल रूप से जुड़े वेब फ़ॉन्ट उपलब्ध नहीं थे। फ़ॉन्ट को किसी सार्वजनिक URL से लिंक करें, @font-face और data URI से अंदर डालें, या आम फ़ॉन्ट इस्तेमाल करें।
टूल मेरी फ़ाइल नहीं ले रहा
सिर्फ़ .html और .htm चलती हैं। सेव की गई .mhtml या .webarchive फ़ाइलों को दोबारा HTML Only के रूप में सेव करना होगा।

अक्सर पूछे जाने वाले सवाल

क्या URL डालकर किसी वेबसाइट को कन्वर्ट कर सकते हैं?

नहीं। टूल आपकी चुनी हुई HTML फ़ाइल को कन्वर्ट करता है। पहले पेज को HTML के रूप में सेव करें, या लाइव पेज के लिए ब्राउज़र का Print > Save as PDF इस्तेमाल करें।

क्या HTML फ़ाइल अपलोड होती है?

हाँ। वह एन्क्रिप्ट होकर कन्वर्ज़न सेवा पर जाती है, वहीं रेंडर होती है और बाद में हटा दी जाती है। ऐसे पेज कन्वर्ट न करें जिनमें ऐसा निजी डेटा हो जिसे आप किसी तीसरी सेवा से प्रोसेस नहीं करवाना चाहते।

मेरी इमेज और CSS गायब क्यों हैं?

सिर्फ़ HTML फ़ाइल ही अपलोड होती है। जिन फ़ाइलों का वह relative path से रेफ़रेंस देती है, वे आपके कंप्यूटर पर ही रह जाती हैं; पूरे https:// लिंक इस्तेमाल करें या उन्हें HTML के अंदर डाल दें।

क्या पेज साइज़ या मार्जिन सेट कर सकते हैं?

टूल पेज पर नहीं। इन्हें HTML में CSS के @page नियम से सेट करें, जैसे @page { size: A4; margin: 15mm; }।

क्या PDF में लिंक क्लिक होते हैं?

वेब एड्रेस वाले लिंक आम तौर पर क्लिक करने लायक रहते हैं। दूसरी लोकल फ़ाइलों के relative लिंक कहीं काम की जगह नहीं ले जाएँगे।

क्या कन्वर्ज़न के दौरान JavaScript चलती है?

थोड़ी-बहुत चल सकती है, लेकिन देर से लोड होने वाला या यूज़र के क्लिक पर निर्भर कंटेंट अक्सर छूट जाता है। भरोसेमंद नतीजे के लिए HTML में पहले से ही फ़ाइनल कंटेंट होना चाहिए।
