HTML से PDF

सेव की हुई HTML फ़ाइल को कन्वर्ज़न सर्वर पर PDF में बदलें — वेब पेज या HTML एक्सपोर्ट को तय, प्रिंट करने लायक पेजों में।

🔒 आपकी फ़ाइलें आपके ब्राउज़र में ही प्रोसेस होती हैं और कभी अपलोड नहीं होतीं।
1

अपलोड करें

अपनी फ़ाइल चुनें या खींचकर छोड़ें।

2

सेट करें

अपने विकल्प चुनें — सब कुछ आपके ब्राउज़र में होता है।

3

डाउनलोड करें

तैयार फ़ाइल तुरंत सेव करें। कोई वॉटरमार्क नहीं।

कॉलेज पोर्टल से फ़ीस भरी, रसीद वाला पेज Ctrl+S से सेव कर लिया, और अब ऑफ़िस वाले कह रहे हैं कि "PDF भेजिए"। ऐसा अक्सर होता है। ऑर्डर कन्फ़र्मेशन, किसी सॉफ़्टवेयर की एक्सपोर्ट की हुई रिपोर्ट, न्यूज़लेटर, एक ही लंबे पेज वाला डॉक्यूमेंटेशन या आपका अपना बनाया पेज — ये सब HTML में ही मिलते हैं। दिक्कत यह है कि HTML जिस भी विंडो में खुले, उसी के हिसाब से फैलता-सिकुड़ता है। फ़ाइल में लगाना हो, प्रिंट निकालना हो या किसी क्लेम के साथ जमा करना हो, तो यह लचीलापन उल्टा पड़ता है; PDF उसी पेज को एक तय साइज़ पर रोक देती है।

HTML से PDF टूल आपके कंप्यूटर में रखी .html या .htm फ़ाइल लेता है — वेब एड्रेस डालने का विकल्प नहीं है। यहाँ कन्वर्ज़न आपके ब्राउज़र में नहीं होता: फ़ाइल एन्क्रिप्ट होकर PDFora के रिले के रास्ते CloudConvert सेवा तक जाती है, वहाँ एक रेंडरिंग इंजन पेज का लेआउट बनाकर उसे PDF में छापता है। तैयार PDF आपकी ही फ़ाइल के नाम से लौटती है और सेवा से बाद में हटा दी जाती है। ध्यान रहे, टूल पेज पर पेज साइज़ या मार्जिन चुनने की कोई सेटिंग नहीं है।

सबसे ज़्यादा लोग यहीं अटकते हैं: HTML फ़ाइल जिन दूसरी चीज़ों की तरफ़ इशारा करती है, उनका क्या होगा? कोई वेब पेज शायद ही एक अकेली फ़ाइल होता है। इमेज, स्टाइलशीट और फ़ॉन्ट आम तौर पर अलग फ़ाइलों में रहते हैं और HTML में उनका सिर्फ़ रेफ़रेंस होता है। अपलोड केवल वही एक फ़ाइल होती है जिसे आपने चुना, तो आपकी डिस्क पर relative path से जुड़ी कोई भी चीज़ सर्वर तक पहुँचती ही नहीं। इसलिए ठीक-ठाक PDF का राज़ कन्वर्ज़न में कम, तैयारी में ज़्यादा है — HTML को पहले अपने-आप में पूरा (self-contained) बना लें।

HTML को PDF में कैसे बदलें

  1. पक्का करें कि HTML फ़ाइल अपने-आप में पूरी है, या उसकी इमेज और स्टाइलशीट पूरे वेब एड्रेस (https://...) से जुड़ी हैं; नीचे के नोट्स देखें।
  2. HTML से PDF टूल खोलें और .html या .htm फ़ाइल चुनें।
  3. कन्वर्ट करें पर क्लिक करें और फ़ाइल के अपलोड होकर सर्वर पर रेंडर होने तक इंतज़ार करें।
  4. PDF डाउनलोड करें; उसका नाम आपकी फ़ाइल वाला ही रहेगा, बस एक्सटेंशन .pdf होगा।
  5. देखें कि इमेज, रंग और लेआउट ठीक आए हैं, और दाईं ओर कुछ कटा तो नहीं।

यह टूल कब इस्तेमाल करें

  • कॉलेज या स्कूल पोर्टल से सेव किया गया फ़ीस रसीद वाला पेज, जिसे स्कॉलरशिप फ़ॉर्म या रीइंबर्समेंट के साथ PDF में लगाना है।
  • ऑनलाइन बुकिंग या ऑर्डर का कन्फ़र्मेशन पेज, जिसे हिसाब-किताब या किसी विवाद में सबूत के तौर पर PDF में संभालकर रखना है।
  • छोटे कारोबार या फ़्रीलांसर, जिनका बिलिंग सॉफ़्टवेयर इनवॉइस, सर्टिफ़िकेट या लेटर HTML टेम्पलेट से बनाता है और प्रिंट लेआउट जाँचना है।
  • किसी टूल से HTML में निकली रिपोर्ट, जिसे क्लाइंट या बॉस को ईमेल में अटैच करना या आर्काइव करना है।
  • एक लंबे HTML पेज पर बनी यूज़र गाइड या डॉक्यूमेंटेशन, जिसे ट्रेन के सफ़र में ऑफ़लाइन पढ़ने के लिए PDF बनाना है।
  • रिसर्च के लिए सेव किए लेख या HTML में सेव ईमेल न्यूज़लेटर, जिनका ऐसा रिकॉर्ड चाहिए जो वेबसाइट बदलने पर भी न बदले।

शुरू करने से पहले जान लें

  • Relative लिंक टूट जाते हैं। अगर HTML में <img src="images/logo.png"> या <link href="style.css"> लिखा है, तो वे फ़ाइलें आपके कंप्यूटर पर ही रहती हैं और सर्वर उन्हें नहीं देख सकता। तब PDF में इमेज गायब होंगी और टेक्स्ट बिना स्टाइल के। पूरे https:// एड्रेस इस्तेमाल करें, या CSS को <style> ब्लॉक में और इमेज को data URI के रूप में अंदर ही डाल दें।
  • पूरे वेब एड्रेस वाली चीज़ें सर्वर पेज रेंडर करते समय ला सकता है, इसलिए सार्वजनिक रूप से खुलने वाली इमेज और स्टाइलशीट आम तौर पर आ जाती हैं। लॉगिन के पीछे, इंट्रानेट पर या localhost पर रखी चीज़ें नहीं आएँगी।
  • URL डालने का बॉक्स नहीं है। लाइव पेज कन्वर्ट करना हो तो पहले उसे सेव करें; ब्राउज़र का Save Page As > Web Page, Single File (.mhtml) नहीं चलता, इसलिए Web Page, HTML Only चुनें और मानकर चलें कि relative इमेज गायब होंगी — या फिर ब्राउज़र का अपना Print > Save as PDF इस्तेमाल करें।
  • प्रिंट स्टाइल लागू होते हैं। अगर पेज में @media print वाली CSS है, तो कन्वर्टर आम तौर पर उसी को इस्तेमाल करता है; इससे स्क्रीन के मुकाबले नेविगेशन बार छिप सकते हैं या रंग बदल सकते हैं। पेज ब्रेक CSS में break-before और break-inside से कंट्रोल किए जा सकते हैं।
  • JavaScript से बनने वाले कंटेंट पर भरोसा नहीं किया जा सकता। जो पेज लोड होने के बाद स्क्रिप्ट से कंटेंट लाते हैं, वे खाली ढाँचे की तरह कन्वर्ट हो सकते हैं। पेज पूरी तरह लोड होने के बाद सेव करें, या कंटेंट सर्वर साइड पर ही HTML में डाल दें।
  • प्रिंट पेज से चौड़े लेआउट, जैसे 1400 पिक्सेल की फ़िक्स्ड डिज़ाइन या चौड़ी टेबल, कट सकते हैं या छोटे हो सकते हैं। आम तौर पर responsive लेआउट या मुख्य कंटेंट पर max-width लगाने से यह ठीक हो जाता है।

बेहतरीन नतीजों के लिए सुझाव

  • अपने टेम्पलेट में सारी CSS <head> के अंदर <style> ब्लॉक में रखें; स्टाइल वाली PDF पाने का यही सबसे भरोसेमंद तरीका है।
  • खास पेज साइज़ या मार्जिन चाहिए तो CSS में @page { size: A4; margin: 15mm; } जोड़ें।
  • टेबल की लाइनों, कार्ड और फ़िगर पर break-inside: avoid लगाएँ ताकि वे दो पेजों में न बँटें।
  • इमेज का साइज़ समझदारी से रखें: data URI में डाली गई 5 MB की बड़ी इमेज से PDF भी 5 MB की ही बनेगी।
  • पहले HTML फ़ाइल को ब्राउज़र के प्रिंट प्रीव्यू में खोलकर देखें; अगर वहाँ गड़बड़ दिखे, तो कन्वर्ट हुई PDF में भी शायद वैसा ही दिखेगा।

उदाहरण: जयपुर की एक CA फ़र्म की HTML सैलरी स्लिप

जयपुर की एक छोटी CA फ़र्म में इंटर्न रोहित हर महीने एक Python स्क्रिप्ट से 22 कर्मचारियों की सैलरी स्लिप HTML में बनाता है। हर स्लिप उसी फ़ोल्डर की slip.css, फ़र्म की मुहर वाली stamp.png और लोकल रखे एक हिंदी वेब फ़ॉन्ट से जुड़ी है, और लेआउट 1100 पिक्सेल की फ़िक्स्ड चौड़ाई पर बना है। पहली बार सीधे कन्वर्ट किया तो PDF में मुहर नहीं थी, हिंदी नाम किसी दूसरे फ़ॉन्ट में दिख रहे थे और कटौतियों वाली टेबल दाईं ओर से कट गई थी। वजह साफ़ थी: सर्वर को HTML तो मिला, पर CSS, इमेज और फ़ॉन्ट नहीं।

रोहित ने स्क्रिप्ट में चार बदलाव किए। slip.css का पूरा कंटेंट अब <head> के <style> ब्लॉक में जाता है, उसमें @page { size: A4; margin: 12mm; } जोड़ा गया और मुख्य कंटेनर पर max-width: 100% लगाया गया। करीब 40 KB की मुहर को data URI बनाकर HTML के अंदर ही डाल दिया। और हिंदी फ़ॉन्ट को लोकल फ़ाइल की जगह एक सार्वजनिक https:// लिंक से जोड़ा।

अगली बार हर स्लिप एक पेज की A4 PDF बनकर आई — मुहर अपनी जगह पर, हिंदी नाम सही फ़ॉन्ट में और टेबल पूरी। चूँकि मुहर छोटी थी, हर PDF का साइज़ भी हल्का रहा। अब टेम्पलेट ख़ुद में पूरा है, इसलिए अगले महीने की 22 स्लिप भी बिना किसी जुगाड़ के इसी तरह कन्वर्ट होंगी।

समस्याएँ और समाधान

PDF में कोई स्टाइल नहीं, बस सादा टेक्स्ट है
स्टाइलशीट relative path से जुड़ी थी और अपलोड नहीं हुई। CSS को <style> ब्लॉक में डालें या पूरे https:// एड्रेस से लिंक करें।
इमेज गायब हैं
आपकी डिस्क पर relative path वाली इमेज तक सर्वर नहीं पहुँच सकता। सार्वजनिक https:// URL इस्तेमाल करें या इमेज को data URI के रूप में डालें, फिर दोबारा कन्वर्ट करें।
पेज दाईं ओर से कटा हुआ है
लेआउट की फ़िक्स्ड चौड़ाई पेज से ज़्यादा है। मुख्य कंटेनर और इमेज पर max-width: 100% लगाएँ, या ऐसी प्रिंट स्टाइलशीट जोड़ें जो लेआउट को संकरा कर दे।
PDF खाली या लगभग खाली है
शायद कंटेंट लोड होने के बाद JavaScript से बनता है, या फ़ाइल सिर्फ़ एक redirect है। पेज पूरी तरह रेंडर होने के बाद सेव करें, या कंटेंट HTML में ही डालें।
टेक्स्ट किसी दूसरे फ़ॉन्ट में दिख रहा है
लोकल रूप से जुड़े वेब फ़ॉन्ट उपलब्ध नहीं थे। फ़ॉन्ट को किसी सार्वजनिक URL से लिंक करें, @font-face और data URI से अंदर डालें, या आम फ़ॉन्ट इस्तेमाल करें।
टूल मेरी फ़ाइल नहीं ले रहा
सिर्फ़ .html और .htm चलती हैं। सेव की गई .mhtml या .webarchive फ़ाइलों को दोबारा HTML Only के रूप में सेव करना होगा।

अक्सर पूछे जाने वाले सवाल

क्या वेबसाइट का लिंक डालकर सीधे PDF बन सकती है?

नहीं, यह टूल सिर्फ़ आपकी चुनी हुई HTML फ़ाइल को कन्वर्ट करता है। पहले पेज को HTML के रूप में सेव कर लें; अगर लाइव पेज ही चाहिए, तो ब्राउज़र का Print > Save as PDF ज़्यादा आसान रहेगा।

मेरी HTML फ़ाइल कहीं बाहर जाती है क्या?

हाँ, जाती है। फ़ाइल एन्क्रिप्ट होकर कन्वर्ज़न सेवा पर पहुँचती है, वहीं रेंडर होती है और फिर हटा दी जाती है। अगर पेज में ऐसी निजी जानकारी है जिसे आप किसी तीसरी सेवा पर प्रोसेस नहीं करवाना चाहते, तो उसे इस टूल से कन्वर्ट न करें।

PDF में फ़ोटो और डिज़ाइन क्यों नहीं आ रहे?

क्योंकि अपलोड सिर्फ़ HTML फ़ाइल होती है। जिन इमेज और CSS फ़ाइलों का रेफ़रेंस relative path से है, वे आपके कंप्यूटर पर ही रह जाती हैं। उन्हें पूरे https:// लिंक से जोड़ें या सीधे HTML के अंदर डाल दें।

A4 साइज़ या मार्जिन कहाँ से सेट करूँ?

टूल पेज पर ऐसी कोई सेटिंग नहीं है। यह काम HTML के अंदर CSS के @page नियम से होता है, जैसे @page { size: A4; margin: 15mm; }।

PDF में लिंक पर क्लिक करने से खुलेंगे?

जो लिंक किसी वेब एड्रेस पर जाते हैं, वे आम तौर पर क्लिक करने लायक बने रहते हैं। आपकी दूसरी लोकल फ़ाइलों वाले relative लिंक किसी काम की जगह नहीं ले जाएँगे।

जिस पेज का कंटेंट JavaScript से आता है, वह कन्वर्ट होगा?

स्क्रिप्ट थोड़ी-बहुत चल सकती है, लेकिन देर से लोड होने वाला या किसी क्लिक पर खुलने वाला कंटेंट अक्सर छूट जाता है। भरोसेमंद नतीजे के लिए HTML में पहले से ही फ़ाइनल कंटेंट मौजूद होना चाहिए।
