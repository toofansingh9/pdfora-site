Compress PDF makes a file smaller by rebuilding every page as a JPEG picture at a lower resolution. That single sentence explains both why it works so well on scans and why it is the wrong tool for some documents, so it is worth understanding before you click the button. On a scanned contract or a photo-heavy brochure, the tool routinely cuts the size by 60 to 90 percent. On a PDF that is already mostly text, it can make the file bigger and will turn the selectable text into a picture of text.

Here is what happens under the hood. Each page is rendered in your browser to a bitmap (PDF.js does the rendering), the bitmap is saved as a JPEG at the quality you chose, and a new PDF is assembled with one JPEG per page at the original page dimensions. Low keeps the most detail (about 162 dpi, JPEG quality 82), Recommended balances size and legibility (about 124 dpi, quality 65), and Strong goes for the smallest file (about 97 dpi, quality 50). Everything happens on your device; nothing is uploaded.

Because the output is a stack of images, the compressed PDF has no live text, no clickable links, no bookmarks and no form fields. For a scan that is no loss at all: a scan is already a picture. For a digital document it is a real trade-off, and the sections below tell you when to accept it and when to choose a different route.

How to compress a PDF online

  1. Open Compress PDF and drop the file in. The current size is shown next to the file name.
  2. Choose a level. Start with Recommended; use Low if the document has small print or fine line drawings, Strong if you only need the file to be readable on screen.
  3. Click Compress PDF. The progress bar advances page by page; a 50-page scan takes roughly 10 to 20 seconds on a laptop.
  4. Read the result line: it shows the original size, the new size and the percentage saved. If the new size is larger, stop and read the troubleshooting section below.
  5. Download the file, open it and zoom in on the smallest text before you rely on it.

When to use this tool

  • Scanned documents (contracts, ID pages, certificates) that must fit a portal's upload limit.
  • Photo-heavy brochures, property listings and portfolios sent by email.
  • Lecture slides exported from PowerPoint with full-size images on every page.
  • Camera-scanned receipts and forms from a phone, which are often 3 to 8 MB per page.
  • Archiving old paper files where legibility matters but editability does not.
  • Shrinking a file to post in a chat app that compresses or rejects large attachments.

What to know before you start

  • The result is image-only. Text cannot be selected, searched or copied, links do not work, and bookmarks and form fields are removed. If any of that matters, do not compress a digital document this way.
  • Text-only PDFs usually get bigger, not smaller. A 300 KB digital invoice is tiny because its text is stored as characters; as a JPEG per page it becomes 150 to 400 KB per page. Those files are already small enough to send.
  • Resolution, not just quality, is what shrinks a scan. A phone scan at 300 dpi re-rendered at 124 dpi has about one sixth of the pixels, which is where most of the saving comes from.
  • Colour is preserved. Compress does not convert to black and white; run Grayscale PDF first if you want a further reduction on colour scans.
  • Page size and page count are unchanged. A4 stays A4, and a 40-page file stays 40 pages, so the document paginates and prints exactly as before.
  • Very large files are limited by your device's memory because each page is rendered in the browser. Hundreds of pages are fine on a desktop; on a phone, split a very long scan first.

Tips for the best results

  • Compress scans, not digital documents. If you are unsure, try selecting text in your viewer: if the cursor selects words, the file is digital and probably does not need this tool.
  • Try Recommended first and only go to Strong if you must; the step from Recommended to Strong saves comparatively little and costs the most legibility.
  • For a document with both a scanned part and a digital part, split it, compress only the scanned pages, then merge the two parts back.
  • Zoom to 200 percent on the page with the smallest text (footnotes, serial numbers, stamps) before accepting the result.
  • Keep the original. Compression is one-way; you cannot recover detail from a compressed copy.

A worked example: a 38 MB scan and a 25 MB email limit

A 12-page rental agreement scanned on a phone comes out at 38 MB: each page is a 300 dpi colour photograph of about 3 MB. Gmail refuses attachments over 25 MB, so the file has to lose at least a third of its size, and ideally far more so it also opens quickly on the landlord's phone.

Compress PDF on the Recommended level renders each page at about 124 dpi and JPEG quality 65. A 3 MB page typically comes out between 250 and 500 KB, so the whole agreement lands around 3 to 6 MB, an 85 to 90 percent reduction. Signatures, stamps and the 9-point clause numbering remain readable at normal zoom. On Strong the same file would be nearer 2 to 3 MB, but the fine print starts to look soft, which is not what you want on a legal document.

If the agreement had instead been a 400 KB PDF exported from Word, the right answer would have been to send it as it is: it already fits, and compressing it would have replaced crisp, searchable text with pictures of text.

Troubleshooting

The compressed file is larger than the original
The source was a digital, text-based PDF. Its text was stored efficiently as characters and has now become JPEG images. Discard the result and send the original; it was already small.
The text became blurry or hard to read
The chosen resolution is too low for the print size. Re-run from the original on Low (about 162 dpi). For documents with 6-point text or fine engineering lines, Low is the only sensible level.
I can no longer select or search the text
That is how this tool works: pages become images. If you need searchable text, keep the original digital PDF. PDFora's OCR PDF can pull the words out of the compressed scan as a separate .txt file, but it does not make the PDF itself searchable.
The file hardly shrank at all
Either the PDF was already compressed (a previous run, or a scanner that already saves at 100 dpi JPEG), or it is mostly text. Check the result line: a saving under 10 percent means there was little to gain.
Links, bookmarks or form fields are gone
Expected; the output contains only page images. If you need them, compress only the scanned pages (split, compress, merge) and keep the interactive pages untouched.
The browser tab froze or crashed
Each page is rendered in memory; a very long scan on a phone or a low-memory laptop can run out. Split the document into parts of 50 to 100 pages, compress each, then merge.

Frequently asked questions

How much smaller will my PDF get?

Scans and photo-heavy files typically shrink by 60 to 90 percent on the Recommended level. Text-based digital PDFs do not shrink and may grow, because their text is already stored compactly.

Does compression reduce quality?

Yes, deliberately: pages are re-rendered at a lower resolution and saved as JPEG. Low is close to the original for normal print sizes; Strong is for screen reading only.

Will the text still be searchable after compression?

No. The output is image-only. If you need the words, run OCR PDF on it to get them as a .txt file; the PDF itself stays unsearchable.

Is there a file size or page limit?

No fixed limit. Processing happens in your browser, so the practical limit is your device's memory; split very long scans into parts if a tab freezes.

Can I compress a PDF without turning it into images?

Not with this tool. For a digital PDF the honest answer is usually that it does not need compressing; if it contains a few huge embedded photos, reduce those in the source document and export again.

Is my document uploaded anywhere?

No. Rendering and re-encoding happen entirely in your browser with PDF.js and pdf-lib. The file never leaves your device.
