HTML do PDF

Převeďte uložený HTML soubor na PDF na převodním serveru a udělejte z webové stránky nebo HTML exportu pevné stránky připravené k tisku.

Spousta užitečných dokumentů existuje jen jako HTML: potvrzení objednávky uložené z prohlížeče, report vyexportovaný z aplikace, newsletter, dokumentace vygenerovaná jako jedna stránka nebo stránka, kterou jste si sami postavili. HTML se přizpůsobuje oknu, ve kterém je zobrazené, a přesně to nechcete, když má dokument skončit v archivu, na tiskárně nebo jako příloha reklamace. PDF ho zafixuje na jeden formát stránky.

Nástroj pracuje se souborem .html nebo .htm z vašeho počítače, ne s webovou adresou. Soubor se šifrovaně nahraje přes prostředníka PDFora do služby CloudConvert, kde vykreslovací jádro stránku rozvrhne a „vytiskne“ do PDF; výsledek se vrátí pojmenovaný podle vašeho souboru a ze služby se pak smaže. Převod tedy neprobíhá ve vašem prohlížeči a na stránce nástroje nejsou žádná nastavení formátu stránky ani okrajů.

Většinu lidí nejvíc překvapí, co se stane se vším, na co HTML soubor odkazuje. Webová stránka je málokdy jeden soubor: obrázky, styly a písma bývají samostatné soubory, na které HTML odkazuje. Nahraje se jen ten jeden soubor, který vyberete, takže cokoli, na co se odkazuje relativní cestou na vašem disku, server nenajde. Věrné PDF tak získáte hlavně tím, že HTML soubor před převodem uděláte soběstačným.

Jak převést HTML do PDF

  1. Ověřte, že je HTML soubor soběstačný nebo používá pro obrázky a styly úplné webové adresy (https://...); podrobnosti najdete níže.
  2. Otevřete nástroj HTML do PDF a vyberte soubor .html nebo .htm.
  3. Klikněte na Převést a počkejte, než se soubor nahraje a na serveru vykreslí.
  4. Stáhněte PDF, které si ponechá název vašeho souboru s příponou .pdf.
  5. Zkontrolujte, že se přenesly obrázky, barvy a rozvržení a že u pravého okraje nic nechybí.

Kdy tento nástroj použít

  • Účtenky a potvrzení rezervací uložená z prohlížeče, archivovaná jako PDF pro účetnictví nebo jako doklad.
  • Reporty, které software exportuje jako HTML a které je potřeba přiložit k e-mailu nebo archivovat.
  • Vývojáři, kteří z vygenerované HTML šablony faktury, certifikátu nebo dopisu dělají PDF, aby zkontrolovali tiskové rozvržení.
  • Dokumentace nebo uživatelská příručka publikovaná jako jedna dlouhá HTML stránka, vytištěná ke čtení offline.
  • Uložené webové články pro studium nebo výzkum ve formátu, který se nezmění, ani když se změní web.
  • E-mailové newslettery uložené jako HTML a převedené pro záznam o tom, co se rozeslalo.

Co vědět, než začnete

  • Relativní odkazy se rozbijí. Pokud HTML obsahuje <img src="images/logo.png"> nebo <link href="style.css">, tyto soubory zůstanou na vašem počítači a server je nevidí. V PDF pak chybí obrázky a text je bez stylů. Použijte absolutní adresy https://, nebo vložte CSS do bloku <style> a obrázky jako data URI.
  • Zdroje s absolutní webovou adresou si server při vykreslování může stáhnout, takže veřejně dostupné obrázky a styly se obvykle zobrazí. Nic, co je za přihlášením, na intranetu nebo na localhostu, se ale nezobrazí.
  • Pole pro URL tu není. Chcete-li převést živou stránku, nejdřív ji uložte; volba prohlížeče Uložit stránku jako > Webová stránka, jeden soubor (.mhtml) se nepřijímá, takže použijte Webová stránka, pouze HTML a počítejte s tím, že relativní obrázky budou chybět. Případně použijte vlastní Tisk > Uložit jako PDF v prohlížeči.
  • Uplatní se tiskové styly. Pokud má stránka CSS pro @media print, převodník ho obvykle použije, a to může oproti obrazovce skrýt navigaci nebo změnit barvy. Zalomení stránek lze řídit vlastnostmi break-before a break-inside v CSS.
  • Obsah skládaný JavaScriptem je nespolehlivý. Stránky, které si obsah dotahují skripty až po načtení, se mohou převést jako prázdná kostra. Uložte stránku, až se úplně načte, nebo obsah vykreslete přímo do HTML na straně serveru.
  • Rozvržení širší než tištěná stránka, například pevný design 1400 pixelů nebo široké tabulky, se může oříznout nebo zmenšit. Obvykle pomůže responzivní rozvržení nebo max-width u hlavního obsahu.

Tipy pro nejlepší výsledky

  • U vlastních šablon dejte všechno CSS do bloku <style> v <head>; je to nejspolehlivější cesta ke stylovanému PDF.
  • Pokud potřebujete konkrétní formát stránky nebo okraje, přidejte do CSS @page { size: A4; margin: 15mm; }.
  • U řádků tabulek, karet a obrázků použijte break-inside: avoid, aby se nerozdělily na dvě stránky.
  • Držte velikost obrázků v rozumných mezích: úvodní obrázek o 5 MB vložený jako data URI udělá stejně PDF o 5 MB.
  • Nejdřív si HTML soubor otevřete v náhledu tisku prohlížeče; pokud vypadá špatně tam, nejspíš bude vypadat špatně i převedené PDF.

Praktický příklad: HTML šablona faktury malého e-shopu

Dvoučlenný e-shop generuje faktury jako HTML soubory jednoduchým skriptem. Každý soubor odkazuje na invoice.css a logo.png ve stejné složce. Při přímém převodu vyjde PDF jako obyčejný černý text ve výchozím písmu, bez loga a s tabulkou součtů roztaženou přes celou šířku, protože server dostal HTML soubor bez stylů a bez obrázku.

Řešením je udělat soubor soběstačným. Skript teď kopíruje obsah invoice.css do bloku <style>, přidává @page { size: A4; margin: 18mm; } a break-inside: avoid u řádků tabulky s položkami a logo načítá z jeho veřejné adresy https na webu obchodu místo z lokální cesty. Nic jiného se nemění.

Po novém převodu je faktura jednostránkové PDF ve formátu A4 s logem, barvami obchodu a tabulkou součtů, která se už nerozděluje, ani když má objednávka hodně položek. Protože je šablona teď soběstačná, převede se stejně každá faktura, kterou skript vytvoří.

Řešení problémů

PDF nemá žádné styly, jen holý text
Styly byly odkázané relativní cestou a nenahrály se. Vložte CSS do bloku <style> nebo ho odkažte úplnou adresou https://.
Chybí obrázky
Obrázky na vašem disku odkázané relativní cestou nejsou dostupné. Použijte veřejné adresy https:// nebo obrázky vložte jako data URI a převeďte znovu.
Stránka je vpravo useknutá
Rozvržení má pevnou šířku větší než stránka. Přidejte hlavním kontejnerům a obrázkům max-width: 100 %, nebo tiskový styl, který rozvržení zúží.
PDF je prázdné nebo skoro prázdné
Obsah nejspíš vytváří JavaScript až po načtení, nebo je soubor jen přesměrování. Uložte stránku, až je úplně vykreslená, nebo obsah vložte přímo do HTML.
Text je v jiném písmu
Webová písma odkázaná lokálně nebyla k dispozici. Odkažte písmo z veřejné adresy, vložte ho přes @font-face jako data URI, nebo použijte běžnou sadu písem.
Nástroj můj soubor odmítá
Přijímají se jen soubory .html a .htm. Uložené soubory .mhtml nebo .webarchive je potřeba znovu uložit jako pouze HTML.

Často kladené otázky

Můžu převést web zadáním jeho URL?

Ne. Nástroj převádí HTML soubor, který vyberete. Stránku nejdřív uložte jako HTML, nebo u živé stránky použijte Tisk > Uložit jako PDF v prohlížeči.

Nahrává se HTML soubor na server?

Ano. Šifrovaně se odešle do převodní služby, tam se vykreslí a poté smaže. Nepřevádějte stránky s osobními údaji, které byste nechtěli svěřit ke zpracování třetí straně.

Proč mi chybí obrázky a CSS?

Nahraje se jen samotný HTML soubor. Soubory, na které odkazuje relativní cestou, zůstanou na vašem počítači; použijte absolutní odkazy https:// nebo je vložte přímo do HTML.

Můžu nastavit formát stránky nebo okraje?

Na stránce nástroje ne. Nastavte je v HTML pravidlem CSS @page, například @page { size: A4; margin: 15mm; }.

Budou odkazy v PDF klikací?

Odkazy na webové adresy obvykle klikací zůstanou. Relativní odkazy na jiné lokální soubory nikam užitečně nepovedou.

Spouští se při převodu JavaScript?

Může se částečně spustit, ale obsah, který se načítá později nebo závisí na akci uživatele, často chybí. Pro spolehlivý výsledek by HTML mělo už obsahovat finální obsah.
