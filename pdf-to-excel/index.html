The usual reason anyone wants a PDF in Excel is a table: a bank statement, a price list, a report appendix, an exam result sheet. In the PDF the numbers look tidy, but there is no grid underneath. Each figure is a separate piece of text placed at a position on the page, and the lines that look like cell borders are only drawings. Copying from a PDF viewer into a spreadsheet therefore tends to dump everything into one column.

A proper converter looks at where the text sits, decides which items line up vertically into columns and horizontally into rows, and writes that into real spreadsheet cells. PDFora sends the PDF to a server-side conversion engine for this (CloudConvert, through our own relay), because that analysis is far beyond what a web page can do reliably. The file is uploaded over an encrypted connection, converted to .xlsx and downloaded back to you; the uploaded copy is removed from the service after the job.

There are no options to set: one PDF in, one workbook out, covering the whole document. Expect clean results from PDFs exported by accounting software or spreadsheets, and more cleanup from designed reports, rotated tables or scans. Numbers in particular deserve a check, because a value that looks right can still be stored as text.

How to convert a PDF to Excel

  1. Open PDF to Excel and choose one PDF. If you only need a single table, extract its pages first so the workbook contains nothing else.
  2. Click Convert and watch the status move through Uploading and Converting.
  3. Wait for the download. The tool polls the server every couple of seconds and stops after around three minutes if the job has not finished.
  4. Save the .xlsx (the original file name with an .xlsx extension, unless the server returns a different name).
  5. Open the workbook, select the number columns and check that Excel treats them as numbers, for example by summing a column and comparing the total with the PDF.

When to use this tool

  • A small shop owner turning a supplier's PDF price list into a sheet they can add their own margin column to.
  • Reconciling a bank or card statement against bookkeeping entries.
  • An NGO collecting survey summaries that partner offices sent as PDF reports.
  • Students analysing tables from a published government statistics PDF.
  • Reworking a timetable or roster that arrived as a PDF so it can be filtered by person or day.
  • Pulling inventory lists out of old reports where the source spreadsheet no longer exists.

What to know before you start

  • The file is processed on a server, not in your browser: uploaded encrypted, converted, and deleted from the conversion service afterwards.
  • Scanned tables are images. Without a text layer there are no numbers to place in cells, so run the OCR tool first; even then, check every figure because OCR can misread digits such as 1 and 7 or 0 and 8.
  • Number formats may arrive as text. Thousands separators, currency symbols, a minus sign written as brackets or a trailing CR can stop Excel from recognising a value as a number.
  • Merged headings, wrapped cell text and rows that span two lines in the PDF often split across several spreadsheet rows.
  • Content that is not a table (paragraphs, footnotes, page headers) also lands in cells, so expect some clearing out.
  • Password-protected PDFs cannot be converted; remove the protection in the source application first. A spreadsheet that runs a running balance formula next to the converted balance column will flag the first row where the two numbers disagree, which is usually the row the converter shifted.

Tips for the best results

  • Extract only the pages containing the table before converting; it keeps the workbook small and the cleanup focused.
  • If numbers sit on the left of their cells, they are text. Use Data > Text to Columns with no changes, or multiply by 1, to turn them into numbers.
  • Check the regional setting: a PDF using commas as decimal separators can confuse a spreadsheet set up for points, and the other way round.
  • Delete repeated header rows (one per PDF page) with a filter on the header text rather than by hand.
  • Always compare at least one column total with the PDF before trusting the converted figures.

Example: a freelancer reconciling a quarterly statement

A freelance designer receives a four-page PDF statement from her payment processor listing 63 incoming payments for the quarter. Her accountant wants them in a spreadsheet with the client name, date, gross amount and fee in separate columns.

She converts the PDF and opens the workbook. The rows are there, but every page starts with a repeated header row, and the fee column shows values like (2.40) for deductions, which Excel reads as text. She filters out the header rows, uses Find and Replace to turn the brackets into a leading minus sign, and converts the column to numbers. The dates came through as real dates because the PDF used an unambiguous year-month-day format.

As a final check she sums the gross column and compares it with the total printed on the last page of the statement. They match to the cent, so she knows no row was dropped or split. That one comparison is worth doing on every converted table. Bank statements deserve a specific warning. Many banks print the running balance in its own column and leave blank cells where a transaction has no debit or no credit. After conversion those blanks sometimes collapse, which shifts a credit into the debit column on that row only. Sorting or filtering will not reveal it; only a total, or a running-balance formula compared with the printed balance, will. Build that check in once and you can reuse the sheet for every month that follows.

Troubleshooting

Everything is in column A
The converter could not detect columns, often because the PDF used spaces rather than positions to align text. Use Data > Text to Columns with a space or fixed-width split.
Numbers will not add up
They are stored as text. Remove currency symbols and thousands separators, then convert the cells to numbers; check for brackets used as minus signs.
One PDF row became two spreadsheet rows
A cell in the PDF wrapped onto a second line. Join the parts with a formula such as =A2&" "&A3 or edit them by hand, then delete the extra row.
The workbook is full of images instead of numbers
The PDF is a scan. Run it through OCR first, convert the result, and proof the digits.
The job timed out
Large reports can take longer than the tool's roughly three-minute wait. Extract the pages with the tables and convert just those.
Conversion failed on the server
Check whether the PDF asks for a password or is damaged. Remove protection or run Repair PDF, then try again.

Frequently asked questions

Do I get one sheet per page or one sheet for everything?

That depends on how the conversion engine reads your document; multi-page tables are often split by page. Combine them with copy and paste or Power Query if needed.

Will formulas from the original spreadsheet come back?

No. A PDF only stores the displayed values, so the workbook contains numbers and text, not the formulas that produced them.

Can it read tables from scanned documents?

Only after OCR. Run the OCR tool first, then convert, and check figures carefully.

Does it work with Google Sheets or LibreOffice?

Yes. The output is a standard .xlsx file that both can open.

Why are some dates wrong?

Dates like 03/04 are ambiguous. Excel interprets them using your regional settings, so check a few dates against the PDF.

Is the file uploaded?

Yes, this tool uses a server-side converter. The PDF is sent encrypted and deleted from the service after the conversion.
