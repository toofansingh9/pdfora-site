HTML in PDF

Converti un file HTML salvato in PDF tramite un server di conversione, trasformando una pagina web o un'esportazione HTML in pagine fisse e stampabili.

🔒 I tuoi file vengono elaborati localmente nel browser e non vengono mai caricati.
1

Carica

Seleziona il tuo file o trascinalo.

2

Regola

Scegli le tue opzioni — tutto avviene nel tuo browser.

3

Scarica

Salva subito il file finito. Nessuna filigrana.

Molti documenti utili esistono solo in HTML: una conferma d'ordine salvata dal browser, un report esportato da un gestionale, una newsletter, una documentazione generata come pagina unica o una pagina che hai costruito tu. L'HTML si adatta alla finestra in cui viene aperto, ed è proprio quello che non vuoi quando il documento va archiviato, stampato o allegato a una pratica. Il PDF lo blocca su un formato di pagina preciso.

Lo strumento accetta un file .html o .htm dal tuo computer, non un indirizzo web. Il file viene caricato in forma cifrata sul servizio CloudConvert tramite il relay di PDFora: lì un motore di rendering impagina la pagina e la stampa in PDF. Il risultato torna con il nome del tuo file e viene poi cancellato dal servizio. La conversione quindi non avviene nel browser, e nella pagina dello strumento non ci sono impostazioni per formato o margini.

La sorpresa più comune riguarda tutto ciò a cui il file HTML fa riferimento. Una pagina web raramente è un file solo: immagini, fogli di stile e font sono di solito file separati, richiamati dall'HTML. Viene caricato solo il file che scegli, quindi tutto ciò che è indicato con un percorso relativo sul tuo disco il server non lo trova. Per ottenere un PDF fedele, il lavoro vero è rendere il file HTML autosufficiente prima di convertirlo.

Come convertire un file HTML in PDF

  1. Verifica che il file HTML sia autosufficiente o che usi indirizzi web completi (https://...) per immagini e fogli di stile; trovi i dettagli più sotto.
  2. Apri HTML in PDF e seleziona il file .html o .htm.
  3. Fai clic su Converti e attendi che il file venga caricato e impaginato sul server.
  4. Scarica il PDF, che mantiene il nome del tuo file con estensione .pdf.
  5. Controlla che immagini, colori e layout siano arrivati e che nulla sia tagliato sul bordo destro.

Quando usare questo strumento

  • Ricevute e conferme di prenotazione salvate dal browser, da conservare in PDF per il commercialista o come prova.
  • Report esportati in HTML da un software, da allegare a un'email o da archiviare.
  • Sviluppatori che trasformano in PDF un modello HTML di fattura, attestato o lettera per controllarne la resa in stampa.
  • Documentazione o manuali pubblicati come un'unica lunga pagina HTML, da stampare e leggere offline.
  • Articoli web salvati per una ricerca, in un formato che non cambia se cambia il sito.
  • Newsletter salvate in HTML e convertite per tenere traccia di ciò che è stato inviato.

Cosa sapere prima di iniziare

  • I collegamenti relativi non funzionano. Se l'HTML contiene <img src="images/logo.png"> o <link href="style.css">, quei file restano sul tuo computer e il server non li vede: nel PDF mancano le immagini e il testo è senza stile. Usa indirizzi assoluti https://, oppure inserisci il CSS in un blocco <style> e le immagini come data URI.
  • Le risorse con indirizzo web assoluto possono essere scaricate dal server durante il rendering, quindi immagini e fogli di stile pubblici di solito compaiono. Non compare invece nulla che stia dietro un login, in una intranet o su localhost.
  • Non c'è un campo per l'URL. Per convertire una pagina online devi prima salvarla. Il formato Pagina web, file singolo (.mhtml) non è accettato: usa Pagina web, solo HTML, mettendo in conto che le immagini relative mancheranno, oppure usa direttamente Stampa > Salva come PDF del browser.
  • Gli stili di stampa vengono applicati. Se la pagina ha regole CSS per @media print, il convertitore di norma le usa, e questo può nascondere menu di navigazione o cambiare i colori rispetto a ciò che vedi a schermo. Le interruzioni di pagina si controllano in CSS con break-before e break-inside.
  • I contenuti generati da JavaScript sono poco affidabili. Le pagine che caricano i contenuti con script dopo l'apertura possono uscire come un guscio vuoto. Salva la pagina quando è completamente caricata, oppure genera il contenuto direttamente nell'HTML lato server.
  • I layout più larghi di una pagina stampata, come design fissi a 1400 pixel o tabelle molto larghe, possono risultare tagliati o rimpiccioliti. Di solito si risolve con un layout responsive o con un max-width sul contenuto principale.

Consigli per risultati migliori

  • Per i tuoi modelli, metti tutto il CSS in un blocco <style> nell'<head>: è il modo più sicuro in assoluto per ottenere un PDF con lo stile giusto.
  • Se ti servono un formato o margini precisi, aggiungi al CSS @page { size: A4; margin: 15mm; }.
  • Usa break-inside: avoid su righe di tabella, riquadri e figure, così non vengono spezzati tra due pagine.
  • Tieni d'occhio il peso delle immagini: un'immagine da 5 MB inserita come data URI produce comunque un PDF da 5 MB.
  • Apri prima il file HTML nell'anteprima di stampa del browser: se lì non va bene, molto probabilmente non andrà bene nemmeno nel PDF convertito.

Un esempio pratico: il modello di fattura HTML di un piccolo negozio online

Un piccolo e-commerce gestito da due soci a Torino genera le fatture come file HTML con un semplice script. Ogni file richiama invoice.css e logo.png nella stessa cartella. Convertito così com'è, il PDF esce in testo nero semplice con il font di sistema, senza logo e con la tabella dei totali allargata su tutta la pagina, perché il server ha ricevuto il file HTML senza foglio di stile e senza immagine.

La soluzione è rendere il file indipendente. Ora lo script copia il contenuto di invoice.css in un blocco <style>, aggiunge @page { size: A4; margin: 18mm; } e break-inside: avoid sulle righe della tabella degli articoli, e fa puntare il logo al suo indirizzo https pubblico sul sito del negozio invece che a un percorso locale. Nient'altro cambia.

Riconvertita, la fattura è un PDF A4 di una pagina con logo, colori del negozio e una tabella dei totali che non si spezza più quando l'ordine ha molte righe. Visto che il modello ora è autosufficiente, ogni fattura prodotta dallo script si converte allo stesso modo.

Risoluzione dei problemi

Il PDF non ha stile, solo testo semplice
Il foglio di stile era richiamato con un percorso relativo e non è stato caricato. Inserisci il CSS in un blocco <style> o collegalo con un indirizzo https:// completo.
Mancano le immagini
Le immagini sul tuo disco richiamate con percorsi relativi non sono raggiungibili. Usa URL https:// pubblici o inserisci le immagini come data URI, poi converti di nuovo.
La pagina è tagliata a destra
Il layout ha una larghezza fissa maggiore della pagina. Aggiungi max-width: 100% ai contenitori principali e alle immagini, oppure un foglio di stile per la stampa che restringa il layout.
Il PDF è vuoto o quasi
Probabilmente il contenuto viene creato da JavaScript dopo il caricamento, oppure il file è solo un reindirizzamento. Salva la pagina quando è completamente visualizzata, o genera il contenuto direttamente nell'HTML.
Il testo compare con un altro font
I web font richiamati in locale non erano disponibili. Collega il font da un URL pubblico, incorporalo con @font-face e un data URI, oppure usa una serie di font comuni.
Lo strumento rifiuta il mio file
Sono accettati solo .html e .htm. I file .mhtml o .webarchive vanno salvati di nuovo come solo HTML.

Domande frequenti

Posso convertire un sito inserendo il suo URL?

No. Lo strumento converte un file HTML che selezioni tu. Salva prima la pagina in HTML, oppure per una pagina online usa Stampa > Salva come PDF del browser.

Il file HTML viene caricato online?

Sì. Viene inviato cifrato al servizio di conversione, impaginato lì e poi cancellato. Evita di convertire pagine con dati personali che non vorresti far trattare a terzi.

Perché mancano immagini e CSS?

Viene caricato solo il file HTML. I file che richiama con percorsi relativi restano sul tuo computer: usa link assoluti https:// oppure incorporali nell'HTML.

Posso impostare formato e margini della pagina?

Non dalla pagina dello strumento. Impostali nell'HTML con una regola CSS @page, ad esempio @page { size: A4; margin: 15mm; }.

I link nel PDF sono cliccabili?

I link a indirizzi web di norma restano cliccabili. I link relativi ad altri file locali non porteranno da nessuna parte.

JavaScript viene eseguito durante la conversione?

In parte può esserlo, ma i contenuti che arrivano in ritardo o che dipendono da un'interazione dell'utente spesso mancano. Per risultati affidabili, l'HTML dovrebbe contenere già il contenuto definitivo.
