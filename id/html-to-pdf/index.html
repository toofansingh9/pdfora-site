HTML ke PDF

Ubah file HTML yang tersimpan menjadi PDF melalui server konversi, sehingga halaman web atau hasil ekspor HTML menjadi halaman tetap yang siap dicetak.

🔒 File Anda diproses secara lokal di browser dan tidak pernah diunggah.
1

Unggah

Pilih file Anda atau seret dan lepas.

2

Sesuaikan

Pilih opsi Anda — semuanya berlangsung di browser Anda.

3

Unduh

Simpan file yang selesai secara instan. Tanpa watermark.

Kenapa repot mengubah HTML menjadi PDF? Karena HTML selalu menyesuaikan diri dengan lebar layar tempat ia dibuka, sedangkan dokumen yang harus diarsipkan, dicetak, atau dilampirkan ke pengajuan klaim butuh bentuk yang tetap. Dan ternyata banyak dokumen penting yang hanya ada sebagai HTML: bukti pemesanan yang disimpan dari browser, laporan hasil ekspor aplikasi, newsletter, panduan yang terbit sebagai satu halaman panjang, atau template buatan Anda sendiri. PDF membekukan semuanya dalam satu ukuran halaman.

HTML ke PDF menerima file .html atau .htm dari komputer Anda, bukan alamat situs. File itu diunggah terenkripsi ke layanan CloudConvert melalui relay PDFora, lalu mesin rendering di sana menyusun tata letaknya dan mencetaknya ke PDF. Hasilnya kembali dengan nama yang sama seperti file Anda, dan file dihapus dari layanan itu setelah selesai. Konversi tidak dilakukan di browser Anda, dan halaman alat ini tidak menyediakan pengaturan ukuran kertas maupun margin.

Yang paling sering membuat orang kaget adalah nasib file-file pendukung. Halaman web jarang berdiri sendiri: gambar, stylesheet, dan font biasanya file terpisah yang dipanggil dari HTML. Padahal yang diunggah hanya satu file yang Anda pilih, jadi semua yang dirujuk dengan path relatif di disk Anda tidak akan ditemukan oleh server. Kunci PDF yang mirip aslinya adalah membuat file HTML itu mandiri sebelum dikonversi.

Cara mengubah HTML ke PDF

  1. Pastikan file HTML sudah mandiri atau memakai alamat web lengkap (https://...) untuk gambar dan stylesheet-nya; lihat catatan di bawah.
  2. Buka alat HTML ke PDF dan pilih file .html atau .htm Anda.
  3. Klik Konversi, lalu tunggu selama file diunggah dan dirender di server.
  4. Unduh PDF-nya; nama file tetap sama seperti file Anda, hanya ekstensinya menjadi .pdf.
  5. Periksa apakah gambar, warna, dan tata letak terbawa dengan benar, dan tidak ada konten yang terpotong di tepi kanan.

Kapan menggunakan alat ini

  • Bukti pemesanan tiket kereta, pesawat, atau hotel yang disimpan dari browser, diarsipkan sebagai PDF untuk laporan perjalanan dinas atau reimburse kantor.
  • Laporan hasil ekspor aplikasi dalam format HTML yang perlu dilampirkan ke email atau diarsipkan.
  • Developer yang mengecek tampilan cetak template faktur, sertifikat, atau surat berbasis HTML.
  • Panduan pengguna atau dokumentasi yang terbit sebagai satu halaman HTML panjang, dicetak untuk dibaca offline.
  • Artikel web yang disimpan sebagai bahan skripsi atau riset, dalam bentuk yang tidak ikut berubah meski situsnya diperbarui.
  • Newsletter email yang disimpan sebagai HTML lalu dikonversi sebagai arsip dari apa yang sudah dikirim.

Yang perlu diketahui sebelum mulai

  • Path relatif akan putus. Jika HTML berisi <img src="images/logo.png"> atau <link href="style.css">, file-file itu tetap di komputer Anda dan tidak bisa dilihat server. Akibatnya PDF menampilkan gambar yang hilang dan teks tanpa gaya. Gunakan alamat https:// absolut, atau masukkan CSS ke dalam blok <style> dan gambar sebagai data URI.
  • Sumber daya dengan alamat web absolut mungkin diambil oleh server saat merender halaman, jadi gambar dan stylesheet yang bisa diakses publik biasanya muncul. Apa pun yang berada di balik login, di intranet, atau di localhost tidak akan muncul.
  • Tidak ada kolom URL. Untuk mengonversi halaman yang sedang tayang, simpan dulu halamannya. Format Save Page As > Web Page, Single File (.mhtml) di browser tidak diterima, jadi pilih Web Page, HTML Only dan bersiaplah gambar relatifnya hilang, atau gunakan fitur Print > Save as PDF bawaan browser.
  • Gaya cetak ikut berlaku. Jika halaman punya CSS untuk @media print, konverter biasanya memakainya, sehingga bilah navigasi bisa tersembunyi atau warnanya berbeda dari tampilan di layar. Pergantian halaman bisa diatur dengan break-before dan break-inside di CSS.
  • Konten yang dibangun JavaScript tidak bisa diandalkan. Halaman yang mengambil isinya lewat skrip setelah dimuat bisa terkonversi sebagai kerangka kosong. Simpan halaman setelah benar-benar selesai dimuat, atau render kontennya ke dalam HTML dari sisi server.
  • Tata letak yang lebih lebar dari halaman cetak, misalnya desain dengan lebar tetap 1400 piksel atau tabel yang lebar, bisa terpotong atau mengecil. Tata letak responsif atau max-width pada konten utama biasanya menyelesaikannya.

Tips untuk hasil terbaik

  • Untuk template buatan sendiri, taruh semua CSS di blok <style> di dalam <head>; inilah cara paling andal untuk mendapatkan PDF yang tetap bergaya.
  • Tambahkan @page { size: A4; margin: 15mm; } ke CSS jika Anda butuh ukuran halaman atau margin tertentu.
  • Pakai break-inside: avoid pada baris tabel, kartu, dan gambar agar tidak terbelah di dua halaman.
  • Jaga ukuran gambar tetap wajar: gambar banner 5 MB yang ditanam sebagai data URI tetap menghasilkan PDF 5 MB.
  • Buka dulu file HTML di print preview browser; kalau tampilannya sudah salah di sana, kemungkinan besar PDF hasil konversinya juga salah.

Contoh nyata: sertifikat kursus dari template HTML

Arif mengurus sistem di sebuah lembaga kursus bahasa di Yogyakarta. Ia membuat sertifikat kelulusan dalam bentuk template HTML: latar bermotif di folder img, font dari folder fonts, dan nama peserta yang diisi oleh JavaScript setelah halaman dimuat. Di browser-nya semua tampak sempurna, tetapi PDF hasil konversi pertama hanya menampilkan teks polos dengan font standar, tanpa latar, dan kolom nama peserta kosong.

Ketiga masalah itu bersumber dari hal yang sama: server hanya menerima satu file HTML. Arif mengubah skripnya supaya nama peserta langsung tertulis di HTML saat file dibuat, bukan diisi JavaScript belakangan. Gambar latar sekitar 300 KB ia tanam sebagai data URI, font ditanam lewat @font-face dengan data URI, dan ia menambahkan @page { size: A4 landscape; margin: 0; } di blok <style>.

Konversi berikutnya menghasilkan sertifikat A4 lanskap satu halaman, lengkap dengan latar, font, dan nama peserta. Ukuran PDF-nya naik mengikuti gambar latar yang ditanam, jadi Arif memperkecil gambar itu lebih dulu sebelum membuat sertifikat untuk 45 peserta angkatan berikutnya.

Pemecahan masalah

PDF tidak bergaya, hanya teks polos
Stylesheet dirujuk dengan path relatif sehingga tidak ikut terunggah. Masukkan CSS ke blok <style> atau tautkan dengan alamat https:// lengkap.
Gambar tidak muncul
Gambar di disk Anda yang dirujuk dengan path relatif tidak bisa dijangkau. Pakai URL https:// publik atau tanam gambar sebagai data URI, lalu konversi ulang.
Halaman terpotong di sisi kanan
Tata letaknya memakai lebar tetap yang melebihi halaman. Tambahkan max-width: 100% pada kontainer utama dan gambar, atau stylesheet cetak yang mempersempit tata letak.
PDF kosong atau hampir kosong
Kemungkinan kontennya dibuat oleh JavaScript setelah halaman dimuat, atau file itu hanya berisi pengalihan. Simpan halaman setelah selesai dirender sepenuhnya, atau tulis kontennya langsung di dalam HTML.
Teks muncul dengan font yang berbeda
Web font yang dirujuk secara lokal tidak tersedia. Tautkan font dari URL publik, tanam dengan @font-face dan data URI, atau gunakan font yang umum.
Alat menolak file saya
Hanya .html dan .htm yang diterima. File .mhtml atau .webarchive perlu disimpan ulang sebagai HTML saja.

Pertanyaan yang sering diajukan

Bisa nggak saya tempel URL situs untuk dikonversi?

Tidak bisa. Alat ini hanya mengonversi file HTML yang Anda pilih. Simpan dulu halamannya sebagai HTML, atau pakai Print > Save as PDF di browser untuk halaman yang sedang dibuka.

File HTML saya dikirim ke server?

Ya. File dikirim terenkripsi ke layanan konversi, dirender di sana, lalu dihapus. Hindari mengonversi halaman berisi data pribadi yang tidak ingin Anda serahkan ke pihak ketiga.

Kenapa gambar dan CSS saya tidak muncul di PDF?

Karena yang diunggah hanya file HTML-nya. File yang dirujuk dengan path relatif tetap tertinggal di komputer Anda; pakai tautan https:// lengkap atau tanam langsung ke dalam HTML.

Ukuran kertas dan margin bisa diatur?

Tidak di halaman alat. Aturlah di HTML dengan CSS @page, misalnya @page { size: A4; margin: 15mm; }.

Link di PDF hasilnya masih bisa diklik?

Tautan ke alamat web biasanya tetap bisa diklik. Tautan relatif ke file lokal lain tidak akan mengarah ke mana pun yang berguna.

JavaScript di halaman ikut dijalankan?

Mungkin sebagian, tetapi konten yang dimuat belakangan atau yang menunggu interaksi pengguna sering tidak muncul. Supaya hasilnya bisa diandalkan, isi HTML sebaiknya sudah final sebelum dikonversi.
