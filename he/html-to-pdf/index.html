HTML ל-PDF

המרת קובץ HTML שמור ל-PDF בשרת המרה, כך שדף אינטרנט או ייצוא HTML הופכים לעמודים קבועים שאפשר להדפיס.

🔒 הקבצים שלכם מעובדים מקומית בדפדפן ולעולם אינם מועלים לשרת.

העלאה

התאמה

הרבה מסמכים שימושיים קיימים רק כ-HTML: אישור הזמנה ששמרתם מהדפדפן, דוח שאפליקציה ייצאה, ניוזלטר, תיעוד שנוצר כדף אחד ארוך או דף שבניתם בעצמכם. HTML מתארגן מחדש לפי גודל החלון שבו הוא מוצג, וזה בדיוק מה שלא רוצים כשצריך לתייק את המסמך, להדפיס אותו או לצרף אותו לתביעה. PDF מקבע אותו בגודל עמוד אחד.

הכלי מקבל קובץ ‎.html או ‎.htm מהמחשב שלכם, לא כתובת אינטרנט. הקובץ מועלה בצורה מוצפנת לשירות CloudConvert דרך שרת הממסר של PDFora, ושם מנוע תצוגה פורס את הדף ומדפיס אותו ל-PDF; התוצאה חוזרת בשם הקובץ שלכם ונמחקת מהשירות לאחר מכן. ההמרה לא מתבצעת בדפדפן, ובדף הכלי אין הגדרות לגודל עמוד או לשוליים.

מה שמפתיע את רוב האנשים הוא מה שקורה לכל מה שקובץ ה-HTML מפנה אליו. דף אינטרנט הוא כמעט אף פעם לא קובץ אחד: תמונות, גיליונות סגנון וגופנים הם בדרך כלל קבצים נפרדים שה-HTML מפנה אליהם. רק הקובץ היחיד שבחרתם מועלה, ולכן כל מה שמוזכר בנתיב יחסי בדיסק שלכם לא נגיש לשרת. כדי לקבל PDF נאמן למקור, העיקר הוא להפוך את קובץ ה-HTML לעצמאי לפני ההמרה.

איך ממירים HTML ל-PDF

  1. ודאו שקובץ ה-HTML עצמאי, או שהוא משתמש בכתובות מלאות (https://...) לתמונות ולגיליונות הסגנון; ראו את ההערות בהמשך.
  2. פתחו את HTML ל-PDF ובחרו את קובץ ה-‎.html או ה-‎.htm.
  3. לחצו על המרה והמתינו בזמן שהקובץ מועלה ומעובד בשרת.
  4. הורידו את ה-PDF; הוא שומר על שם הקובץ שלכם עם הסיומת ‎.pdf.
  5. בדקו שהתמונות, הצבעים והפריסה עברו כמו שצריך, ושאין תוכן שנחתך בקצה הימני.

מתי להשתמש בכלי הזה

  • קבלות ואישורי הזמנה ששמרתם מהדפדפן ורוצים לשמור כ-PDF להנהלת חשבונות או כתיעוד משפטי.
  • דוחות שתוכנה מייצאת כ-HTML וצריך לצרף למייל או לשמור בארכיון.
  • מפתחים שהופכים תבנית HTML של חשבונית, תעודה או מכתב ל-PDF כדי לבדוק את פריסת ההדפסה.
  • תיעוד או מדריך למשתמש שפורסם כדף HTML ארוך אחד ומודפס לקריאה בלי חיבור.
  • כתבות שנשמרו מהרשת לצורך מחקר, בפורמט שלא ישתנה גם אם האתר ישתנה.
  • ניוזלטרים במייל שנשמרו כ-HTML ומומרים כתיעוד של מה שנשלח.

מה כדאי לדעת לפני שמתחילים

  • קישורים יחסיים נשברים. אם ב-HTML כתוב <img src="images/logo.png"> או <link href="style.css">, הקבצים האלה נשארים במחשב שלכם והשרת לא רואה אותם. ב-PDF יופיעו אז תמונות חסרות וטקסט בלי עיצוב. השתמשו בכתובות https:// מלאות, או הטמיעו את ה-CSS בבלוק <style> ואת התמונות כ-data URI.
  • משאבים עם כתובת אינטרנט מלאה עשויים להיטען על ידי השרת בזמן התצוגה, ולכן תמונות וגיליונות סגנון ציבוריים בדרך כלל מופיעים. כל מה שמאחורי התחברות, ברשת פנימית או ב-localhost לא יופיע.
  • אין שדה לכתובת URL. כדי להמיר דף חי, שמרו אותו קודם. האפשרות 'שמירה בשם' > דף אינטרנט, קובץ יחיד (‎.mhtml) לא מתקבלת, אז בחרו דף אינטרנט, HTML בלבד, והיו מוכנים לכך שתמונות יחסיות יחסרו, או השתמשו בהדפסה > שמירה כ-PDF של הדפדפן עצמו.
  • סגנונות הדפסה חלים. אם לדף יש CSS עבור ‎@media print, הממיר בדרך כלל משתמש בו, וזה יכול להסתיר סרגלי ניווט או לשנות צבעים לעומת מה שרואים במסך. אפשר לשלוט במעברי עמוד בעזרת break-before ו-break-inside ב-CSS.
  • תוכן שנבנה ב-JavaScript לא אמין. דפים שמושכים את התוכן שלהם בסקריפטים אחרי הטעינה עלולים להיות מומרים כשלד ריק. שמרו את הדף אחרי שנטען במלואו, או צרו את התוכן בתוך ה-HTML בצד השרת.
  • פריסות רחבות מעמוד מודפס, כמו עיצוב קבוע של 1400 פיקסלים או טבלאות רחבות, עלולות להיחתך או להתכווץ. פריסה רספונסיבית או max-width על התוכן הראשי בדרך כלל פותרות את זה.

טיפים לתוצאות הטובות ביותר

  • בתבניות שלכם, שימו את כל ה-CSS בבלוק <style> בתוך ה-<head>; זו הדרך הבטוחה ביותר לקבל PDF מעוצב.
  • הוסיפו ל-CSS את ‎@page { size: A4; margin: 15mm; }‎ אם צריך גודל עמוד או שוליים מסוימים.
  • השתמשו ב-break-inside: avoid על שורות טבלה, כרטיסים ואיורים כדי שלא יתפצלו בין שני עמודים.
  • שמרו על גודל תמונות סביר: תמונה של 5 MB שמוטמעת כ-data URI עדיין יוצרת PDF של 5 MB.
  • פתחו קודם את קובץ ה-HTML בתצוגה המקדימה להדפסה של הדפדפן; אם זה נראה לא טוב שם, כנראה שזה ייראה לא טוב גם ב-PDF.

דוגמה מעשית: תבנית חשבונית HTML של חנות קטנה

חנות אונליין של שני שותפים מפתח תקווה מפיקה חשבוניות כקובצי HTML בעזרת סקריפט פשוט. כל קובץ מקשר ל-invoice.css ול-logo.png באותה תיקייה. כשממירים אותו כמו שהוא, ה-PDF יוצא כטקסט שחור פשוט בגופן ברירת מחדל, בלי לוגו, וטבלת הסכומים נמתחת לכל הרוחב, כי השרת קיבל את קובץ ה-HTML בלי גיליון הסגנון והתמונה.

הפתרון הוא להפוך את הקובץ לעצמאי. עכשיו הסקריפט מעתיק את התוכן של invoice.css לבלוק <style>, מוסיף ‎@page { size: A4; margin: 18mm; }‎ ו-break-inside: avoid לשורות טבלת הפריטים, ומפנה את הלוגו לכתובת ה-https הציבורית שלו באתר החנות במקום לנתיב מקומי. שום דבר אחר לא משתנה.

בהמרה החוזרת החשבונית יוצאת כ-PDF של עמוד A4 אחד, עם הלוגו, צבעי החנות וטבלת סכומים שכבר לא מתפצלת כשבהזמנה יש הרבה שורות. מכיוון שהתבנית עכשיו עצמאית, כל חשבונית שהסקריפט מפיק מומרת באותה צורה.

פתרון בעיות

ב-PDF אין עיצוב, רק טקסט פשוט
גיליון הסגנון הוזכר בנתיב יחסי ולא הועלה. הטמיעו את ה-CSS בבלוק <style> או קשרו אליו בכתובת https:// מלאה.
תמונות חסרות
לתמונות בדיסק שלכם שמוזכרות בנתיבים יחסיים אין גישה. השתמשו בכתובות https:// ציבוריות או הטמיעו את התמונות כ-data URI, והמירו שוב.
העמוד נחתך בצד ימין
לפריסה יש רוחב קבוע גדול מהעמוד. הוסיפו max-width: 100%‎ לאזורים הראשיים ולתמונות, או גיליון סגנון להדפסה שמצמצם את הפריסה.
ה-PDF ריק או כמעט ריק
סביר שהתוכן נוצר ב-JavaScript אחרי הטעינה, או שהקובץ הוא רק הפניה. שמרו את הדף אחרי שהוצג במלואו, או הפיקו את התוכן בתוך ה-HTML עצמו.
הטקסט מופיע בגופן אחר
גופני רשת שהוזכרו באופן מקומי לא היו זמינים. קשרו את הגופן מכתובת ציבורית, הטמיעו אותו עם ‎@font-face ו-data URI, או השתמשו ברשימת גופנים נפוצים.
הכלי דוחה את הקובץ שלי
מתקבלים רק ‎.html ו-‎.htm. קובצי ‎.mhtml או ‎.webarchive צריך לשמור מחדש כ-HTML בלבד.

שאלות נפוצות

אפשר להמיר אתר על ידי הזנת הכתובת שלו?

לא. הכלי ממיר קובץ HTML שאתם בוחרים. שמרו קודם את הדף כ-HTML, או השתמשו בהדפסה > שמירה כ-PDF של הדפדפן עבור דף חי.

האם קובץ ה-HTML מועלה?

כן. הוא נשלח מוצפן לשירות ההמרה, מעובד שם ונמחק לאחר מכן. הימנעו מהמרת דפים שמכילים מידע אישי שלא הייתם רוצים שצד שלישי יעבד.

למה התמונות וה-CSS שלי חסרים?

רק קובץ ה-HTML עצמו מועלה. קבצים שהוא מפנה אליהם בנתיבים יחסיים נשארים במחשב שלכם; השתמשו בקישורי https:// מלאים או הטמיעו אותם ב-HTML.

אפשר לקבוע גודל עמוד או שוליים?

לא בדף הכלי. הגדירו אותם ב-HTML בעזרת כלל CSS ‏‎@page‎, למשל ‎@page { size: A4; margin: 15mm; }‎.

האם הקישורים לחיצים ב-PDF?

קישורים לכתובות אינטרנט בדרך כלל נשארים לחיצים. קישורים יחסיים לקבצים מקומיים אחרים לא יובילו לשום מקום שימושי.

האם JavaScript רץ בזמן ההמרה?

ייתכן שחלקית, אבל תוכן שנטען באיחור או שתלוי בפעולת משתמש חסר לעיתים קרובות. לתוצאה אמינה, ה-HTML צריך כבר להכיל את התוכן הסופי.
