Why PDF to Word Messes Up Formatting, and How to Fix It

By Toofan Singh · 31 October 2026 · 9 min read

PDF to Word layouts shift because a PDF stores fixed positions, not paragraphs, so the converter has to rebuild structure by guessing. Check whether your PDF has real text or is a scan, choose PDF to Word, PDF to Text or OCR accordingly, and then clean the .docx in Word with formatting marks, styles and section breaks.

Why a converted document never matches the PDF exactly

A Word file and a PDF describe a page in opposite ways. In Word you write a stream of paragraphs and the program decides where each line wraps and where each page ends. A PDF stores the finished result of that process: this word, in this font, at this exact position on this page. The paragraphs, the styles, the table that held a row together and the column that text flowed through are usually gone by the time the file is saved. What survives is a list of drawing instructions.

A PDF to Word converter has to run the process backwards. It looks at loose words and positions and guesses which lines belong to one paragraph, where one column stops and the next begins, and whether a set of ruled lines and numbers is a table or just a drawing. When the guesses are right you get a document you can edit straight away. When they are wrong you get the familiar symptoms: every line ending in a hard break, text sitting in floating boxes, tables made of tabs and spaces, and pages that end in different places from the original. Microsoft's own help for opening PDFs in Word warns of the same thing: lines and pages can break at different points, and files that look like photocopied manuscripts convert badly.

The five things that cause most layout shifts

Fixed positions instead of flow

Because the PDF only knows where each line sat, the converter must decide whether two lines are one paragraph or two. A heading followed by a short line, a numbered clause that wraps, or a block quote with a different indent are the usual places where it decides wrongly. The result is either a paragraph broken into one-line pieces or two paragraphs glued together.

Fonts

Most PDFs embed only the characters of a font they actually use, and that subset is for display, not editing. When the .docx opens, Word looks for a font of the same name on your computer. If it is not installed, Word substitutes another one. Even a small change in letter width moves the line endings, and a few extra lines per page are enough to push headings and tables onto the next page.

Columns, sidebars and text boxes

A two-column newsletter, a CV with a side panel or a brochure with pull quotes has no single reading order on the page. Converters often rebuild these as separate text boxes or frames placed at fixed positions. They look right at first, but as soon as you edit, the text no longer flows from one box into the next.

Tables

A table in a PDF is often just ruling lines with words placed between them. If the lines are missing, faint, or the cells contain wrapped text, the converter may produce one table per row, a table with merged cells in the wrong places, or plain text separated by tabs.

Scanned pages

A scan contains no text at all, only a picture of a page. There is nothing for the converter to rebuild, so a scanned page normally arrives in Word as one image per page. No amount of cleanup in Word fixes that; the text has to be recognised first.

Check what kind of PDF you have

Thirty seconds of checking tells you which route to take. Open the PDF in any viewer and try to select a sentence. If you can highlight individual words and paste them into a note, the file has a real text layer. If dragging selects the whole page as a rectangle, or nothing at all, it is a scan or an image-only export.

A second quick check is PDF to Text. It reads only the text layer, so if the .txt it returns is empty or nearly empty, you are dealing with images. Some files are mixed: a typed letter with a scanned signature page, or a report with a few scanned appendices. Treat those as two jobs.

Also note whether the file is password-protected. The Word conversion cannot open protected files. If the PDF opens without a password but has restrictions on copying or editing, and it is your document or you are entitled to edit it, Unlock PDF removes the restrictions in your browser first.

Choosing the right route

Not every job needs a .docx. If you only want to quote, translate or search the words, a plain text file is faster to work with and has no layout to fight. Use this table to decide.

Digital PDF, you need the words only (quotes, translation, search)PDF to TextA .txt file, each page as one run of text, processed in your browser

For scans, the dependable path into Word is OCR PDF with text output, then paste the text into a new document and apply styles yourself. You can also try converting the searchable-PDF output with PDF to Word, but whether a converter uses an invisible text layer varies, so treat it as something to try rather than something to rely on.

Prepare the PDF before converting

A little preparation removes problems that are tedious to fix afterwards.

  1. Convert only what you need. PDF to Word converts the whole file with no page-range option. If you need pages 12 to 15 of a 90-page report, pull them out with Extract Pages first. A shorter job is quicker and much easier to proofread. It also avoids the time limit: the tool stops waiting for the server after about three minutes, which very long or image-heavy files can exceed.
  2. Fix orientation. Pages scanned sideways or upside down confuse both layout analysis and OCR. Turn them upright with Rotate PDF, and straighten slanted scans with Deskew before running OCR.
  3. Remove what you will delete anyway. Cover pages, blank separators and full-page adverts add conversion time and clutter. Delete them before converting rather than after.
  4. Do not compress first. Compress PDF rebuilds every page as a JPEG image, which removes the text layer. A compressed copy will convert like a scan. Always convert from the original.
  5. Consider where the file goes. PDF to Word uploads the file over HTTPS through PDFora's relay to the conversion service, where it is deleted after processing. PDF to Text and OCR PDF run entirely in your browser. For a document you may not share with a third party, the in-browser routes are the ones to use.

If you are running OCR, it helps to know what resolution the engine sees. Pages are rendered at about 144 dpi, so an A4 page (595 by 842 points, where a point is 1/72 inch) becomes roughly 1190 by 1684 pixels. At that resolution an 8-point footnote has a type size of only about 16 pixels (8 ÷ 72 × 144), and its lowercase letters are much smaller than that, which is why small print produces the most recognition errors. Large, clean body text comes out far better.

Clean up the .docx in Word

Expect to spend a few minutes tidying any converted document. Work in this order, because each step makes the next one easier.

1. Turn on formatting marks

Click the ¶ button on the Home tab (Show/Hide). You will now see paragraph marks, manual line breaks, tabs and section breaks. Most conversion problems become obvious at once: a line break symbol at the end of every line, or a row of tab arrows where a table should be.

2. Rejoin broken lines

If every line ends with a manual line break, use Find and Replace. Search for ^l (the manual line break code, also available under the Special button) and replace it with a single space. Do this one section at a time, not on the whole document, so you do not merge real paragraphs. Then put a paragraph mark back at the end of each genuine paragraph where one is missing.

3. Get text out of text boxes

Text trapped in floating boxes is one of the commonest reasons a converted file falls apart once you start editing. Click the edge of a box, select its contents, cut, click in the body of the document where the text belongs and paste. Then delete the empty box. For a two-column layout, it is usually quicker to move all the text into a single column first and then apply columns from the Layout tab.

4. Apply styles instead of formatting by hand

Converters normally apply direct formatting to every line: a font, a size and spacing that look right but are not tied to anything. Select a heading, choose Heading 1 from the Styles gallery, and repeat for the other levels. If the style does not look like the original, format one heading the way you want, then right-click the style in the gallery and choose Update Heading 1 to Match Selection; every heading with that style changes together. Do the same for body text with the Normal style. Once styles are in place, a table of contents and the Navigation pane work, and future edits keep a consistent look.

5. Sort out section breaks

Converters often insert a section break at every page, sometimes with different margins or orientation in each section. With formatting marks visible you will see them as dotted lines labelled Section Break. Delete the ones you do not need. Be aware that a section break carries that section's page setup, headers and footers, so deleting one can change the layout of the text before it. Keep the breaks where the original genuinely changed, for example a landscape page for a wide table; Word's Layout, Breaks menu offers Next Page and Continuous breaks for those.

6. Rebuild tables that came out wrong

If a table arrived as tab-separated text, select those lines and use Insert, Table, Convert Text to Table with tabs as the separator. If it arrived as one table per row, it is often faster to insert a fresh table and paste the cell contents in than to merge the fragments.

7. Replace substituted fonts

Select all text and set the font you actually want to use, or install the original font if you have a licence for it. Do this before checking page breaks, because the font decides where lines end.

A quick final check

Before you rely on the converted file, put it side by side with the PDF and compare the parts where errors cost the most: numbers, dates, names, amounts in tables and the order of numbered clauses. Converters rarely change words in a digital PDF, but they can drop a footnote, move a caption away from its figure or reorder a sidebar. For OCR text, check every figure against the scan, because 0 and O, 1 and l, and 5 and S are easy for the engine to confuse. Keep the original PDF as the record; the Word file is your working copy.

Frequently asked questions

Why does every line in my converted document end with a break?

The converter treated each stored line of the PDF as its own unit. Replace manual line breaks (^l) with spaces in Word, one section at a time, then restore real paragraph ends.

Will PDF to Word make a scanned page editable?

Not on its own. A scan has no text layer, so it usually arrives as a picture per page. Run OCR PDF first and use the recognised text.

Why do fonts look different in Word than in the PDF?

PDFs usually embed only part of a font for display, and Word cannot use that for editing. If the same font is not installed on your computer, Word substitutes another one.

Is my file uploaded when I convert PDF to Word?

Yes. PDF to Word sends the file over HTTPS through PDFora's relay to a conversion service and it is deleted after processing. PDF to Text and OCR PDF run in your browser instead.

Should I compress a PDF before converting it to Word?

No. PDFora's Compress PDF rebuilds pages as images, so the compressed copy has no text layer and converts like a scan. Convert from the original file.
