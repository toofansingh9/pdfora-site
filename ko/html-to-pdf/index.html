HTML을 PDF로

저장해 둔 HTML 파일을 변환 서버에서 PDF로 바꿔, 웹 페이지나 HTML 내보내기 결과를 고정된 인쇄용 페이지로 만듭니다.

🔒 파일은 브라우저 안에서 로컬로 처리되며 절대 업로드되지 않습니다.

3

다운로드

완성된 파일을 즉시 저장하세요. 워터마크가 없습니다.

쓸모 있는 문서 중에는 HTML로만 존재하는 것이 꽤 많습니다. 브라우저에서 저장한 주문 확인서, 앱이 내보낸 보고서, 뉴스레터, 한 페이지로 생성된 설명서, 직접 만든 페이지 등이죠. HTML은 창 크기에 맞춰 내용이 다시 배치되는데, 문서를 보관하거나 인쇄하거나 청구 서류에 첨부해야 할 때는 바로 그 점이 문제가 됩니다. PDF는 문서를 한 가지 페이지 크기로 고정해 줍니다.

이 도구는 웹 주소가 아니라 내 컴퓨터에 있는 .html 또는 .htm 파일을 받습니다. 파일은 PDFora의 중계 서버를 거쳐 암호화된 상태로 CloudConvert 서비스에 업로드되고, 그곳의 렌더링 엔진이 페이지를 배치해 PDF로 출력합니다. 결과물은 원래 파일 이름으로 돌아오며, 서비스에 있던 파일은 이후 삭제됩니다. 변환은 브라우저 안에서 이루어지지 않으며, 페이지 크기나 여백 설정은 도구 화면에 없습니다.

대부분이 가장 놀라는 부분은 HTML 파일이 참조하는 다른 파일들입니다. 웹 페이지는 파일 하나로 끝나는 경우가 드물고, 이미지·스타일시트·글꼴은 보통 HTML에서 참조하는 별도 파일입니다. 업로드되는 건 선택한 파일 하나뿐이라, 내 디스크의 상대 경로로 참조된 것은 서버가 찾을 수 없습니다. 그래서 원본에 충실한 PDF를 얻는 핵심은 변환 전에 HTML 파일을 그 자체로 완결되게 만드는 것입니다.

HTML을 PDF로 변환하는 방법

  1. HTML 파일이 그 자체로 완결되어 있는지, 또는 이미지와 스타일시트에 전체 웹 주소(https://...)를 쓰는지 확인합니다. 아래 설명을 참고하세요.
  2. HTML을 PDF로 도구를 열고 .html 또는 .htm 파일을 선택합니다.
  3. 변환 버튼을 누르고 파일이 업로드되어 서버에서 렌더링되는 동안 기다립니다.
  4. PDF를 다운로드합니다. 파일 이름은 그대로이고 확장자만 .pdf로 바뀝니다.
  5. 이미지, 색상, 레이아웃이 제대로 나왔는지, 오른쪽 끝에서 잘린 내용은 없는지 확인합니다.

이 도구가 필요한 경우

  • 브라우저에서 저장한 영수증이나 예약 확인서를 회계 자료나 증빙으로 PDF로 보관할 때.
  • 소프트웨어가 HTML로 내보낸 보고서를 메일에 첨부하거나 보관해야 할 때.
  • 개발자가 생성한 HTML 청구서, 수료증, 안내문 템플릿을 PDF로 만들어 인쇄 레이아웃을 점검할 때.
  • 긴 HTML 페이지 하나로 공개된 설명서나 사용자 가이드를 오프라인에서 읽으려고 인쇄할 때.
  • 자료 조사용으로 저장한 웹 기사를 사이트가 바뀌어도 변하지 않는 형식으로 보관할 때.
  • HTML로 저장한 이메일 뉴스레터를 발송 기록으로 남길 때.

시작하기 전에 알아둘 점

  • 상대 경로 링크는 깨집니다. HTML에 <img src="images/logo.png">나 <link href="style.css">라고 되어 있으면 그 파일은 내 컴퓨터에 남아 있어 서버가 볼 수 없습니다. 그러면 PDF에 이미지가 빠지고 스타일 없는 텍스트만 나옵니다. 절대 주소 https://를 쓰거나, CSS는 <style> 블록에, 이미지는 data URI로 넣으세요.
  • 절대 웹 주소로 된 리소스는 서버가 렌더링할 때 가져올 수 있으므로, 공개적으로 접근 가능한 이미지와 스타일시트는 보통 나타납니다. 로그인이 필요한 곳, 사내망, localhost에 있는 것은 나타나지 않습니다.
  • URL 입력란은 없습니다. 실제 웹 페이지를 변환하려면 먼저 저장하세요. 브라우저의 '다른 이름으로 저장 > 웹 페이지, 단일 파일(.mhtml)'은 받지 않으니 '웹 페이지, HTML만'으로 저장하고 상대 경로 이미지는 빠질 수 있다고 생각하세요. 아니면 브라우저의 인쇄 > PDF로 저장을 쓰세요.
  • 인쇄용 스타일이 적용됩니다. 페이지에 @media print용 CSS가 있으면 변환기가 대개 그것을 사용하므로, 화면에서 보던 것과 달리 내비게이션 바가 숨겨지거나 색이 바뀔 수 있습니다. 페이지 나눔은 CSS의 break-before와 break-inside로 조절할 수 있습니다.
  • JavaScript로 만들어지는 내용은 믿기 어렵습니다. 로드된 뒤 스크립트로 내용을 불러오는 페이지는 빈 껍데기로 변환될 수 있습니다. 페이지가 완전히 로드된 뒤 저장하거나, 서버 쪽에서 내용을 HTML에 미리 렌더링하세요.
  • 고정 1400픽셀 디자인이나 넓은 표처럼 인쇄 페이지보다 넓은 레이아웃은 잘리거나 축소될 수 있습니다. 반응형 레이아웃이나 본문에 max-width를 주면 대개 해결됩니다.

더 좋은 결과를 위한 팁

  • 직접 만든 템플릿이라면 모든 CSS를 <head> 안의 <style> 블록에 넣으세요. 스타일이 적용된 PDF를 얻는 가장 확실한 방법입니다.
  • 특정 페이지 크기나 여백이 필요하면 CSS에 @page { size: A4; margin: 15mm; }를 추가하세요.
  • 표의 행, 카드, 그림에는 break-inside: avoid를 지정해 두 페이지에 걸쳐 잘리지 않게 하세요.
  • 이미지 크기를 적당히 유지하세요. 5 MB짜리 대표 이미지를 data URI로 넣으면 PDF도 5 MB가 됩니다.
  • 먼저 브라우저의 인쇄 미리보기로 HTML 파일을 열어 보세요. 거기서 이상하게 보이면 변환된 PDF도 아마 이상하게 나옵니다.

실제 예시: 작은 온라인 쇼핑몰의 HTML 거래명세서 템플릿

두 사람이 운영하는 온라인 쇼핑몰이 간단한 스크립트로 거래명세서를 HTML 파일로 만들고 있습니다. 각 파일은 같은 폴더의 invoice.css와 logo.png를 참조합니다. 그대로 변환하면 PDF는 기본 글꼴의 검은 텍스트뿐이고, 로고는 없으며, 합계 표가 전체 너비로 늘어납니다. 서버가 스타일시트와 이미지 없이 HTML 파일만 받았기 때문입니다.

해결책은 파일을 단독으로 완결되게 만드는 것입니다. 이제 스크립트는 invoice.css 내용을 <style> 블록에 복사하고, @page { size: A4; margin: 18mm; }와 품목 표의 행에 break-inside: avoid를 추가하며, 로고는 로컬 경로 대신 쇼핑몰 웹사이트의 공개 https 주소를 가리키게 합니다. 그 외에는 바꾼 것이 없습니다.

다시 변환하자 로고와 쇼핑몰 색상이 들어간 A4 한 장짜리 PDF가 나오고, 주문 품목이 많아도 합계 표가 잘리지 않습니다. 템플릿이 이제 그 자체로 완결되어 있으니 스크립트가 만드는 모든 명세서가 똑같이 변환됩니다.

문제 해결

PDF에 스타일 없이 텍스트만 나와요
스타일시트가 상대 경로로 참조되어 업로드되지 않았습니다. CSS를 <style> 블록에 넣거나 전체 https:// 주소로 연결하세요.
이미지가 빠져 있어요
상대 경로로 참조된 내 디스크의 이미지에는 접근할 수 없습니다. 공개 https:// URL을 쓰거나 이미지를 data URI로 넣은 뒤 다시 변환하세요.
페이지 오른쪽이 잘려요
레이아웃 고정 너비가 페이지보다 큽니다. 주요 컨테이너와 이미지에 max-width: 100%를 주거나, 레이아웃을 좁히는 인쇄용 스타일시트를 추가하세요.
PDF가 비어 있거나 거의 비어 있어요
내용이 로드 후 JavaScript로 만들어지거나, 파일이 리디렉션일 가능성이 큽니다. 페이지가 완전히 렌더링된 뒤 저장하거나 HTML 자체에 내용을 넣으세요.
글꼴이 다르게 나와요
로컬로 참조된 웹 글꼴을 쓸 수 없었습니다. 공개 URL로 글꼴을 연결하거나, @font-face와 data URI로 넣거나, 흔한 글꼴 조합을 쓰세요.
도구가 파일을 받지 않아요
.html과 .htm만 받습니다. .mhtml이나 .webarchive로 저장한 파일은 'HTML만'으로 다시 저장해야 합니다.

자주 묻는 질문

URL을 입력해서 웹사이트를 변환할 수 있나요?

아니요. 이 도구는 선택한 HTML 파일을 변환합니다. 먼저 페이지를 HTML로 저장하거나, 실제 페이지는 브라우저의 인쇄 > PDF로 저장을 쓰세요.

HTML 파일이 업로드되나요?

네. 암호화되어 변환 서비스로 전송되고, 그곳에서 렌더링된 뒤 삭제됩니다. 제3자가 처리하길 원치 않는 개인정보가 담긴 페이지는 변환하지 마세요.

이미지와 CSS가 왜 빠지나요?

HTML 파일 하나만 업로드되기 때문입니다. 상대 경로로 참조된 파일은 내 컴퓨터에 남으니, 절대 https:// 링크를 쓰거나 HTML 안에 넣으세요.

페이지 크기나 여백을 정할 수 있나요?

도구 화면에서는 안 됩니다. HTML에서 CSS @page 규칙으로 정하세요. 예: @page { size: A4; margin: 15mm; }

PDF에서 링크를 클릭할 수 있나요?

웹 주소로 가는 링크는 보통 그대로 클릭됩니다. 다른 로컬 파일로 가는 상대 경로 링크는 쓸모 있는 곳으로 연결되지 않습니다.

변환할 때 JavaScript가 실행되나요?

일부 실행될 수는 있지만, 늦게 로드되거나 사용자 조작이 필요한 내용은 빠지는 경우가 많습니다. 안정적인 결과를 원한다면 HTML에 최종 내용이 이미 들어 있어야 합니다.
