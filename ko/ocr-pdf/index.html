OCR PDF

스캔하거나 사진으로 찍은 PDF에서 광학 문자 인식(OCR)으로 텍스트를 읽어 내 일반 텍스트 파일로 다운로드합니다.

다운로드

완성된 파일을 즉시 저장하세요. 워터마크가 없습니다.

스캔한 PDF는 문서처럼 보이지만 실제로는 사진첩처럼 동작합니다. 각 페이지가 글자를 찍은 그림일 뿐이라 검색도, 문단 복사도, 숫자를 스프레드시트에 붙여 넣는 것도 안 됩니다. 광학 문자 인식(OCR)은 그 그림을 보고 어떤 글자인지 알아냅니다. PDFora의 OCR 도구는 PDF의 모든 페이지에 그 작업을 하고, 인식한 텍스트를 검색·편집·재사용할 수 있는 .txt 파일로 돌려줍니다.

결과물이 무엇인지 분명히 해 두겠습니다. 현재 도구는 검색 가능한 PDF가 아니라 일반 텍스트를 만듭니다. 각 페이지를 약 144 ppi로 렌더링해 Tesseract.js(브라우저에서 돌아가도록 컴파일된 오픈 소스 OCR 엔진)에 넘기고, 읽어 낸 텍스트를 페이지 순서대로 파일에 쓰며 페이지 사이에는 빈 줄을 넣습니다. 레이아웃은 없습니다. 다단 구성, 표, 글꼴은 재구성되지 않습니다. 페이지 이미지 뒤에 보이지 않는 텍스트를 까는 검색 가능한 PDF 출력은 계획 중이지만 아직은 제공되지 않습니다. 결과는 약간 다듬어야 한다고 생각하세요. 줄 끝 하이픈은 그대로 남고, 머리글이나 쪽 번호도 일반 텍스트 줄로 읽힙니다.

인식은 내 기기에서 실행됩니다. 처음 실행할 때 공개 CDN에서 Tesseract 엔진과 언어 데이터를 내려받는데, 연결이 느리면 시간이 걸릴 수 있습니다. PDF 자체는 이 다운로드와 무관하며 어디로도 전송되지 않습니다.

스캔한 PDF에서 텍스트를 추출하는 방법

  1. OCR 도구를 열고 PDF 한 개를 추가합니다. 스캔본, PDF로 저장한 휴대폰 사진, 이미지로만 된 내보내기 파일 모두 됩니다.
  2. 문서 언어를 고릅니다: 영어, 힌디어, 스페인어, 프랑스어 중 하나입니다. 기본값은 영어입니다.
  3. OCR 실행을 누릅니다. 상태 줄에 지금 읽고 있는 페이지가 표시되며, 페이지당 몇 초씩, 휴대폰에서는 더 오래 걸립니다.
  4. 원래 이름에 -ocr.txt가 붙은 결과 파일(예: lease-ocr.txt)을 다운로드합니다.
  5. 텍스트 파일을 열어 이름, 숫자, 금액을 스캔본과 대조해 확인한 뒤에 사용하세요.

이 도구가 필요한 경우

  • 스캔한 영문 계약서의 조항을 다시 타이핑하지 않고 회신 메일에 복사할 때.
  • 인쇄된 영문 회의록이나 NGO 현장 보고서를 소식지나 데이터베이스용 편집 가능한 텍스트로 바꿀 때.
  • 복사본으로 받은 원서 챕터나 해외 논문에서 학습 노트용 인용문을 뽑을 때. 페이지 구분도 유지됩니다.
  • 스캔한 영문 서신 묶음에서 주소와 참조 번호를 추출해 나중에 검색할 때.
  • 힌디어나 스페인어 문서를 텍스트로 읽어 번역기에 붙여 넣을 때.
  • PDF에 이미 텍스트 레이어가 있는지 확인할 때: PDF를 텍스트로 도구에서는 아무것도 안 나오는데 OCR에서는 텍스트가 나오면 순수 스캔 파일입니다.

시작하기 전에 알아둘 점

  • 결과는 일반 .txt 파일입니다. 엔진이 본 읽기 순서대로 글자만 담기며 서식, 이미지, 페이지 레이아웃은 없습니다.
  • 언어는 영어, 힌디어, 스페인어, 프랑스어 네 가지입니다. 한국어를 포함해 그 밖의 언어로 된 문서는 맞지 않는 문자 모델로 읽혀 결과가 좋지 않습니다.
  • 정확도는 대부분 스캔 상태에 달려 있습니다. 깨끗하고 반듯하며 대비가 뚜렷한 인쇄 페이지는 대개 잘 나오지만, 손글씨, 흐린 복사본, 글자 위에 찍힌 도장, 기울어진 휴대폰 사진은 오류가 많습니다.
  • 표와 다단 레이아웃은 텍스트 줄로 읽힙니다. 단이 서로 섞일 수 있고, 표 칸은 격자 구조를 잃습니다.
  • 인식 전에 페이지를 약 144 ppi로 렌더링합니다. 8 pt 미만의 각주처럼 아주 작은 글씨는 그 해상도에서 엔진이 안정적으로 읽기 어려울 수 있습니다.
  • 이미 실제 텍스트가 있는 페이지까지 모든 페이지를 OCR합니다. 섞인 문서라면 디지털 페이지는 PDF를 텍스트로 도구가 더 빠르고 정확합니다.

더 좋은 결과를 위한 팁

  • 스캐너를 직접 다룰 수 있다면 300 dpi 흑백이나 회색조로 스캔하세요. 도구의 어떤 설정보다 인식에 더 도움이 됩니다.
  • 옆으로 누운 페이지는 PDF 회전 도구로 먼저 바로 세우세요. 엔진은 똑바로 선 페이지에서 왼쪽에서 오른쪽으로 흐르는 글자를 기대합니다.
  • 긴 문서라면 분할해서 필요한 페이지만 OCR하세요. 인식 시간은 페이지 수만큼 늘어납니다.
  • 숫자는 꼼꼼히 확인하세요. 0과 O, 1과 l, 5와 S의 혼동은 가장 흔한 OCR 오류이고, 청구서나 신분 번호에서는 가장 비싼 실수가 됩니다.
  • 원본 스캔본을 텍스트 파일과 함께 보관하세요. 텍스트는 작업용 사본이고, 스캔본이 기록입니다.

실제 예시: 복사본 강의 자료를 받은 대학원생

사학과 대학원생 정하윤 씨는 학과에서 복사본을 스캔해 만든 22페이지짜리 영문 강독 자료를 받았습니다. 리포트에 쓸 인용문이 열두 개쯤 필요하고, 특정 조약이 언급된 곳을 다시 훑어 읽는 대신 검색으로 찾고 싶습니다.

영어를 선택해 PDF를 OCR에 돌리니 노트북에서 몇 분이 걸립니다. 결과 텍스트 파일은 바로 검색할 수 있고, 페이지 사이의 빈 줄 덕분에 각 인용문이 몇 페이지에서 나왔는지 알아내 출처를 표기할 수 있습니다. 비스듬히 복사된 두 페이지는 줄이 엉망으로 나와서, 도서관에서 그 두 장을 바로 세워 다시 스캔하고 따로 OCR해 깨끗한 텍스트를 붙여 넣습니다.

인용문 하나가 잘못 읽힌 단어 때문에 틀리면 안 쓰느니만 못하니, 사용하는 인용문은 모두 스캔본과 대조합니다. 그 과정에서 엔진이 1648을 1043으로 읽은 연도 하나를 고칩니다.

참고문헌 목록을 만들 때도 이 텍스트 파일을 씁니다. 각 장 표지의 서지 정보는 보통 크고 간격 넓은 글씨로 인쇄되어 깨끗하게 나오기 때문입니다. 오류가 가장 많이 몰리는 곳은 작은 각주라서, 각주는 인식된 텍스트를 믿지 않고 스캔본에서 직접 읽습니다.

문제 해결

텍스트 파일이 비어 있거나 거의 비어 있어요
페이지의 대비가 매우 낮거나, 글씨가 아주 작거나, 빈 페이지일 수 있습니다. PDF를 열고 확대해 보세요. 사람이 읽기 힘들면 엔진도 마찬가지입니다. 가능하면 대비를 높여 다시 스캔하세요.
결과가 이상한 문자로 가득해요
언어 설정이 문서와 맞는지 확인하세요. 페이지가 똑바로 서 있는지도 확인하세요. 옆으로 눕거나 뒤집힌 페이지는 엉터리 결과를 냅니다. 먼저 회전하세요.
시작할 때 도구가 멈춰 있어요
처음 실행할 때 OCR 엔진과 언어 데이터를 내려받습니다. 느리거나 필터링된 네트워크, 스크립트 차단기가 있으면 멈출 수 있습니다. cdn.jsdelivr.net을 허용하고 다시 시도하세요.
단이 서로 섞여요
다단 페이지는 경우에 따라 페이지를 가로지르는 줄로 읽힙니다. PDF 자르기 도구로 각 단을 별도 페이지로 잘라 내거나, 필요한 부분만 복사해 손으로 정리하세요.
휴대폰에서 너무 느려요
OCR은 부담이 큰 작업이고, 각 페이지가 기기 프로세서에서 인식됩니다. 긴 문서는 데스크톱을 쓰거나, 분할한 뒤 필요한 페이지만 OCR하세요.
텍스트가 아니라 검색 가능한 PDF를 원했어요
검색 가능한 PDF 출력은 아직 제공되지 않습니다. 당분간은 텍스트 파일로 검색과 복사를 하고, 스캔본은 원본 기록으로 보관하세요.

자주 묻는 질문

이 도구로 PDF를 검색 가능하게 만들 수 있나요?

아직은 아닙니다. 인식한 텍스트를 .txt 파일로 출력합니다. 검색 가능한 PDF 출력은 계획 중입니다.

어떤 언어를 지원하나요?

영어, 힌디어, 스페인어, 프랑스어입니다. OCR을 실행하기 전에 문서에 맞는 언어를 고르세요.

손글씨도 읽을 수 있나요?

잘 못 읽습니다. 엔진은 인쇄된 글자로 학습되어 있어서, 또박또박 쓴 대문자는 가끔 되지만 필기체는 대개 안 됩니다.

인식을 위해 문서가 업로드되나요?

아니요. 엔진이 브라우저로 다운로드되어 그 안에서 인식이 실행됩니다. CDN에서 가져오는 건 엔진과 언어 파일뿐입니다.

페이지마다 왜 몇 초씩 걸리나요?

각 페이지를 이미지로 렌더링하고 내 프로세서에서 글자 모양을 분석하기 때문입니다. 이미 있는 텍스트를 읽는 것보다 훨씬 무거운 작업입니다.

표와 서식이 유지되나요?

아니요. 결과는 읽기 순서대로 된 일반 텍스트입니다. 표 구조, 글꼴, 이미지는 재현되지 않습니다.
