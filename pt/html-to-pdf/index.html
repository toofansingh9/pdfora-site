HTML para PDF

Converta um arquivo HTML salvo em PDF por meio de um servidor de conversão, transformando uma página da web ou uma exportação HTML em páginas fixas e prontas para imprimir.

🔒 Seus arquivos são processados localmente no seu navegador e nunca são enviados.

Salve o arquivo pronto na hora. Sem marcas d'água.

Sabe aquele comprovante de passagem que você salvou com Ctrl+S, ou o extrato que o sistema da empresa exporta como página da web? Abra o mesmo arquivo num notebook e depois no celular e o texto se rearruma todo, porque o HTML foi feito para se ajustar à tela. Para guardar, imprimir ou anexar a uma reclamação, isso atrapalha. No PDF o conteúdo fica preso a um tamanho de página e não muda mais.

Um detalhe importante antes de começar: o HTML para PDF não aceita endereço de site, só um arquivo .html ou .htm que esteja no seu computador. Esse arquivo segue criptografado, pelo intermediário do PDFora, até o serviço CloudConvert. Lá um mecanismo de renderização monta a página e a imprime em PDF, que volta com o mesmo nome do seu arquivo e depois é apagado do serviço. Ou seja, nada é convertido dentro do seu navegador, e a página da ferramenta não oferece ajuste de tamanho de folha nem de margens.

O erro mais comum é esquecer que uma página da web quase nunca é um arquivo só. Imagens, folhas de estilo e fontes costumam morar em arquivos separados, chamados de dentro do HTML. Como só o arquivo escolhido é enviado, o servidor não acha nada que esteja apontado por um caminho relativo no seu disco, e o PDF sai pelado. Por isso, o segredo de um resultado fiel é deixar o HTML autossuficiente antes de converter.

Como converter HTML em PDF

  1. Confira se o arquivo HTML é autossuficiente ou usa endereços completos (https://...) para imagens e folhas de estilo; veja as observações abaixo.
  2. Abra HTML para PDF e escolha o arquivo .html ou .htm.
  3. Clique em Converter e espere enquanto o arquivo é enviado e renderizado no servidor.
  4. Baixe o PDF, que mantém o nome do seu arquivo com a extensão .pdf.
  5. Verifique se as imagens, as cores e o layout vieram certos e se nenhum conteúdo ficou cortado na margem direita.

Quando usar esta ferramenta

  • Comprovantes de compra, de Pix agendado ou de reserva salvos do navegador, guardados em PDF para o controle de gastos ou para o Imposto de Renda.
  • Boletins e relatórios que o portal da escola ou da faculdade só mostra como página da web, convertidos para anexar a um pedido de bolsa ou transferência.
  • Relatórios exportados em HTML por um sistema de gestão que precisam seguir por e-mail para o contador ou ir para o arquivo.
  • Desenvolvedores e freelancers que testam como um modelo HTML de orçamento, recibo ou certificado fica na hora de imprimir.
  • Manuais e documentações publicados numa página única e comprida, impressos para consultar sem internet.
  • Artigos e newsletters salvos em HTML para pesquisa ou como registro do que foi publicado, num formato que não muda se o site mudar.

O que saber antes de começar

  • Caminhos relativos param de funcionar. Se o HTML tiver <img src="images/logo.png"> ou <link href="style.css">, esses arquivos ficam no seu computador e o servidor não os enxerga. O PDF sai então sem imagens e com texto sem estilo. Use endereços absolutos https://, ou coloque o CSS num bloco <style> e as imagens como data URIs.
  • Recursos com endereço web absoluto podem ser buscados pelo servidor durante a renderização, então imagens e folhas de estilo acessíveis publicamente costumam aparecer. O que estiver atrás de login, numa intranet ou em localhost não aparece.
  • Não existe campo para URL. Para converter uma página on-line, salve-a primeiro. A opção do navegador Salvar página como > Página da web, arquivo único (.mhtml) não é aceita; use Página da web, somente HTML e conte com a falta das imagens relativas, ou use o Imprimir > Salvar como PDF do próprio navegador.
  • Os estilos de impressão são aplicados. Se a página tiver CSS para @media print, o conversor normalmente usa esse CSS, o que pode esconder menus ou mudar cores em relação ao que você vê na tela. As quebras de página são controladas com break-before e break-inside no CSS.
  • Conteúdo gerado por JavaScript não é confiável. Páginas que buscam o conteúdo com scripts depois de carregar podem ser convertidas como uma estrutura vazia. Salve a página depois que ela carregar por completo, ou gere o conteúdo no HTML do lado do servidor.
  • Layouts mais largos que uma folha impressa, como designs fixos de 1400 pixels ou tabelas largas, podem ficar cortados ou reduzidos. Um layout responsivo ou um max-width no conteúdo principal costuma resolver.

Dicas para obter os melhores resultados

  • Nos seus próprios modelos, coloque todo o CSS num bloco <style> dentro do <head>; é o jeito mais seguro de ter um PDF com estilo.
  • Adicione @page { size: A4; margin: 15mm; } ao CSS se precisar de um tamanho de página ou de margens específicas.
  • Use break-inside: avoid em linhas de tabela, cards e figuras para que não fiquem divididos entre duas páginas.
  • Mantenha as imagens num tamanho razoável: uma imagem de 5 MB embutida como data URI continua gerando um PDF de 5 MB.
  • Abra o HTML primeiro na visualização de impressão do navegador; se lá estiver ruim, o PDF convertido provavelmente também vai estar.

Exemplo prático: o certificado de um curso on-line feito em HTML

A Juliana, de Recife, organiza cursos livres de fotografia pela internet e gera os certificados dos alunos com um pequeno script que preenche um modelo HTML. O modelo chama certificado.css e assinatura.png, guardados na mesma pasta. Na primeira tentativa, o PDF chegou com o nome do aluno em fonte padrão, sem a moldura colorida, sem a assinatura e com o texto espalhado de ponta a ponta, já que o servidor recebeu só o HTML, sem o CSS e sem a imagem.

Para resolver, ela mudou o script para colar o conteúdo de certificado.css num bloco <style> no <head>, acrescentou @page { size: A4 landscape; margin: 12mm; } e break-inside: avoid no quadro central, e trocou o caminho local da assinatura pela imagem convertida em data URI. O texto do certificado continuou igual.

Na nova conversão, cada certificado virou um PDF A4 deitado, de uma página só, com a moldura, as cores da escola e a assinatura no lugar. Como o modelo agora não depende de nenhum arquivo externo, os 37 certificados da última turma saíram iguais, prontos para mandar por e-mail.

Solução de problemas

O PDF está sem estilo, só texto simples
A folha de estilo estava indicada por um caminho relativo e não foi enviada. Coloque o CSS num bloco <style> ou aponte para ele com um endereço https:// completo.
Estão faltando imagens
As imagens do seu disco indicadas por caminhos relativos não estão acessíveis. Use URLs https:// públicas ou embuta as imagens como data URIs e converta de novo.
A página aparece cortada à direita
O layout tem uma largura fixa maior que a página. Adicione max-width: 100% aos contêineres principais e às imagens, ou uma folha de estilo de impressão que estreite o layout.
O PDF está em branco ou quase
O conteúdo provavelmente é gerado por JavaScript depois que a página carrega, ou o arquivo é só um redirecionamento. Salve a página depois que ela estiver totalmente exibida, ou coloque o conteúdo no próprio HTML.
O texto aparece em outra fonte
As fontes web indicadas localmente não estavam disponíveis. Aponte a fonte para uma URL pública, embuta-a com @font-face e um data URI, ou use uma pilha de fontes comuns.
A ferramenta não aceita o meu arquivo
Só .html e .htm são aceitos. Arquivos .mhtml ou .webarchive precisam ser salvos de novo como somente HTML.

Perguntas frequentes

Dá para colar o link de um site e gerar o PDF?

Não dá. A ferramenta trabalha com um arquivo HTML que você escolhe no computador. Salve a página como HTML antes ou, se ela estiver no ar, use o Imprimir > Salvar como PDF do próprio navegador.

Meu arquivo HTML sai do meu computador?

Sai, sim. Ele vai criptografado para o serviço de conversão, é renderizado lá e depois apagado. Se a página tiver dados pessoais que você não quer ver processados por terceiros, é melhor não converter por aqui.

Por que o PDF saiu sem imagens e sem formatação?

Porque só o arquivo HTML em si é enviado. O que ele chama por caminho relativo continua no seu computador; troque por links https:// completos ou embuta esses arquivos no próprio HTML.

Tem como escolher o tamanho da folha ou as margens?

Na página da ferramenta, não. Isso se define dentro do HTML com uma regra CSS @page, por exemplo @page { size: A4; margin: 15mm; }.

Os links continuam funcionando no PDF?

Os que apontam para endereços da web normalmente continuam clicáveis. Já os links relativos para outros arquivos do seu computador não levam a lugar nenhum.

E se a página usa JavaScript, ele roda na conversão?

Pode rodar em parte, mas o conteúdo que carrega depois ou que depende de clique costuma ficar de fora. Para não ter surpresa, o HTML já deve trazer o conteúdo final escrito nele.
