HTML para PDF

Converta um arquivo HTML salvo em PDF por meio de um servidor de conversão, transformando uma página da web ou uma exportação HTML em páginas fixas e prontas para imprimir.

Muitos documentos úteis só existem em HTML: a confirmação de um pedido salva pelo navegador, um relatório exportado por um aplicativo, uma newsletter, uma documentação gerada numa página só ou uma página que você mesmo fez. O HTML se adapta ao tamanho da janela em que é aberto, e é justamente isso que você não quer quando o documento precisa ser arquivado, impresso ou anexado a uma reclamação. Um PDF trava o conteúdo num tamanho de página.

Esta ferramenta recebe um arquivo .html ou .htm do seu computador, não um endereço da web. O arquivo é enviado, criptografado, para o serviço CloudConvert por meio do intermediário do PDFora, onde um mecanismo de renderização monta a página e a imprime em PDF; o resultado volta com o nome do seu arquivo e depois é apagado do serviço. A conversão não acontece no seu navegador, e a página da ferramenta não tem configurações de tamanho de página nem de margens.

O que mais surpreende a maioria das pessoas é o que acontece com tudo aquilo para onde o HTML aponta. Uma página da web quase nunca é um arquivo só: imagens, folhas de estilo e fontes costumam ser arquivos separados, referenciados no HTML. Só o arquivo que você escolher é enviado, então o servidor não encontra nada que esteja indicado por um caminho relativo no seu disco. Conseguir um PDF fiel depende principalmente de deixar o HTML autossuficiente antes de converter.

Como converter HTML em PDF

  1. Confira se o arquivo HTML é autossuficiente ou usa endereços completos (https://...) para imagens e folhas de estilo; veja as observações abaixo.
  2. Abra HTML para PDF e escolha o arquivo .html ou .htm.
  3. Clique em Converter e espere enquanto o arquivo é enviado e renderizado no servidor.
  4. Baixe o PDF, que mantém o nome do seu arquivo com a extensão .pdf.
  5. Verifique se as imagens, as cores e o layout vieram certos e se nenhum conteúdo ficou cortado na margem direita.

Quando usar esta ferramenta

  • Recibos e confirmações de reserva salvos pelo navegador, guardados em PDF para a contabilidade ou como comprovante.
  • Relatórios que um sistema exporta em HTML e que precisam ser anexados a um e-mail ou arquivados.
  • Desenvolvedores que transformam um modelo HTML de nota, certificado ou carta em PDF para ver como fica impresso.
  • Documentação ou manual publicado como uma única página HTML comprida, impresso para ler sem internet.
  • Artigos da web salvos para pesquisa num formato que não muda se o site mudar.
  • Newsletters salvas em HTML e convertidas para ter um registro do que foi enviado.

O que saber antes de começar

  • Caminhos relativos param de funcionar. Se o HTML tiver <img src="images/logo.png"> ou <link href="style.css">, esses arquivos ficam no seu computador e o servidor não os enxerga. O PDF sai então sem imagens e com texto sem estilo. Use endereços absolutos https://, ou coloque o CSS num bloco <style> e as imagens como data URIs.
  • Recursos com endereço web absoluto podem ser buscados pelo servidor durante a renderização, então imagens e folhas de estilo acessíveis publicamente costumam aparecer. O que estiver atrás de login, numa intranet ou em localhost não aparece.
  • Não existe campo para URL. Para converter uma página on-line, salve-a primeiro. A opção do navegador Salvar página como > Página da web, arquivo único (.mhtml) não é aceita; use Página da web, somente HTML e conte com a falta das imagens relativas, ou use o Imprimir > Salvar como PDF do próprio navegador.
  • Os estilos de impressão são aplicados. Se a página tiver CSS para @media print, o conversor normalmente usa esse CSS, o que pode esconder menus ou mudar cores em relação ao que você vê na tela. As quebras de página são controladas com break-before e break-inside no CSS.
  • Conteúdo gerado por JavaScript não é confiável. Páginas que buscam o conteúdo com scripts depois de carregar podem ser convertidas como uma estrutura vazia. Salve a página depois que ela carregar por completo, ou gere o conteúdo no HTML do lado do servidor.
  • Layouts mais largos que uma folha impressa, como designs fixos de 1400 pixels ou tabelas largas, podem ficar cortados ou reduzidos. Um layout responsivo ou um max-width no conteúdo principal costuma resolver.

Dicas para obter os melhores resultados

  • Nos seus próprios modelos, coloque todo o CSS num bloco <style> dentro do <head>; é o jeito mais seguro de ter um PDF com estilo.
  • Adicione @page { size: A4; margin: 15mm; } ao CSS se precisar de um tamanho de página ou de margens específicas.
  • Use break-inside: avoid em linhas de tabela, cards e figuras para que não fiquem divididos entre duas páginas.
  • Mantenha as imagens num tamanho razoável: uma imagem de 5 MB embutida como data URI continua gerando um PDF de 5 MB.
  • Abra o HTML primeiro na visualização de impressão do navegador; se lá estiver ruim, o PDF convertido provavelmente também vai estar.

Exemplo prático: o modelo de nota em HTML de uma pequena loja

Uma loja virtual de duas pessoas, em Belo Horizonte, gera as notas de pedido como arquivos HTML com um script simples. Cada arquivo aponta para invoice.css e logo.png na mesma pasta. Convertido direto, o PDF sai em texto preto simples, com a fonte padrão, sem logotipo e com a tabela de totais esticada na largura toda, porque o servidor recebeu o HTML sem a folha de estilo e sem a imagem.

A solução é deixar o arquivo independente. O script passa a copiar o conteúdo de invoice.css para um bloco <style>, adiciona @page { size: A4; margin: 18mm; } e break-inside: avoid nas linhas da tabela de itens, e aponta o logotipo para o endereço https público no site da loja em vez de um caminho local. Nada mais muda.

Convertida de novo, a nota vira um PDF A4 de uma página, com logotipo, as cores da loja e uma tabela de totais que não se quebra mais quando o pedido tem muitas linhas. Como o modelo agora é autossuficiente, todas as notas que o script gera são convertidas do mesmo jeito.

Solução de problemas

O PDF está sem estilo, só texto simples
A folha de estilo estava indicada por um caminho relativo e não foi enviada. Coloque o CSS num bloco <style> ou aponte para ele com um endereço https:// completo.
Estão faltando imagens
As imagens do seu disco indicadas por caminhos relativos não estão acessíveis. Use URLs https:// públicas ou embuta as imagens como data URIs e converta de novo.
A página aparece cortada à direita
O layout tem uma largura fixa maior que a página. Adicione max-width: 100% aos contêineres principais e às imagens, ou uma folha de estilo de impressão que estreite o layout.
O PDF está em branco ou quase
O conteúdo provavelmente é gerado por JavaScript depois que a página carrega, ou o arquivo é só um redirecionamento. Salve a página depois que ela estiver totalmente exibida, ou coloque o conteúdo no próprio HTML.
O texto aparece em outra fonte
As fontes web indicadas localmente não estavam disponíveis. Aponte a fonte para uma URL pública, embuta-a com @font-face e um data URI, ou use uma pilha de fontes comuns.
A ferramenta não aceita o meu arquivo
Só .html e .htm são aceitos. Arquivos .mhtml ou .webarchive precisam ser salvos de novo como somente HTML.

Perguntas frequentes

Posso converter um site digitando a URL?

Não. A ferramenta converte um arquivo HTML que você escolher. Salve a página como HTML primeiro, ou use Imprimir > Salvar como PDF no navegador para uma página on-line.

O arquivo HTML é enviado para algum lugar?

Sim. Ele é enviado criptografado para o serviço de conversão, renderizado lá e apagado depois. Evite converter páginas com dados pessoais que você não queira ver processados por terceiros.

Por que as imagens e o CSS estão faltando?

Só o próprio arquivo HTML é enviado. Os arquivos referenciados por caminhos relativos ficam no seu computador; use links https:// absolutos ou embuta-os no HTML.

Posso definir o tamanho da página ou as margens?

Não na página da ferramenta. Defina no HTML com uma regra CSS @page, por exemplo @page { size: A4; margin: 15mm; }.

Os links continuam clicáveis no PDF?

Links para endereços da web normalmente continuam clicáveis. Links relativos para outros arquivos locais não levam a lugar nenhum útil.

O JavaScript é executado durante a conversão?

Pode ser executado em parte, mas o conteúdo que carrega depois ou depende da interação do usuário muitas vezes fica faltando. Para resultados confiáveis, o HTML já deve conter o conteúdo final.
