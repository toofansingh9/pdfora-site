Repair PDF

Re-read a PDF that other programs choke on and write it out again with a clean, rebuilt file structure.

A PDF is not one stream of content; it is a collection of numbered objects plus a cross-reference table that tells a reader where each object starts. When a download is cut short, a program writes the table badly, or a file is edited by several tools in a row, that table can point to the wrong places. Some viewers quietly cope, others show blank pages, and upload portals often reject the file with a vague error. Repair PDF is built for that middle ground: files that are structurally untidy but whose content is still there.

What the tool does is specific. It loads the file with the pdf-lib library, which reads the objects it can find and works out the structure itself rather than trusting a broken table, and then saves a fresh copy. The new file gets a freshly written cross-reference table, and every object is written out individually instead of being packed into compressed object streams, an older layout that strict or old readers accept more easily. The page content itself is copied, not re-rendered, so text, fonts and images stay exactly as they were.

It is worth being honest about the ceiling. This is a rebuild, not data recovery. If bytes are genuinely missing, for example the second half of a truncated download, there is nothing to rebuild those pages from, and no tool can invent them. In that case the right fix is a fresh copy of the file from its source.

How to repair a PDF file

  1. Open Repair PDF and add the problem file. Only one file is handled per run.
  2. Click Repair & rebuild. The file is parsed and saved again; for most documents this takes a second or two.
  3. If the tool reports an error, the file could not be parsed at all; go to the troubleshooting section below.
  4. Download the result, saved as the original name with -repaired added, for example contract-repaired.pdf.
  5. Open the repaired copy in the viewer or portal that failed before, and page through it to check that every page has content.

When to use this tool

  • A university submission portal rejects a thesis PDF as invalid even though it opens on your own laptop.
  • A file exported from an older scanner or accounting package opens in one viewer and shows blank pages in another.
  • A PDF edited many times by different programs has become sluggish or gives warnings about being damaged on open.
  • Preparing a file for a print shop or e-filing system whose validator is stricter than a normal viewer.
  • Normalising a document before merging or splitting it, when those tools refuse to load the original.
  • Checking quickly whether a file is structurally readable before asking the sender to export it again.

What to know before you start

  • Repair rebuilds structure; it does not restore lost content. A truncated file will at best come back with the pages that were complete.
  • The output is written without compressed object streams. That makes it more compatible but often a little larger than the input, sometimes by 10 to 30 percent on files that used object streams heavily.
  • Pages are copied as they are. If a page looked wrong because its own content stream is corrupt, it can still look wrong after the rebuild.
  • The file is opened with encryption checks switched off. A password-protected PDF may load, but its content stays encrypted and the saved copy is unlikely to display properly; remove the password first with Unlock PDF or at the source.
  • Forms, bookmarks and annotations that pdf-lib can read are carried into the new file because the whole document is saved, not just the pages.
  • The work happens in your browser, so even a file you would not want to send to an online recovery service can be tried here.

Tips for the best results

  • Always keep the original next to the repaired copy until you have checked the result page by page.
  • Compare the page count of the repaired file with what you expected. A lower number is the clearest sign that the source was truncated.
  • If a portal still rejects the repaired file, try printing it to PDF from your viewer; that re-renders every page and fixes problems inside page content that a rebuild cannot.
  • For a file that was emailed or downloaded, ask for it again before spending time on repair. A clean copy beats any repair.
  • After a successful repair, run Compress PDF if the size grew and the file is mostly scans.

A worked example: a freelancer's invoice bundle

A freelance translator exports twelve monthly invoices from an old invoicing program into one PDF for the annual tax return. The file opens in the browser's built-in viewer, but the tax office's upload form rejects it as an invalid document, and Merge PDF refuses to add it to the rest of the paperwork.

Run through Repair PDF, the file loads, gets a newly written cross-reference table and is saved without object streams. The upload form accepts the repaired copy and the merge tool now reads it. The file grew from 410 KB to about 460 KB, which is the cost of the more conservative layout and is irrelevant here.

Before submitting, the translator counts the pages: twelve invoices, twelve pages. Had the count been nine, the original export would have been incomplete, and the only real fix would have been exporting it again from the invoicing program.

Troubleshooting

The tool shows an error and produces nothing
The file could not be parsed at all, typically because it is not really a PDF (for example an HTML error page saved with a .pdf name) or is badly truncated. Open it in a text editor: a real PDF starts with %PDF. Otherwise get a fresh copy.
Some pages are missing in the repaired file
Those pages were not present in readable form in the source, usually because a download was cut short. Download or export the document again.
Pages are still blank or garbled
The page content itself is damaged, which a structural rebuild does not touch. Try printing the original to PDF from whichever viewer displays it best, or ask the sender for a new export.
The repaired file is bigger than the original
The tool writes objects individually instead of in compressed object streams. That is intentional for compatibility; compress the result if size matters.
The repaired copy shows unreadable content
The source was probably encrypted. Encryption is ignored on load, so content stays scrambled. Remove the password in the program that created the file or with Unlock PDF if you know the password, and repair that copy.
The portal still rejects the file
The validator may object to something other than structure, such as file size, page size or embedded fonts. Check the portal's stated requirements; resize, compress or print to PDF accordingly.

Frequently asked questions

What exactly does Repair PDF change?

It re-reads the document's objects, writes a new cross-reference table and saves every object individually without object streams. Page content is copied unchanged.

Can it recover a PDF that will not open anywhere?

Sometimes. If the objects are intact and only the structure is broken, yes. If the data itself is missing or the file is not a PDF, no repair tool can bring it back.

Will repairing reduce the quality?

No. Nothing is re-rendered or recompressed, so text and images look exactly as they did.

Why did the file size increase?

Compressed object streams are not used in the output, which makes the file slightly larger but readable by older and stricter software.

Does repair remove a password?

No. It does not decrypt anything, and an encrypted file will usually not display correctly after the rebuild. Use Unlock PDF to remove a password you know.

Can I repair several files at once?

The tool takes one file per run. Process each file in turn; it is quick for ordinary documents.
