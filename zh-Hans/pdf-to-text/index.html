手动从 PDF 里复制文字又慢又乱：选区会在分栏之间乱跳，页眉每页都重复一遍，长文档更是要反复全选几十次。这个工具读取 PDF 中本来就存着的文字，按页面顺序全部写进一个纯文本文件，可以直接用文本编辑器、电子表格或脚本打开处理。

这里的“文字”是什么意思，有必要先说清楚。由文字处理软件、浏览器或财务软件生成的 PDF，里面存的是带位置信息的真实字符。PDF.js 会逐页读取这些字符，把每页上的文字片段用空格连接起来，页与页之间用一个空行隔开。而扫描页只是一张纸的照片，里面根本没有字符，所以本工具对这类页面什么也提取不出来。扫描件需要用 OCR 来识别图片中的文字。

输出内容刻意保持朴素：没有粗体、没有字体、没有表格、没有图片，页面内原有的换行也不会保留，每一页都是一整段连续的文字。这样的文件便于搜索，也便于交给其他工具处理，但它不能用来还原文档版式。如果版式很重要，“PDF 转 Word”是更好的选择。

如何从 PDF 中提取文字

  1. 打开“PDF 转文本”，选择一个 PDF 文件。
  2. 点击“提取文字”。工具会依次读取每页的文字内容，进度条逐页前进。
  3. 完成后，结果会显示处理了多少页。下载 .txt 文件，文件名与你的 PDF 相同（thesis.pdf 会得到 thesis.txt）。
  4. 用文本编辑器打开文件，搜索一句你确定在文档中出现过的话，确认文字已经完整提取。
  5. 如果有整页是空的，说明那些页面是图片；在“OCR PDF”里把输出选为“文本文件（.txt）”就能得到这些页的文字，也可以先把 PDF 变成可搜索的，再重新提取。

适用场景

  • 把论文或研究报告中的段落引用到自己的笔记里，不用重新打字。
  • 在一份很长的合同或制度文件里，用文本编辑器的查找功能找出某个术语的每一处出现。
  • 把文档交给字数统计、翻译工具或只接受纯文本的脚本处理。
  • 原始可编辑文件丢失时，找回文档的文字内容，作为新版本的起点。
  • 检查读屏软件或搜索引擎大概能从 PDF 中读到什么，因为它们依赖的是同一个文字层。
  • 从对账单中提取数字，粘贴到电子表格里再整理。

开始前需要了解

  • 只读取文字层。扫描页、文档照片以及已转成轮廓的文字，在输出中都是空白或几乎空白的页面。
  • 同一页上的文字片段用一个空格连接，页与页之间用一个空行分隔。页面内的换行不会保留，因此段落和表格行会连在一起。
  • 阅读顺序取决于文字在 PDF 中的存储顺序，通常与视觉顺序一致，但并非总是如此。双栏排版、侧边栏和脚注可能会交错在一起。
  • 页眉、页脚和页码在每一页都会被提取出来，因为对 PDF 来说它们就是普通文字。
  • 有些 PDF 逐字存储文字或间距异常，可能导致词语或字与字之间多出空格。还有些 PDF 使用的字体缺少正确的字符映射，提取出来会是乱码符号而不是文字。
  • 图片、图表和示意图中的文字不会被提取，未扁平化到页面中的表单字段文字也不会。PDF 中跨行断开、带连字符的英文单词通常保持断开状态，中间是连字符加一个空格，搜索“- ”就能找到大部分。

获得最佳效果的技巧

  • 如果结果是乱码或空白，先在普通 PDF 阅读器里试着选中文字。如果在那里都选不中，提取也不会成功，这时该改用“OCR PDF”：把输出选为“文本文件（.txt）”，就能直接拿到识别出的文字。
  • 用编辑器的查找替换功能一次性去掉重复的页眉页脚，比逐页手动修改省事得多。
  • 处理表格时，“PDF 转 Excel”能保持行列分开；纯文本会把每一行挤成一行文字。
  • 如果编辑器询问编码，请以 UTF-8 保存 .txt；从 PDF 中提取的中文及其他非拉丁字符都以 Unicode 保存。
  • 如果只需要其中一章，先把大 PDF 拆分开；文本文件小一些更好处理。隐藏文字（例如其他软件的 OCR 在扫描图片下方添加的文字层）会和其他文字一样被提取出来。

实例：法学研究生整理阅读材料

一位法学研究生从法院网站下载了一份 60 页的判决书 PDF，想找出所有引用某个先前案例的段落，再把这些段落粘贴进自己的笔记。在 PDF 阅读器里滚动复制时，每次都会把页眉一起选进来。

她提取了文字，用纯文本编辑器打开 judgment.txt。搜索那个案例名称，找到了 11 处。由于每页是一整块文字，她通过数空行就能大致判断每处结果在第几页；页眉出现在每个页面块的开头，很容易忽略。

有一页提取出来是空的。重新打开 PDF 一看，那是插在判决书中的一份扫描附件。她用“OCR PDF”的“文本文件（.txt）”输出处理判决书，从得到的文件里复制附件的文字，补进空缺处。这个道理具有普遍性：一个 PDF 里可能混有真实文字页和图片页，只有前者能被直接提取。

故障排除

文本文件是空的，或者只有空行
这个 PDF 是扫描件或由图片组成。请改用“OCR PDF”并选择“文本文件（.txt）”输出，或者先生成可搜索 PDF，再从中提取。
输出内容全是奇怪的符号
PDF 使用的字体没有可用的字符映射，字符无法还原成文字。在提取失败的情况下，对渲染后的页面做 OCR 通常能解决。
文字中间多出了空格
PDF 把文字存成了很小的片段，而工具用空格连接这些片段。可以在编辑器中用查找替换整理常见的模式。
各栏内容混在一起
文字按存储顺序读取，多栏页面可能会在栏与栏之间来回跳。可以在 PDF 阅读器中单独复制需要的那一栏，或者用能识别版式的“PDF 转 Word”。
PDF 在工具中打不开
文件可能设有密码或已损坏。请在生成它的程序中去掉密码，或者先用“修复 PDF”处理。
段落内的换行没有了
工具就是这样工作的：每页变成一整段文字。可以粘贴到文字处理软件中，在需要的地方手动换行；如果结构很重要，请用“PDF 转 Word”。

常见问题

这个工具能读取扫描版 PDF 吗？

不能。扫描件里是图片，不是字符。请改用“OCR PDF”并选择“文本文件（.txt）”输出，或者先用“可搜索 PDF”输出处理，再提取。

粗体、标题等格式会保留吗？

不会。输出是纯文本，没有字体、样式、表格或图片。

为什么每一页开头都是同一行字？

那是 PDF 中的页眉。它是普通文字，所以每一页都会被提取出来。

支持哪些语言？

只要字符在 PDF 中存储正确，任何语言都可以，文字以 Unicode 保存。从右到左书写的文字可能按存储顺序而不是显示顺序输出。

.txt 文件中各页是怎么分隔的？

每页文字后面跟一个空行，所以各页显示为独立的文字块。

提取是在服务器上进行的吗？

不是。PDF.js 在你的浏览器中读取文字，.txt 文件也在本地生成。如果文档是不想上传的合同草稿或试卷，这一点很重要。
