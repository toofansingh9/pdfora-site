PDF 转 Excel

把 PDF 里的表格提取到 Excel（.xlsx）工作簿中，方便排序、筛选和计算。

想把 PDF 转成 Excel，通常都是为了里面的表格：银行流水、价目表、报告附录、成绩单。PDF 里的数字看着整整齐齐，底下其实并没有网格。每个数字都是一段独立的文字，放在页面的某个位置上，那些看起来像单元格边框的线条只是绘图。所以从 PDF 阅读器复制到表格软件里，内容往往全挤在一列。

真正的转换器会分析文字所在的位置，判断哪些内容纵向对齐成列、横向对齐成行，再写进真正的表格单元格。PDFora 为此把 PDF 发送到服务端的转换引擎（经由我们自己的中转发往 CloudConvert），因为这种分析远远超出网页能稳定完成的范围。文件通过加密连接上传，转成 .xlsx 后再下载回来；任务结束后，上传的副本会从该服务上删除。

没有需要设置的选项：输入一个 PDF，输出一个覆盖整个文档的工作簿。由财务软件或表格软件导出的 PDF 通常效果很干净；经过设计排版的报告、旋转的表格或扫描件则需要更多整理。数字尤其要核对，因为看起来正确的值，仍可能是以文本形式存储的。

PDF 转 Excel 的步骤

  1. 打开“PDF 转 Excel”，选择一个 PDF。如果只需要其中一个表格，先把那几页提取出来，工作簿里就不会有别的内容。
  2. 点击“转换”，状态会依次显示“正在上传…”和“正在转换…”。
  3. 等待下载。工具每隔几秒查询一次服务器，如果任务约三分钟还没完成，就会停止。
  4. 保存 .xlsx 文件（与原文件同名、扩展名为 .xlsx，除非服务器返回了别的名字）。
  5. 打开工作簿，选中数字列，确认 Excel 把它们当作数字，比如对某一列求和，再和 PDF 上的合计对比。

适用场景

  • 小店老板把供应商发来的 PDF 价目表转成表格，加一列自己的加价。
  • 把银行流水或信用卡账单与记账分录逐笔核对。
  • 公益机构汇总各地合作办公室以 PDF 报告形式发来的调查结果。
  • 学生分析公开发布的统计年鉴 PDF 里的表格。
  • 把以 PDF 发来的课表或排班表改成可以按人或按天筛选的表格。
  • 从原始表格早已找不到的旧报告里提取库存清单。

开始前需要了解

  • 文件在服务器上处理，而不是在你的浏览器里：加密上传、转换，之后从转换服务上删除。
  • 扫描的表格是图片。没有文字层就没有数字可以放进单元格。“OCR PDF”可以把数字识别到 .txt 文件里，再由你自己粘贴进表格；一定要逐个核对数字，因为 OCR 可能把 1 和 7、0 和 8 之类的数字读错。
  • 数字格式可能以文本形式导入。千位分隔符、货币符号、用括号表示的负数或末尾的 CR，都可能让 Excel 无法把值识别为数字。
  • 合并的标题、单元格内换行的文字，以及在 PDF 中跨两行的行，经常会被拆成好几行。
  • 不是表格的内容（段落、脚注、页眉）也会落进单元格，需要做些清理。
  • 有密码保护的 PDF 无法转换；请先在源程序中解除保护。在转换出的余额列旁边加一列累计余额公式，可以标出两个数字第一次不一致的那一行，通常就是转换器错位的那一行。

获得最佳效果的技巧

  • 转换前只提取包含表格的那几页；工作簿更小，清理也更有针对性。
  • 如果数字靠单元格左侧对齐，说明它们是文本。用“数据 > 分列”不做任何更改直接完成，或者乘以 1，就能变成数字。
  • 注意区域设置：用逗号作小数点的 PDF，可能会让设置为小数点的表格软件出错，反之亦然。
  • 重复的表头行（PDF 每页一行）用筛选表头文字的方式批量删除，别手动一行行删。
  • 在信任转换出的数字之前，至少把一列的合计与 PDF 对比一次。

示例：自由职业者核对季度账单

一位自由设计师从收款平台收到一份四页的 PDF 账单，列出了本季度的 63 笔入账。她的会计希望把它们做成表格，客户名称、日期、总额和手续费各占一列。

她转换 PDF 后打开工作簿。行都在，但每页开头都有一行重复的表头，手续费列里扣款显示为 (2.40) 这样的形式，Excel 把它当成了文本。她筛掉表头行，用“查找和替换”把括号改成前置负号，再把这一列转成数字。日期则正确识别成了真正的日期，因为 PDF 用的是不会产生歧义的年-月-日格式。

最后她对总额列求和，与账单最后一页印的合计对比，分毫不差，于是确认没有哪一行丢失或被拆开。每张转换出来的表格都值得做这一次对比。银行流水尤其要注意。很多银行把累计余额单独列成一列，没有支出或收入的交易就留空。转换后这些空格有时会塌缩，导致那一行的收入被挪到支出列。排序或筛选都发现不了，只有合计，或者拿累计余额公式与印出的余额对比，才能发现。把这个核对做进表格一次，之后每个月都能重复使用。

故障排除

所有内容都在 A 列
转换器没能识别出列，通常是因为 PDF 用空格而不是位置来对齐文字。用“数据 > 分列”，按空格或固定宽度拆分。
数字加不起来
它们是以文本形式存储的。去掉货币符号和千位分隔符，再把单元格转成数字；注意检查有没有用括号表示负数。
PDF 里的一行变成了表格里的两行
PDF 中某个单元格换行到了第二行。用 =A2&" "&A3 这样的公式拼接，或手动编辑，然后删掉多出来的那一行。
工作簿里全是图片而不是数字
这个 PDF 是扫描件，没有真正的数字可供转换。用“OCR PDF”把数字导出为 .txt 文件，粘贴进表格，再校对数字。
任务超时了
大型报告可能超过工具约三分钟的等待时间。把含有表格的页面提取出来，只转换这些页。
服务器转换失败
检查 PDF 是否要求输入密码或已损坏。解除保护或用“修复 PDF”处理后再试。

常见问题

是每页一个工作表，还是全部放在一个工作表里？

取决于转换引擎如何解读你的文档；跨多页的表格经常按页拆开。如有需要，用复制粘贴或 Power Query 合并。

原始表格里的公式能恢复吗？

不能。PDF 只保存显示出来的值，所以工作簿里只有数字和文字，没有生成它们的公式。

能读取扫描文档里的表格吗？

不能直接转换。“OCR PDF”可以把数字识别到 .txt 文件里，你再粘贴进表格，并仔细核对。

能用 WPS、Google 表格或 LibreOffice 打开吗？

可以。输出的是标准 .xlsx 文件，这些软件都能打开。

为什么有些日期不对？

像 03/04 这样的日期有歧义。Excel 会按你的区域设置来解读，所以请拿几个日期和 PDF 对照一下。

文件会被上传吗？

会，这个工具使用服务端转换器。PDF 加密发送，转换完成后从服务上删除。
